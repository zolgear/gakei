# ADR-0025: 認証モードでは本人のものだけを見せる(他人のプライバシーを守る)

**Status:** Proposed
**Date:** 2026-09-28

2026-09-28 にユーザーが次のように決めた。

- 認証を有効にしたとき、他人のプライバシーが侵されないようにする。
- 共有機能は将来の課題とし、今回は作らない。
- 管理者も、他人の Run や画像は見られない。
- 実行者が記録されていない既存のデータ(個人モードの頃のもの)は、管理者だけが見られる。

同日、この ADR の内容がユーザーに承認された。

## Context

ADR-0019 4章は、認証モードの閲覧範囲を「全員が全件」と決めていた。単一組織なのでメンバー管理を作らない、という理由だった。この決め方では、ログインした人は誰でも、他人のプロンプト、生成画像、アップロード画像、実行者の名前とメールアドレスを見られる。削除や取り消しも他人のものに対してできた(ADR-0019 4章の追記、指摘 I-6)。MCP(ADR-0023)の `list_runs` と `search_assets` も同じ範囲を返す。

プロンプトやアップロード画像には、個人的な内容や業務上の秘密が含まれうる。組織の中であっても、本人の同意なく他人に見えるのは望ましくない。

## Decision

### 1. 閲覧範囲

| モード | 見られる範囲 |
|---|---|
| 個人モード(`AUTH_MODE=none`) | 変えない(全件。利用者は 1 人) |
| 認証モード(`AUTH_MODE=oidc`) | **本人が作ったものだけ。** 管理者も同じ |

- 実行者が記録されていないもの(`created_by_user_id` が NULL。個人モードで作ったデータ)は、認証モードでは **管理者だけ** が見られる。個人モードでは利用者が管理者として動いていたため。
- 共有(他人に見せる)機能は作らない。必要になったら、この ADR を改めて足す。

### 2. 「本人のもの」の決め方

| 対象 | 所有者 |
|---|---|
| Run | `run.created_by_user_id` |
| 生成された Asset | その Asset を作った Run の実行者 |
| アップロード、マスク、スケッチの Asset | `asset.created_by_user_id` |
| グループ | `asset_group.created_by_user_id` |
| プロンプトセット | `prompt_set.created_by_user_id`(新しく足す列。既存の行は NULL) |

- 所有者の判定は、サーバー側の 1 か所(可視性の関数)にまとめる。一覧、詳細、画像の配信、系列、検索、SSE、MCP のすべてがそこを通る。
- 他人のものへのアクセスは、存在を明かさないよう **403 ではなく 404** を返す。

### 3. 対象になる操作

見る操作:
- Run の一覧・詳細・履歴、Asset の詳細・ストック・検索、画像の配信(原本、プレビュー、サムネイル。ADR-0004)、系列のグラフ(ADR-0003)、比較画面。
- 進捗の SSE と、実行中・待機中の件数(App バー)。本人の Run だけを数え、流す。
- MCP のすべてのツール(ADR-0023)。`list_runs` の `created_by=anyone` はなくす。

変える操作:
- Run の取り消し・削除・再実行、Asset の削除、グループの編集、プロンプトセットの編集。ADR-0019 4章の追記「削除・取り消し・編集は全員可」は、この ADR で改める(本人だけ)。

入力に使う操作:
- Run の入力画像とマスクには、本人が見られる Asset だけを指定できる。見られない Asset を指定すると、その Asset が存在しない場合と同じエラーにする。

### 4. 系列と重複の扱い

- **アップロードの重複判定は、本人の Asset の中だけで行う。** ADR-0014 では、ダウンロードした PNG を再アップロードすると、埋め込まれた系列の参照と内容が一致すれば既存の Asset を返していた。今後は、その既存の Asset が本人に見えるときだけ返す。見えなければ、新しい Asset として取り込む。他人の画像の存在が、ファイルを持っているだけで分かってしまうことを防ぐため。
  - 同じ内容の画像ファイルは、これまでどおり保存領域の中で共有する(ADR-0004)。ファイルの共有は利用者からは見えない。
- **系列の自称の参照(`origin_asset_id`、`origin_ref_asset_id`)が他人の Asset を指す場合、その Asset は見せない。** 画面は「このインスタンスの別の Asset(表示できません)」とだけ示す。埋め込みメタ情報の内容そのもの(ADR-0014、ADR-0018)は、ファイルに書かれていたものなので、これまでどおり表示する。
- 系列のグラフは、見られるノードだけで作る。共有機能が無いので、本人の Run が他人の Asset を入力にすることは、3 章の入力の制限により起きない。

### 5. 管理者

- 管理者も、他人の Run、Asset、グループ、プロンプトセットは見られない。見られるのは、本人のものと、所有者が NULL のもの(1 章)だけ。
- 管理者設定(OpenAI のキー、ComfyUI の接続、MCP、ワークフローの登録など)はこれまでどおりで、利用者のデータとは別。
- 利用者ごとの件数や料金の集計を管理者に見せる機能は、必要になったら別に決める(今回は作らない)。

### 6. 変わらないもの

- 来歴の記録(ADR-0003)は変えない。可視性は読み出しの側で絞る。
- 個人モードの動作は変えない。

## Options Considered

### Option A: 全員全件のまま(ADR-0019)
**Pros:** 実装が要らない。チームで成果物を見せ合える。
**Cons:** 本人の同意なく、プロンプトや画像が他人に見える。

### Option B: 本人だけ + 共有機能
**Pros:** プライバシーを守りつつ、見せたいものは見せられる。
**Cons:** 共有の単位(グループ、1 枚ずつ、相手の指定)を決める必要があり、画面も大きくなる。ユーザーの判断で将来に回した。

### Option C: 本人だけ、共有なし(採用)
**Pros:** 規則が単純で、漏れを検査しやすい。共有は後から足せる。
**Cons:** チームで画像を見せ合うには、ダウンロードして渡す必要がある。

## Trade-off Analysis

決め手はユーザーの判断で、プライバシーを優先する。共有を後から足せるよう、可視性の判定を 1 か所に集める。そうすれば、共有を足すときも、その関数の条件を広げるだけで済む。

## Consequences

- 認証モードでは、利用者どうしが互いの Run と画像を見られなくなる。管理者も同じ。
- 個人モードで作ったデータは、認証を有効にした後は管理者だけに見える。
- `prompt_set` に `created_by_user_id` が加わる(マイグレーション)。
- ADR-0019 4章の「閲覧範囲は全員全件」と「削除・取り消し・編集は全員可」を改める。ADR-0023 の `list_runs` の `created_by=anyone` をなくす。
- タイトルとタグ(ADR-0024。PR #20、未マージ)の編集、タグの一覧と件数も、本人の Asset に限る。
