# ADR-0020: ユーザーのアバター画像(アップロードと生成画像からの選択)

**Status:** Proposed
**Date:** 2026-09-27

## Context

ADR-0019 で OIDC ログインを入れ、右上のユーザーメニューには名前の頭文字だけを出している。画像生成のツールなのに、自分のアバターを自分の生成画像から選べないのは味気ない、という利用者の要望があった。IdP(Google など)の `picture` クレームを使う案もあるが、IdP ごとに有無が違い、生成画像を使いたいという要望には応えられない。

## Decision

### 1. 範囲

- アバターは **oidc モードだけ** の機能。個人モード(`AUTH_MODE=none`)にはユーザーが無いので、設定画面にも出さない。
- 自分のアバターだけを変えられる。管理者が他人のアバターを変える機能は作らない。
- 画像の出所は2つ: **ファイルのアップロード**(PNG / JPEG / WebP、20MB 以下)と、**ストックの画像(既存の Asset)からの選択**。どちらも同じ処理で正方形に整える。

### 2. 保存

- アバターは **Asset にしない。** 作品(生成物・入力)ではなく、ストックや系列グラフに出てはいけないし、差し替え・削除は証跡ではないので物理的に消してよい(ADR-0003 の追記のみの規則の対象外)。
- 保存先は `DATA_DIR/avatars/{user_id}.webp`。利用者が選んだ範囲(5章)を正方形に切り出して 256×256 の WebP にする(サーバー側で Pillow)。範囲の指定が無ければ中央の正方形。
- `app_user.avatar_sha256`(NULL 可)に内容のハッシュを持ち、URL のキャッシュ破り(`?v=`)と `ETag` に使う。
- Asset から選んだ場合は、その時点の原本から作った複製を保存する。元の Asset を後から削除してもアバターは残る(参照は持たない)。

### 3. API

| メソッド | パス | 内容 |
|---|---|---|
| `POST` | `/api/users/me/avatar` | multipart `file` をアップロードして自分のアバターにする。任意の form 項目 `crop`(JSON 文字列 `{x, y, width, height}`。元画像のピクセル座標)で切り出す範囲を指定できる |
| `POST` | `/api/users/me/avatar/from-asset` | `{ "asset_id", "crop"? }` の Asset(削除済みでないもの)からアバターを作る。`crop` は原本のピクセル座標 |
| `DELETE` | `/api/users/me/avatar` | アバターを消す(頭文字の表示に戻る) |
| `GET` | `/api/users/{user_id}/avatar` | `image/webp`。ログインしていれば誰のものでも見られる(履歴に出すため)。無ければ 404。`Cache-Control: private, max-age=31536000, immutable`(URL に `?v=<sha256 の先頭8桁>` を付けるので不変扱いでよい) |

- `AuthUser` と `CreatedBy` に `avatar_url: string | null` を足す(`/api/users/{id}/avatar?v=…`。無ければ null)。画面は URL の有無だけを見る。
- 個人モードでは `/api/users/me/avatar*` は 404(`t("auth.disabled")` と同じ扱い)。
- 画像の検証は既存のアップロード(`domain/sizes.py`、`ingest_upload`)と同じ方針: Pillow でデコードできること、`Image.MAX_IMAGE_PIXELS` の上限、拡張子ではなく中身で判定。アニメーションは最初のフレームだけ使う。

### 4. 画面

- **設定 → ユーザー設定 → 「プロフィール」**(oidc モードのときだけ): 現在のアバター(無ければ頭文字)、「画像をアップロード」「ストックから選ぶ」「削除」。ストックの選択は、入力画像の追加ダイアログ(ADR-0009 1章、`AddInputImagesDialog`)のサムネイル一覧を共通部品に切り出して、1枚だけ選ぶモードで使う。どちらも選んだ後にトリミングのダイアログ(5章)を経て確定する。
- ユーザーメニューのアバターは枠線を付けない(2026-09-27 の確認で「枠は不要」)。
- ユーザーメニュー(右上)はアバターがあればそれを、無ければ頭文字を出す。
- 履歴カードと Run 詳細の実行者名の横に、小さなアバター(16〜20px)を出す。

### 5. トリミング(共通部品。2026-09-27 追記)

- 中央固定では顔が端にある画像を使えない、という確認結果を受けて、**切り出す範囲を選ぶダイアログ**を作る。アバター専用にせず、他の用途(将来の入力画像の一部切り出しなど)でも使える共通部品にする。
- 画面側: `features/crop/` に、画像と縦横比(`1` で正方形、`null` で自由)を受け取り、**元画像のピクセル座標の矩形**を返す `CropEditor`(枠のドラッグ移動と四隅のハンドルで大きさを変える。縦横比を指定したときは固定)と、それをモーダルに載せた `ImageCropDialog`。座標変換と縦横比の維持は純粋関数(`cropMath.ts`)に置いてテストする。
- サーバー側: 切り出しはサーバーで行う(ブラウザで再エンコードしない。ストックの画像は原本をブラウザに送らずに済む)。範囲は元画像のピクセル座標で受け取り、画像の外にはみ出す・空の矩形は 422。用途ごとの後処理(アバターなら正方形化と 256px への縮小)はその用途の関数が行う。
- 拡大・回転・自由な形の切り出しは作らない(ADR-0001 の非ゴール「高機能な画像編集」)。

### 作らないもの

- 拡大率・回転を選ぶ UI、複数のアバターの保管、IdP の `picture` クレームの利用、個人モードでのアバター、管理者による他人のアバターの変更。

## Options Considered

| 保存の方法 | 評価 |
|---|---|
| A: `DATA_DIR/avatars/` に WebP を1枚(採用) | 単純。ストックや系列に混ざらない。削除が物理削除でよい |
| B: Asset として保存し `app_user.avatar_asset_id` で参照 | 既存の配信経路が使えるが、ストックに出る・削除できない(追記のみ)・派生の生成が要る、と辻褄合わせが多い |
| C: IdP の `picture` クレーム | 実装は最小だが、IdP に依存し、生成画像を使えない |

## Consequences

- `app_user` に列が1つ、API が4つ、設定画面にセクションが1つ増える。
- `DATA_DIR/avatars/` がバックアップの対象に加わる(README の `DATA_DIR` の説明はそのまま当てはまる)。
- アバターは他の利用者にも見える(履歴の実行者)。公序良俗に反する画像への対処は運用(管理者が本人に依頼)に任せる。
