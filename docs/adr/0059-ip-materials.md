# ADR-0059: IP 素材(預かった版権の素材の管理・利用の申告・記録・レポート)

**Status:** Proposed
**Date:** 2026-11-01

2026-11-01 にユーザーが次のように決めた。

- 管理者とチーム(ADR-0058)の代表者が、自社や他社の IP(版権のある作品)を、画像の編集の素材として提供できるようにする。手軽なストックのアップロードとは分け、厳密なアクセス管理、記録、状況のレポートを備える。
- 利用者の単位はフラットなチームにする(ADR-0058)。
- 素材から作った画像(派生物)は、同じ許可を持つチームの中で共有する。
- 他社の権利者には、レポートを書き出して渡す。権利者に GAKEI を公開することは通常しない。
- 案件や作業の単位は、利用者の組織に合わせて自由に書けるようにする。一覧や形式で縛らない。
- 「納品済み」の状態は持たない。代わりに、納品・共有・提出したものに付けて削除を防ぐロックを足す(ADR-0060)。
- 複数の IP を混ぜた派生物は、混ぜたどの IP の担当者も見られる。意図しない IP の混入や掛け合わせを見つけられるようにするため。
- 原本の持ち出し(ダウンロード、系列の書き出し)は制限しない。手元に表示できるものの持ち出しを厳密に止めることはできないため。持ち出したことは記録する。

## Context

GAKEI は、預かった素材を正当に使ったことを記録できるように作ってきた。来歴の記録は追記のみで(ADR-0003)、Run には入力、出力、実行者、時刻が残る(ADR-0006、ADR-0019)。系列を「この画像と子孫」の範囲で書き出せば、素材を何に使ったかを示せる(ADR-0037)。

他社の版権の素材を預かる業務では、さらに次が求められる。

- 預かった素材を、許可された人だけが、許可された用途にだけ使うこと。用途の外で使っていないことを、権利者に示せること。
- どの素材を、何の用途に、どれだけ使い、何を作ったかを、期間を区切って報告できること。
- 契約の条件(誰が使えるか、何の用途か、外部の AI に送ってよいか)を、利用者の注意に頼らず、システムが守らせること。
- 契約が終わったら使えなくし、必要なら素材を破棄し、破棄したことを示せること。

今のストックは、利用者が自分の画像を気軽に入れる場所で、本人にだけ見える(ADR-0025)。誰でも入れられ、消せ、外部の AI(自動タイトル・タグ、埋め込み)にも送られる。預かった素材をここに混ぜると、上の要件を満たせない。

## Decision

### 1. 範囲と有効化

- **IP 素材は、普段のストックとは別の棚に置く。** 取り込み、見える範囲、使い方の検査、記録の規則を、普段の画像とは分ける。
- **認証モード(`AUTH_MODE=oidc`)のときだけ使える。** 個人モードでは、誰が使ったかを示せないため。
- **管理者設定で有効にする(既定は無効)。** 無効のときは、IP の画面と API を出さない(ADR-0009「無効な機能は利用者の画面から隠す」)。一度でも IP 素材を取り込んだ後に無効にしても、記録と制限(6章)は効き続ける。

### 2. IP と契約の条件

- **IP** は、作品や版権の単位。名前、区分(自社 / 他社)、権利者の名前、説明、担当者、状態(有効 / 停止 / 終了)を持つ。
  - 担当者は、その IP の素材を取り込み、許可を出し、記録とレポートを見る人。管理者が決める。ふつうはチームの代表者。
- **契約の条件** は、IP ごとに版を重ねる。条件を変えるときは新しい版を作り、古い版は書き換えない。Run の申告(5章)は、そのとき有効だった版を指す。条件の項目:

| 項目 | 内容 |
|---|---|
| 契約番号、有効期間 | 期間の外では使えない(状態が「有効」でも) |
| 許諾された用途 | 用途の名前の一覧。担当者が自由に決める(例: 製品のデザインモック、発注用のコンテ、発注指示書、最終成果物) |
| 外部の AI への送信 | `allow`(許可)/ `local_only`(手元の接続先だけ)/ `deny`(どの AI にも送らない)。接続先の区分は ADR-0051 の `locality` |
| 注記 | クレジットの表記、禁止事項など、システムが守らせられない取り決め(文章)。使う画面に出す |

- **停止** は一時的に止める(許可も効かない)。**終了** は契約が終わったことを表し、戻せない(9章)。

### 3. 素材の取り込み

- **取り込めるのは、その IP の担当者と管理者だけ。** 普段のアップロード(`POST /api/assets`)とは別の入口(`POST /api/ip/{ip_id}/materials`)にする。
- 取り込んだ画像は、普段と同じく原本を sha256 で保存する(ADR-0004)。同じ内容の画像が誰かのストックにあっても、IP 素材は別の Asset として作る(重複判定で既存の Asset を返さない)。
- IP 素材は `ip_material`(asset_id、ip_id、取り込んだ人、時刻、取り下げた時刻)で表す。所有者は人ではなく IP で、見える範囲は4章と6章で決まる。
- **素材は普段の削除では消せない。** 担当者が取り下げる(`withdrawn_at`)と、新しく使えなくなる。記録とこれまでの派生物は残る。原本の破棄は9章。
- **取り込みの後の自動処理は、契約の条件に従う。** 外部の AI への送信が `allow` でなければ、外部の接続先の自動タイトル・タグ(ADR-0024)、埋め込み(ADR-0033)は動かさない(`local_only` なら手元の接続先だけ)。Mod の `asset.ingested`(ADR-0051)は送るが、外部の接続先の Mod には画像を付けない。

### 4. 利用の許可

- **許可は、IP をチーム(ADR-0058)か個人に出す。** 出せるのは担当者と管理者。
- 許可の項目: 期間(開始・終了)、許す用途(契約の用途の一部)、権限。権限は次の2つ。

| 権限 | できること |
|---|---|
| 見る | 素材と派生物を一覧と詳細で見る。原本のダウンロードと系列の書き出しもできる(証跡に残す) |
| 入力に使う | 素材と派生物を Run の入力にする(5章の申告が要る)。「見る」を含む |

- **原本の持ち出しは制限しない。** 見えるものは画面の写しなどで持ち出せるので、ダウンロードだけを止めても守れない。止める代わりに、原本のダウンロードと系列の書き出しを証跡(7章)に残し、レポート(8章)に載せる。

- 許可を変えるときは、古い許可を取り消して新しい許可を作る(いつ誰がどの範囲で使えたかを残すため)。取り消しと期限切れは、次の操作から効く。
- 利用の申請と承認(人が待つワークフロー)は作らない(ADR-0001 の非ゴール)。許可は前もって出しておく。

### 5. 使うときの申告と検査

- **IP 素材か、その派生物(6章)を入力にした Run は、送るときに申告が要る。**
  - **用途:** 許可の用途から選ぶ(必須)。
  - **作業のメモ:** 案件、発注、作業の単位などを自由に書く(任意)。形式も一覧も決めない。前に書いたものを候補に出す(本人の分だけ)。
- 申告は `run_ip_use`(run_id、ip_id、条件の版、許可、用途、作業のメモ)に残し、追記のみにする(ADR-0003)。入力が複数の IP にまたがるときは、IP ごとに1行。
- **サーバーが検査する。** Run を作るときと、worker が実行する直前(ADR-0051 の `ai.before_send` と同じ時点)の2回。間に許可が切れることがあるため。次のどれかに当たれば拒否する。
  - IP の状態が「有効」でない、契約の期間の外、素材が取り下げ済み
  - 実行者に、その IP の「入力に使う」の有効な許可が無い
  - 選んだ用途が、許可の用途に無い
  - プロバイダーの接続先が、外部の AI への送信の条件に合わない(`deny` ならどこにも送らない)
- 拒否は、Run を作る前なら 422、実行の直前なら Run を failed(`error.code = ip_denied`)にする。どちらも証跡(7章)に残す。
- **Run 以外で画像を AI に送る経路も、同じ条件で止める。** アシスタントへの添付、領域の検出の VLM、似た画像の検索のリモートの埋め込みなど。外部の AI を呼ぶ処理は `ai.before_send` の入口を通るので(ADR-0051)、そこで IP の条件を見る。
- MCP(ADR-0023)から作る Run も同じ。申告はツールの引数で渡し、無ければ拒否する。

### 6. 派生物への引き継ぎ

- **IP 素材から作った画像は、その IP の派生物になる。** 孫の世代にも系列をたどって引き継ぐ。Run の出力のほか、IP の画像を下地にしたスケッチ、マスク、配置、領域の画像(ADR-0010、0050、0053)も派生物にする。
- どの IP の派生物かは、Asset を作るときに `asset_ip_lineage`(asset_id、ip_id)に書き、後から変えない。読み出しのたびに系列をたどらない。
- **見える範囲:** 派生物は次の人に見える。ADR-0025 の「本人だけ」の例外はここだけにする。
  - 作った本人。
  - その Asset が引き継ぐ **すべての IP** について「見る」の有効な許可を持つ人(チームのメンバーを含む)。1つでも許可の無い IP が混ざっていれば見えない。
  - その Asset が引き継ぐ **いずれかの IP** の担当者。許可の有無や、ほかの IP が混ざっているかに関わらず見える。意図しない IP の混入や、IP どうしの掛け合わせを見つけられるようにするため。IP のページで、その IP の派生物を一覧でき、ほかの IP が混ざったものに印を付ける。
- **使える範囲:** 派生物を入力にするのは、素材と同じく申告と検査(5章)が要る。作った本人でも、許可が切れていれば入力に使えない。
- **持ち出し:** 派生物の原本のダウンロードと系列の書き出し(ADR-0037)は、見える人ならできる(証跡に残す)。共有リンク(ADR-0029)は作れない。共有リンクは GAKEI が自分でログイン不要の公開の URL を出すもので、見える範囲(許可)の外に素材を見せることになるため。
- **整理:** 派生物の削除、グループ(ADR-0022)、お気に入りは、これまでどおり本人の操作。消せないようにするのはロック(ADR-0060)。

### 7. 証跡(`audit_event`)

ADR-0006 で設計した `audit_event` を、この ADR で実装する。追記のみ(UPDATE と DELETE をしない)。

| 列 | 内容 |
|---|---|
| id、occurred_at | |
| user_id | 操作した人 |
| action | 下の表 |
| ip_id | 関わる IP(無ければ null)。レポートの絞り込みに使う |
| target_type、target_id | 対象 |
| detail | 補足(JSON) |
| ip、user_agent | リクエストの送り元 |

| 記録する操作 | action |
|---|---|
| IP、条件の版、担当者の変更 | `ip.create`、`ip.terms_add`、`ip.state_change`、`ip.manager_change` |
| 素材の取り込み・取り下げ | `ip.material_add`、`ip.material_withdraw` |
| 許可を出す・取り消す | `ip.grant_add`、`ip.grant_revoke` |
| 素材の詳細を開く、原本のダウンロード(素材と派生物) | `asset.view_detail`、`asset.download_original` |
| 系列の書き出し、レポートの書き出し | `export.lineage`、`export.ip_report` |
| 拒否された操作 | `ip.denied`(何を、なぜ) |
| チームの変更(ADR-0058) | `team.create`、`team.member_add`、`team.member_remove`、`team.delete` |

- Run の入力に使ったことは、Run と `run_ip_use` が正本なので、`audit_event` には重ねて書かない。
- サムネイルや一覧の表示は、件数が多すぎるので記録しない。
- 証跡を見られるのは、管理者と、その IP の担当者(その IP の分だけ)。

### 8. 状況のレポート(第2段)

- IP ごとに期間を区切って、次を出す。素材ごとの利用回数、用途別・作業のメモ別・チーム別・人別の内訳、作った派生物の数、外部の AI に送った回数(接続先別)、原本のダウンロード、拒否された試み、許可の経過。
- 出し方は、画面、CSV、権利者に渡す報告書(1つの HTML。ADR-0037 の納品モードを下地にする)。報告書に実行者の名前を入れるかは、書き出すときに選ぶ(既定は入れない。ADR-0037 と同じ)。
- 「用途の外で使っていない」ことは、すべての利用が申告した用途とともに並び、範囲の外の試みは拒否として残っていることで示す。

### 9. 契約の終了と破棄(第2段)

- 状態を「終了」にすると、許可は全部効かなくなり、素材と派生物は新しく使えない。派生物は作った本人だけに見える。
- **素材の原本の破棄:** 担当者か管理者が行う。ADR-0051 4章の「画像を残さない」と同じ仕組みで原本と派生画像を消し、Asset の行、来歴、記録は残す。破棄したことを証跡に残し、報告書に載せる。派生物の原本は消さない(ロック(ADR-0060)した納品物を守るため)。消す必要があるときは、権利者との取り決めに従って利用者が消す。

### 10. ほかの機能での扱い

- **ADR-0025:** 派生物の見える範囲(6章)だけを例外にする。可視性の関数(`domain/visibility.py`)に条件を足し、判定は今と同じ1か所に置く。
- **ADR-0029(共有リンク):** IP 素材と派生物は、共有の範囲に入れない。
- **ADR-0037(系列の書き出し):** 見える人なら書き出せる(証跡に残す)。manifest に IP、条件の版、申告を含める。
- **ADR-0051(Mod):** イベントの `subject` に IP と申告を含める。外部の接続先の Mod に画像を付けるのは、外部の AI への送信が `allow` のときだけ。
- **ADR-0033、ADR-0056(検索・マップ・グループの提案):** 見える範囲の画像だけを使う(今と同じ)。
- **ADR-0060(ロック):** 派生物はロックできる。素材はロックの対象にしない(取り下げと破棄は9章の規則で行う)。

### 11. 画面

- **IP 素材のパネル**(アイコンレールの盾のアイコン。使えるときだけ出す): 見られる IP の一覧。開くと素材のサムネイルを並べ、ドラッグで入力に使える。
- **IP のページ**(`/ip` は一覧、`/ip/:id` は IP ごと): 名前・区分・権利者・状態と、タブ(素材、条件、担当者。担当者と管理者には許可と証跡も)。状態の変更は管理者だけで、終了は確かめてから。
- **管理者設定の「IP 素材」**(`/settings/ip`): 機能の有効・無効と、IP の作成(最初の条件を含む)。
- **ストック:** IP 素材と派生物の画像に、IP の印を付ける。ビューアの詳細に、IP の名前、条件の版、注記を出す。
- **生成のフォーム:** 入力に IP の画像が入ったら、送るボタンの近くに「用途」と「作業のメモ」を出し、用途を選ぶまで送れないようにする。条件の注記もそこに出す。
- 狭い幅でも、一覧、申告、許可の操作ができること(ADR-0009)。

### 12. 段階

| 段 | 中身 |
|---|---|
| 1 | チーム(ADR-0058)、1〜7章、10章、11章 |
| 2 | 8章(レポート)、9章(終了と破棄) |

ロック(ADR-0060)は IP と独立に使えるので、別に進める。

### 13. 実装で決めた細部(2026-11-01 追記)

- **見える範囲を2つに分ける:** 普段の可視性(`asset_visible` と `get_visible_asset`。変更の操作もこれを通る)には、IP 素材は管理者と担当者だけを入れる。許可を受けた人は、詳細と画像の配信だけを `get_readable_asset` で読む。許可を受けた人が素材のタイトル・タグ・グループを変えたり消したりできないようにするため。
- **素材は普段の削除とロックの対象にしない:** `DELETE /api/assets/{id}` とロックの付け外しは 409。取り下げは IP のページで行う。普段のストックの一覧(`GET /api/assets`)には出さない。
- **取り込みの後の処理:** 外部の AI への送信が `allow` でなければ、自動タイトル・タグ、埋め込み、Mod(判定を待つ購読を含む)に渡さない。焦点(手元)だけを求める。手元の接続先だけに送る `local_only` の細かい扱いは、外部の AI へ送る入口で IP の条件を見る段(5章)で行う。Mod の経路の名前は契約の値 `upload` を使う。
- **許可の対象のチーム:** 担当者は管理者でなくても許可を出すので、`GET /api/ip/{id}/grant-targets` でチームの名前の一覧を返す(チームの API は管理者と入っている人だけのまま)。
- **証跡に足した操作:** `ip.settings`(有効・無効)、`ip.update`(名前・権利者・説明)、`team.member_role`、`asset.lock` / `asset.unlock`(ADR-0060)。
- **`reconcile_storage`(ADR-0046):** IP 素材は、原本が無くても消さない(ロックと同じく件数だけを示す)。

## Options Considered

### Option A: 普段のストックに印を付けるだけ
**Pros:** 作るものが少ない。
**Cons:** 誰でも入れられ、消せ、外部の AI に送られる。許可と用途を守らせられず、記録も利用者の注意に頼る。

### Option B: 別の棚と、許可・申告・引き継ぎ・証跡(採用)
**Pros:** 契約の条件をシステムが守らせ、使ったことを申告とともに残せる。権利者への報告を記録から作れる。
**Cons:** 表と画面が増える。可視性の規則に例外が入る。

### Option C: 利用の申請と承認のワークフロー
**Pros:** 使う前に担当者が1件ずつ確かめられる。
**Cons:** 生成のたびに待ちが入る。ADR-0001 の非ゴール(承認ワークフロー)に当たる。前もって出す許可と、使ったときの申告で足りるので見送る。

### 派生物の見える範囲

| 案 | 評価 |
|---|---|
| 作った本人だけ(ADR-0025 のまま) | 規則は単純だが、チームで素材を使う作業の実態に合わない |
| 同じ許可を持つ人と、IP の担当者(採用) | チームで成果を見せ合える。許可が切れれば見えなくなるので、契約の範囲と見える範囲が揃う。担当者は混入や掛け合わせを見つけられる |
| IP の担当者だけに追加で見せる | 担当者の確認には足りるが、チームの作業には足りない |

### 原本の持ち出し

| 案 | 評価 |
|---|---|
| 許可で止める | ダウンロードは止められるが、画面の写しは止められない。守れているように見えて、実際には守れない |
| 止めずに記録する(採用) | 持ち出したことを、誰が、いつ、何を、で示せる |

## Trade-off Analysis

決め手は、契約の条件を利用者の注意ではなくシステムで守らせることと、使ったことの記録を後から報告に使えること。来歴の記録はもともと追記のみなので、IP の申告を Run に結び付ければ、利用の正本はそのまま来歴になる。足すのは、許可、申告、引き継ぎ、Run に現れない操作の証跡だけで済む。

可視性の例外は漏れの原因になりやすい。判定を `visibility.py` の1か所に置き、ADR-0025 のテスト(REST の全ルートと MCP の全ツール)に、許可のある人・無い人・切れた人の場合を足して守る。

## Consequences

- IP、契約の条件、素材、許可、申告、引き継ぎ、証跡の表が加わる(マイグレーション)。
- 認証モードで、IP の派生物だけは、作った本人以外にも見えるようになる(ADR-0025 の改訂)。
- 外部の AI へ送る入口(ADR-0051)で、IP の条件も見るようになる。
- ADR-0001 のゴールに「預かった素材の管理と利用の記録」を足す。非ゴールの「マルチテナント」と「承認ワークフロー」は変えない(権利者は GAKEI の利用者ではなく、許可は前もって出す)。
- ADR-0006 の `audit_event` が実装される。
- ADR-0029、0037、0051 に、IP の扱いの注記を足す。
