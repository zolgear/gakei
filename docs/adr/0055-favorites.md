# ADR-0055: お気に入り(履歴の画像に印を付け、印で絞り込む)

**Status:** Proposed
**Date:** 2026-10-23

## Context

大量に生成した結果から、残したい画像を拾い上げる手段が無い。ADR-0001 のゴール5は「大量に生成した結果を、採用/不採用で整理できる」で、非ゴールの表も汎用 DAM を作らない理由に「プロジェクト+フラグ+タグで足りる」を挙げている。プロジェクトに当たるグループ(ADR-0022)と、タグ(ADR-0024)はできたが、フラグはまだ無い。ADR-0003 は `asset_mark`(asset_id, user_id, flag(`pick` / `reject`), rating, note。証跡ではないので更新可)を設計だけしてある。

利用者から、履歴で画像の上のアイコンを押してお気に入りを付け外しし、お気に入りだけに絞り込みたいと求められた。

関連する決まり:

- ADR-0003: Asset と Run の二部グラフ。来歴の列は追記のみだが、`asset_mark` は証跡ではない。
- ADR-0022: 利用者の分類(グループ)は証跡ではなく、自由に変えられる。Asset を論理削除しても付随する行は残し、一覧で除く。
- ADR-0025: 認証モードでは本人のものだけを見せる。見えない Asset への操作は「存在しない」と同じ 404。
- ADR-0054: 履歴の並べ替え。日付は Run 単位(`GET /api/runs`)、グループと似た画像の順は画像単位(`GET /api/history/assets`)。続きは自動で少しずつ読む。

## Decision

### 1. お気に入りは `asset_mark` の最初の実装にする

- お気に入りは ADR-0003 の `flag = pick`(採用)に当たる。画面と API では「お気に入り(favorite)」と呼ぶ。
- 今回作るのはお気に入りだけ。不採用(`reject`)、評価(`rating`)、メモ(`note`)は作らない。列も足さない(使わない列を先に作ると、意味と既定値を今決めることになる。足すときは新しいマイグレーションで列を加える)。
- **画像(Asset)ごと・利用者ごと。** 認証モードでは利用者ごとに別の印を持ち、他人の印は見えない(グループは全員で共有する分類だが、お気に入りは個人の好みなので分ける)。個人モード(`AUTH_MODE=none`)は暗黙の利用者として、`user_id` を NULL にする(グループやプロンプトセットの `created_by_user_id` と同じ)。
- **Run ではなく Asset 単位。** 1つの Run が複数の画像を出し、良いのはそのうち1枚、ということが普通にある。履歴のカードも出力ごとに1枚に展開して並べている(ADR-0054)。Run に印を付けると、どの画像を気に入ったのかが残らない。系列(ADR-0003)やストック、ビューアに広げるときも、単位が画像なら同じ印をそのまま使える。
- **証跡ではない。** 付け外しは自由で、外したら行を消す(いつ外したかは残さない)。Run や Asset の来歴の列には書かない。

### 2. データモデル

```
asset_mark(
  id UUID PK,
  asset_id UUID NOT NULL FK asset.id,
  user_id UUID NULL FK app_user.id,     -- 個人モードは NULL
  flag VARCHAR(16) NULL,                -- 今は 'pick'(お気に入り)だけ
  created_at, updated_at TIMESTAMPTZ NOT NULL
)
UNIQUE INDEX ux_asset_mark_asset_id_user_id (asset_id, user_id)
UNIQUE INDEX ux_asset_mark_asset_id_local (asset_id) WHERE user_id IS NULL
INDEX ix_asset_mark_user_id_flag (user_id, flag)
```

- 1つの Asset に、1人の利用者の行は1つだけ。NULL どうしは一意制約で重複とみなされないので(SQLite も PostgreSQL も)、個人モードの行は `user_id IS NULL` の部分一意索引で1つに限る。
- `flag` を NULL 可にするのは、将来 `rating` や `note` だけを持つ行がありうるため。今は印を外すと行を消すので、`flag` が NULL の行はできない。`reject` を足すときは、`pick` と `reject` を同じ列の値にして、同時には付かないようにする(採用と不採用は排他)。
- **Asset の論理削除との関係:** Asset を論理削除しても行は残し、一覧と絞り込みでは `asset.deleted_at IS NULL` で除く。Asset を復元(ADR-0008)すればお気に入りも戻る(グループのメンバーと同じ。ADR-0022)。削除済みの Asset への付け外しは 404。
- 原本を手で消した後に DB を合わせるツール(ADR-0046)は、消す Asset の `asset_mark` の行も消す。
- 認証モードに切り替えた後、個人モードで付けた印(`user_id` が NULL)は誰にも見えない(消さずに残す)。管理者に引き継ぐかは、必要になったら決める。

### 3. API

すべて `require_user` の下。対象の Asset は見る人に見えるもの(`get_visible_asset`。ADR-0025)で、削除されていないもの。それ以外は 404(他人の Asset も「存在しない」と同じ)。

| メソッド | パス | 内容 |
|---|---|---|
| `PUT` | `/api/assets/{id}/favorite` | お気に入りにする → `{asset_id, favorite: true}`。既に付いていれば何もしない(冪等) |
| `DELETE` | `/api/assets/{id}/favorite` | お気に入りを外す → `{asset_id, favorite: false}`。付いていなければ何もしない(冪等) |

- 一覧に状態を載せる: `RunSummary.outputs[]`(`RunOutputRef`)に `favorite: bool`(見る人の印)を足す。出力の参照をまとめて引く問い合わせ(`bulk_output_refs`)に結合して引き、ページの件数によらず問い合わせの数を増やさない(N+1 にしない)。`GET /api/runs`、`GET /api/runs/{id}`、`GET /api/history/assets`(項目の `run` の中)、検索の結果のどれでも同じ値になる。
- 絞り込みはサーバーで行う。続きを自動で少しずつ読むので、読み込んだページの中だけで絞ると、お気に入りの少ない履歴では空のページを延々と読むことになる。
  - `GET /api/runs?favorite=true`: お気に入りの出力(削除されていない)を1つ以上持つ Run だけ。並びとカーソルは今のまま(`queued_at DESC, id DESC`)。
  - `GET /api/history/assets?favorite=true`: お気に入りの画像だけ。グループの並びは節の件数(`groups`)も絞り込みの後の数にする。似た画像の順は、お気に入りの画像だけで並びを作る(全体の並びから抜き出すのではない)。キャッシュの鍵に絞り込みを含める(対象の集合の要約が変わるので鍵は別になるが、意味として明示する)。カーソルは今の形のまま(グループは keyset、似た画像の順は順位)。
  - `favorite=false` と省略は同じ(絞り込まない)。「お気に入りでないものだけ」は作らない。

### 4. 画面(履歴)

- **アイコンはハート。** 星は将来の評価(`rating`。ADR-0003)に残す。
- **画像の右上に置く**(操作の行には入れない。操作の行は狭い幅で1行に収める作りで、余裕が無い)。画像のリンクとは別の要素にし、押しても画像のリンク(ビューアへの移動)は起きない。
  - 詳細の形(重ねるカード): 常に出す。お気に入りなら塗り、そうでなければ線。
  - ギャラリー(石積み・行揃え): お気に入りなら常に塗りで出す。そうでなければ、ホバーできる端末ではマウスを載せたとき・キーボードで中に入ったときだけ線で出す。ホバーできない端末(`hover: none`。スマホなど)では、操作の帯は出さないが、ハートだけは常に線で出し、タップで切り替えられるようにする。
  - 当たり判定はどの形でも 32px 以上(狭い幅の詳細の形は 40px)。
  - `aria-pressed` で状態を示し、`aria-label` と `title` は同じ文(「お気に入り」)。
- 押したら楽観的に表示を変える(react-query のキャッシュの中の、同じ Asset の `favorite` を書き換える)。失敗したら元に戻し、トーストで知らせる。
- **絞り込み:** ツールバーの絞り込みのメニュー(すべて / 成功 / 失敗)に「お気に入り」を足す。状態の絞り込みとは独立の切り替え(`menuitemcheckbox`)で、区切り線の下に置く。お気に入りで絞っている間は、状態の絞り込みと同じくボタンに印を付ける。どの並べ方でも効く。
  - 日付の並びでは Run の出力ごとにカードを出すので、お気に入りの出力のカードだけを出す。
  - 絞り込みの中で外したカードは、絞り込みを切り替えるまでその場に残す(押し間違えをすぐに戻せるように)。
  - 該当が無いときは「お気に入りはありません」を出す。
- 選択は状態の絞り込みと同じく、戻る/進むで戻ったときだけ復元する(保存はしない)。

## Options Considered

### 印の単位

| 案 | 評価 |
|---|---|
| A. Asset ごと・利用者ごと(採用) | 履歴のカードの単位と合う。系列・ストック・ビューアにも同じ印を使える |
| B. Run ごと | 複数の出力のうちどれを気に入ったかが残らない |
| C. Asset ごと・全員で共有 | グループと揃うが、好みは人ごとに違う。認証モードで他人の印が混ざる |

### 表の形

| 案 | 評価 |
|---|---|
| A. `asset_mark` に `flag` だけを持たせる(採用) | ADR-0003 の設計の一部で、`reject` は値、`rating` / `note` は列を足すだけで広げられる |
| B. 専用の `asset_favorite` 表 | 単純だが、採用/不採用・評価を足すときに表が増える |
| C. ADR-0003 の列(`flag`、`rating`、`note`)を全部今作る | 使わない列の意味と既定値を今決めることになる |

### 絞り込みの場所

| 案 | 評価 |
|---|---|
| A. サーバー(採用) | 自動読み込みと合う。少ないお気に入りでもすぐに出る |
| B. クライアント(状態の絞り込みと同じ) | 読み込み済みのページしか絞れない。お気に入りが古いページにあると、全部読むまで出ない |

## Trade-off Analysis

個人モードの `user_id` を NULL にしたので、一意性のために部分一意索引が要る。利用者を表す文字列(`user_preference.owner` の `local`)を使えば索引は1つで済むが、`app_user` への外部キーが張れず、他の表(`created_by_user_id`)と扱いがずれる。

絞り込みの中で外したカードを残すのは、表示とサーバーの状態が一時的にずれることになる。押し間違えを戻せることを優先した。絞り込みを切り替えれば揃う。

## Consequences

- 新しい表 `asset_mark` とマイグレーションが増える。
- `RunOutputRef` に `favorite` が増え、`GET /api/runs` と `GET /api/history/assets` に `favorite` の問い合わせの引数が増える。
- 履歴の画像の右上にハートのボタンが増え、絞り込みのメニューに「お気に入り」が増える。
