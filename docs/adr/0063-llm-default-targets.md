# ADR-0063: LLM・VLM の既定の送り先を、外部とローカルの2組で1か所に決める

**Status:** Proposed
**Date:** 2026-11-06

2026-11-06 に、ユーザーが #238 の進め方を決めた。LLM・VLM の既定の送り先(接続先とモデル名)は、外部とローカル(ユーザーの言葉では内部)の2組を1か所で決める。対象の画像を作ったモデルがローカルならローカルの既定を使い、外部なら外部の既定を使う。画面の言葉は、ADR-0051 3章の接続先の区分(外部 / ローカル)にそろえる。組み込みの既定のモデルは `gpt-6-luna` にする。

## Context

- LLM・VLM のモデル名を、機能ごとに入れている(自動タイトル・タグ、生成のアシスタント、領域の検出、グループの名前の提案、SVG を書くモデル)。新しいモデルが出るたびに、管理者は同じ名前を何か所にも入れ直している。
- 組み込みの既定のモデル名(`gpt-5.6-luna`)が、5か所のコードに直接書いてある。gpt-6 系が出て、古くなった。
- 自動タイトル・タグだけは、「既定」と「ComfyUI の画像」の2つの組を持つ(ADR-0024 8章)。手元で作った画像を手元の VLM に送るための仕組みだが、見分け方はプロバイダーが `comfyui` かどうかで、接続先の区分(ADR-0051 3章の `locality`)とは別になっている。
- 画像の生成の区分(外部 / ローカル)は、ADR-0051 3章で決まっている(`ip_usage.run_locality`。プロバイダーの接続の値、ComfyUI はワークフローの値を優先)。

## Decision

### 1. 既定の送り先(2組)

- 管理者設定の「LLM の接続先」の画面に、「既定の送り先」を置く。
  - **外部の既定:** 接続先とモデル名。何も保存していなければ、組み込みの接続先(OpenAI の設定)と `gpt-6-luna`。
  - **ローカルの既定:** 接続先とモデル名。保存していなければ外部の既定を使う(今の「ComfyUI の画像」の組が null なら既定と同じ、と同じ扱い)。
- 保存先は `app_setting` の `llm_defaults.external` / `llm_defaults.local`(`{connection_id, model}`)。API は `PUT /api/settings/llm-connections/defaults`(管理者)で、一覧の応答 `GET /api/settings/llm-connections` の `defaults` に今の値を返す。既定の送り先が使う接続先(外部は保存していなければ組み込みの接続先)は、`register_usage` で「使っている」と答える(削除できない)。
- 組み込みの既定のモデル名は `llm_connections.BUILTIN_DEFAULT_MODEL` の1か所だけに置く。

### 2. 画像の区分

- 画像の区分は、その Asset を作った Run の区分(`ip_usage.run_locality`)。
- Run の無い Asset(アップロード、スケッチ、合成)は外部として扱う。
- 自動タイトル・タグの待ち行列は、1時間の上限に達した組の行を飛ばす(ADR-0024 8章)。そのため区分を SQL の条件でも表す(`llm_defaults.local_run_condition`。プロバイダーの接続先の値と、それを上書きする ComfyUI のワークフローの値から作る)。

### 3. 各機能

各機能の送り先は「既定の送り先」を既定にし、機能ごとに別の接続先とモデル名を選ぶこともできる(上書き)。上書きは、その機能のすべての画像に使う。

| 機能 | 既定の送り先の選び方 |
|---|---|
| 自動タイトル・タグ(LLM・VLM) | 対象の画像の区分。今の「既定」「ComfyUI の画像」の組は「外部の画像」「ローカルの画像」の上書きにする(用途ごと。null は既定の送り先) |
| 領域の検出 | 対象の画像の区分 |
| グループの名前の提案 | 名前を付ける集まりにローカルの画像が1枚でもあればローカル、無ければ外部 |
| 生成のアシスタント | 外部(画像に結び付かない) |
| SVG を書くモデル | 外部の既定の接続先が組み込みの接続先ならそのモデル名、そうでなければ `BUILTIN_DEFAULT_MODEL`。OpenAI の画像の API が書き手を呼ぶため |

### 4. 移行

- 機能ごとに保存してあるモデル名と接続先は、上書きとして残す(画面で「既定の送り先」に戻せる)。アシスタント・領域の検出・グループの名前の提案で、モデル名だけ(または接続先だけ)を保存していたら、もう片方は以前の既定(組み込みの接続先、組み込みの既定のモデル)で埋める。上書きは、接続先とモデル名をそろえて保存する(どちらかに null を送ると上書きを消す)。
- 機能ごとに一度も保存していない項目は、既定の送り先に従う。今まで `gpt-5.6-luna` を使っていたところは、`gpt-6-luna` に変わる。
- 自動タイトル・タグの組(`annotation.profiles`)は、読むときに移す。「既定」(`default`)は「外部の画像」(`external`)、「ComfyUI の画像」(`comfyui`)は「ローカルの画像」(`local`)の上書きになる。「ComfyUI の画像」の null(既定と同じ)は、送り先が変わらないよう「既定」の組で埋める。次に保存したとき新しい形で書く。
- 見分け方がプロバイダーから区分に変わる。ComfyUI の接続先は既定では外部(ADR-0051 3章)なので、ComfyUI の接続先を「ローカル」にしない限り、ComfyUI の画像は「外部の画像」のマスを使う。区分は ADR-0051 の判定にも効く値なので、移行で勝手に変えない(利用者向けの説明は `docs/auto-tags.md`)。ローカルの接続先にした OpenAI 互換の画像のプロバイダーの画像も、ローカルの側に入る。

### 5. 対象外

- 画像のモデル(`gpt-image-*`)は `openai_spec` の一覧から選ぶので対象外。
- 画像の埋め込み(ADR-0033)は、テキストのモデルと別の種類のモデルなので対象外。
- 料金の単価(`openai_pricing.SVG_AUTHOR_PRICES`)は今のまま。LLM の料金を出すのは SVG の書き手だけなので、登録と結び付けない。

## Options Considered

- **接続先ごとに既定のモデルを持たせる:** 機能は接続先だけ選ぶ。外部とローカルを使い分けるには、結局機能ごとに接続先を2つ選ぶことになり、入れ直す場所が減らない。
- **全体で1つの既定のモデル:** ローカルの接続先(Ollama など)に gpt の名前を送ってしまう。
- **接続先ごとにモデルの一覧を登録して選ぶ:** 画面の変更が一番大きく、モデル名を1か所で変える目的には要らない。

## Consequences

- 新しいモデルに変えるときは、既定の送り先の1か所を変えればよい。
- ローカルの既定を決めておけば、ローカルで作った画像はどの機能でもローカルの接続先に送る。
- 自動タイトル・タグの組の見分け方が、プロバイダーから区分に変わる。
