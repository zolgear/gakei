# ADR-0009: スタジオの画面構成、プロンプトセット、系列グラフの前倒し

**Status:** Proposed
**Date:** 2026-09-21

## Context

ローカルMVP(ADR-0008)の最初の画面は、左にフォーム、中央に状態、右に履歴の3ペインだった。実際に触った結果、次の点が分かった。

- 履歴が主役であるべきなのに、右端の細い列に押し込められている。
- 元画像や過去の生成物(ストック)を置く場所がない。
- 同じ系統のプロンプトを何度も打ち直している。
- 「何から何が生まれたか」を一覧から辿れない。

これを受けて、画面構成のデザインを作成した(App バー、リソース用のサイドバー、カード形式の履歴)。デザインには、ADR-0001 のゴールにない「プロンプトセット」と、当初の計画で Phase 2 としていた「世代ツリー表示」が含まれる。CLAUDE.md の作業ルールに従い、実装の前にここで決定を記録する。

## Decision

### 1. 画面構成

- **App バー:** ロゴ、ワークスペースのタブ(履歴 / スタジオ)、キューの状態、「新規作成」。(当初は使用中のプロバイダーも表示していたが、ADR-0013 で Run ごとにモデル選択でプロバイダーを選ぶ形になり、フォームの表示と重複するため外した。)2026-10-04 追記(ADR-0033、ユーザーの指示): タブは「生成」「履歴」「マップ」の順にした。マップは埋め込みが使えるときだけ出す。
- **メイン領域:** タブで切り替える。履歴はカード形式の一覧。スタジオにフォームと実行状態の表示を置く。
- **生成画面はメイン領域を上下に分ける(2026-09-22 承認)。** 上段は結果エリアで、直近の実行結果を大きく表示し、「プレビュー / 系列」を切り替えられる。出力のサムネイル列から画像を選び「入力に使う」と、そのまま下段で Edit を続けられる。下段は入力エリアで、入力画像のチップ行、プロンプト欄、設定のグリッド(モデル、サイズ、画質、枚数、形式、背景。その他は畳む)を横に展開し、スクロールなしで全体を把握できる幅では横並び、狭い幅では縦積みにする。説明文は置かず、ツールチップに移す。実行は Ctrl+Enter でも行える。左フォーム・右進捗の3ペインはやめる。
  - **入力画像の追加はダイアログから(2026-09-26 追加):** 「+ 追加」を押すと、ファイル選択にいきなり進まず、アプリ内のモーダルで「ファイルを選ぶ」と「ストックから選ぶ」(kind で絞り込めるサムネイルの一覧。複数選択して追加)を出す。ドラッグ&ドロップと貼り付けはこれまでどおり直接追加する。ストックパネルの「+」(入力に使う)もそのまま残す。
  - **入力欄の配置を選べる(2026-09-26 追記):** 入力エリアは「左のサイドバー」(既定。2026-09-27 に下段から変更)と「下段」のどちらにも置ける。サイドバー配置では、モデル → 入力画像(正方形のサムネイルのタイル。「+ 追加」と「スケッチ」もタイルにする。番号・マスク・「マスクを描く」「描き込む」「外す」・プレビュー表示はチップ行と同じ)→ プロンプト(セット・保存・文字数)→ サイズと主なパラメーター → その他(畳む)の順に上から下へ並べ、参考価格と生成ボタンは列の下端に固定する。列は縦にスクロールし、幅はドラッグで変えられる(localStorage `gakei:studio-input-width`)。配置は設定画面の「表示」で選び、結果エリアの右上のボタンでも切り替えられる(localStorage `gakei:studio-layout`。既定はサイドバー。2026-09-27 に下段から変更)。フォームの部品(プロンプト欄、モデル選択、パラメーター、送信)は両配置で同じコンポーネントを使い、状態も1か所に持つ(切り替えても入力中の内容は変わらない)。狭い幅(768px 未満)では設定に関わらず従来どおり結果 → 入力の縦積みにする(5章)。2026-09-22 の上下分割は選択肢として残す(2026-09-27 まで既定だった)。
- **ブラウザのダイアログ(`window.confirm` / `alert` / `prompt`)は使わない。** 確認はインラインかアプリ内のモーダルで行う。
- **生成と編集を UI で区別しない。** フォームは1つで、入力画像は任意の欄とする。入力画像が1枚もなければ Generate API、1枚以上あれば Edit API を呼ぶ。利用者が操作の種類を選ぶ場面は作らない。
  - どちらの API を呼んだかは、これまでどおり `run.operation` に記録する(証跡として必要)。画面では、入力画像の有無と枚数として見せれば足り、操作名を前面に出さない。
  - API ごとに使えるパラメーターが違う場合は、入力画像の有無に応じてフォームの項目を出し分ける。使えなくなった項目の値は送らない。`moderation`(Generate のみ)はフォームに出さず、サーバー側の設定値を Run 作成時に `params` へ入れる(2026-09-22)。設定値は設定画面で `auto` / `low` から選べる(2026-09-24)。優先順は ComfyUI の接続先(ADR-0013 7章)と同じで、画面で保存した値(`app_setting`)、環境変数 `MODERATION`、既定の `low` の順。変更は再起動なしで次の Run から反映し、実行中・待機中の Run の `params` は変えない。
  - **参考価格(2026-09-22):** 生成ボタンの左に、現在の設定で1回実行したときの参考価格(USD)を出す。出力トークン数は、画像生成ガイドの「Calculating costs」にある公式の計算機(https://developers.openai.com/api/docs/guides/image-generation#calculating-costs)と同じ式で計算する(サイズと画質から決まる。こちらの実績 `run.usage.output_tokens` と一致することを確認済み)。入力画像のトークンは公式には未公開なので、vision ガイドの 32px パッチ式(予算 1536 パッチ)で推定する(Edit の実績と一致)。`quality=auto` / `size=auto` は計算できないので「参考なし」。単価表(料金ページ https://developers.openai.com/api/docs/pricing)はサーバー側 `providers/openai_pricing.py` に確認日付きで持ち、API は `GET /api/pricing/estimate`。成功した Run には `usage` × 単価の実コスト(`cost_usd`)も添える。いずれも請求額ではなく参考値(途中経過画像とマスクは含まない)。
  - **送信後のフォーム(2026-09-24 改訂。2026-09-22・09-23 の決定を置き換える):** Stable Diffusion(Gradio)などと使い勝手を合わせ、送信してもフォームは何も変えない。プロンプト、入力画像(マスク含む)、モデル、パラメーターはそのまま残り、編集可能で、保存(localStorage)にも残る。出力を入力画像に自動で追加することもしない(利用者が「入力に使う」で明示的に追加する)。フォームを空にするのは「新規生成」だけで、プロンプト、入力画像(マスク含む)、モデル、パラメーターをすべて初期値(capabilities の既定)に戻す。
  - **「新規生成」のショートカット(2026-09-24):** Alt+N(Mac は Option+N)。ブラウザが予約している Ctrl/Cmd+N・Ctrl/Cmd+Shift+N は避ける。入力中の内容があるときはボタンと同じく確認ダイアログを出す。
  - **生成中の Run を開き直す(2026-09-23):** 生成画面は `/studio?run=<id>` で、その Run の進捗(完了後は結果)を表示する。送信時にも URL をこの形にする(リロードで進捗表示に戻れる)。履歴で実行中・待機中のカードの画像部分を押すと、Run 詳細ではなくここへ移る。ほかの画面に移ってからスタジオのタブやサイドバーで戻ったときも、その Run が実行中・待機中なら、この画面に戻す(2026-09-24)。
- **サイドバー:** リソースとデータの置き場所。アイコンレールで ストック / プロンプトセット / 系列グラフ を切り替える。
  - **右側に置き、スタジオ内で参照する(2026-09-26 改訂):** サイドバー(アイコンレール + パネル)はメイン領域の右側に置く。入力欄を左に置くサイドバー配置と合わせ、「左: 入力 / 中央: 結果 / 右: リソース」の並びにする。スタジオ(`/studio`)にいる間は、パネルで選んだもの(ストックの画像、系列のノード、Run 詳細内の入出力)をページを離れず結果エリアに表示する(画像は `?asset=`、完了済みの Run は `?run=` で Run 詳細の中身を結果エリアに埋め込む。結果エリアの「Generated 詳細」も同じ)。スタジオ以外ではこれまでどおりビューアと Run 詳細ページへ移動する。
  - **履歴と検索のパネル(2026-09-26 追加):** アイコンレールに 履歴 / 検索 を足す。履歴パネルは直近の Run を縦一列(サムネイル、プロンプトの抜粋、状態、日時)で並べ、検索パネルはグローバル検索(6章)と同じ API を使って 実行 / 画像 / プロンプトセット の結果を縦に並べる。どちらも、スタジオでは選んだものを結果エリアに表示し、プロンプトセットの項目はプロンプト欄に読み込む。履歴ページと検索ページはそのまま残す(パネルはその圧縮版で、一覧の削除や絞り込みは持たない)。アイコンレールのボタンは常にパネルを開閉する(以前は系列ページで「系列」を押してもパネルを開かなかったが、押せるのに反応しないほうが分かりにくく、開いても壊れるものは無いのでやめた。メインと同じ内容が二重に見えるだけ。系列ページを開いた瞬間に系列パネルを自動で畳む挙動は残す)。
- 雰囲気は ComfyUI に寄せる(ダークなグラファイト、ドットグリッド、ノードと配線、等幅のメタ情報)が、ノードエディタは作らない(ADR-0001 の非ゴールのまま)。
- 主な対象は PC のブラウザ。ただし **最低限のモバイル対応** を行う(下記 5)。

### 2. プロンプトセット(新規。ADR-0001 のゴールに追加)

名前を付けたプロンプトの集まり。選ぶとフォームのプロンプト欄に読み込む。

| テーブル | 主な列 | 備考 |
|---|---|---|
| `prompt_set` | id, name, created_at, updated_at, deleted_at | |
| `prompt_set_item` | id, prompt_set_id, label(null可), text, position, created_at, updated_at, deleted_at | |

- **証跡ではない。** `asset_mark` やタグと同じ扱いで、更新と論理削除ができる。
- **Run との間に外部キーを張らない。** `run.prompt` には実行時の文字列をそのまま保存する(ADR-0003 のとおり)。プロンプトセットを後から書き換えても消しても、Run の記録は変わらない。
- パラメーターは持たせない。プロンプトの文字列だけを扱う。パラメーターの再利用は Run 詳細の「同じ設定で再実行」で足りている。
- **組み合わせて使う(2026-09-23 追加):** セットの項目は「置き換え」ではなく **プロンプトの末尾に追加** する(サイドバーから選んだとき。確認ダイアログは出さない)。加えて、プロンプト欄で `@` に続けて文字を打つと、セット名・項目のラベル・本文で絞り込んだ候補が出て、選ぶと `@…` の位置に本文が挿入される(メンション風の呼び出し)。置き換えたいときは全選択して打ち直せば足りる。
- 変数の埋め込み(テンプレート)、共有、バージョン管理は作らない。

### 3. 系列グラフ(Phase 2 からの前倒し)

- ある Asset を起点に、祖先(その Asset を生んだ Run と入力)と子孫(その Asset を入力に使った Run と出力)を、Asset と Run の二部グラフとして表示する。読み取り専用。
- API は `GET /api/assets/{id}/lineage`。ノード(asset / run)とエッジ(role, position, 主たる親かどうか)を返す。深さに上限を設ける。深さの上限と祖先方向の既定値は 255 ホップ、ノードの上限は 1000 件(2026-09-24 改訂、ADR-0014 6章)。子孫方向の既定値も 255 ホップにした(2026-10-07 改訂)。
- ADR-0003 のルール5(ツリー表示は position 0 の親だけを辿る)は次のように扱う。主たる親のエッジを実線で強調し、その他の入力は参照として破線で描く。失敗した Run も破線で表示する。
- 描画は ADR-0002 で候補に挙げた React Flow を使う。レイアウトは深さごとの単純な段組みで、自動レイアウトのライブラリは追加しない。
- 開いたとき(と枠の大きさが変わったとき)の自動の表示は、全体が読める倍率(0.75 倍。ノードの 11px の文字が約 8px)で収まれば全体を収め、収まらなければ 0.75 倍で止めて、開いている画像・選んだノード(無ければ起点)を中央に置く。サイドバーの系列パネルなど小さい表示(枠の高さ約 340px)は、小さい系列の全体が見えることを優先して下限を 0.5 倍にする(ユーザーが選択)。「全体を表示」と手動のズームアウトは 0.05 倍まで下げられる。共有のページの系列グラフも同じ(2026-10-07 追記)。
- 兄弟比較(2枚並べ)、グラフ上での編集、グラフからの実行は作らない。

### 4. ストック

- 既存の `GET /api/assets`(kind で絞り込み)と `POST /api/assets` をそのまま使う。新しいテーブルは作らない。
- 検索は作らない(Phase 2 のまま)。

### 5. 最低限のモバイル対応(ADR-0001 の非ゴールを一部緩和)

開発中はスマートフォンから確認する場面がある。確認作業が止まらないよう、スマートフォンの幅でも一通り操作できる状態にする。「最適化」はしない。

- 狭い幅では1カラムにする。サイドバーはドロワー(開閉式)にし、履歴カードは1〜2列にする。
- 横スクロールが出ない。文字と入力欄が拡大なしで読める(iOS の自動ズームを避けるため、入力欄は 16px 以上)。タップ対象は 44px 以上。
- 生成、編集(入力の追加、並べ替え)、履歴、Run 詳細、ビューア(ピンチでの拡大縮小)、ストック、プロンプトセット、系列グラフが、タッチで操作できる。
- マスクの描画は指で描ける(Pointer Events、`touch-action: none`)。細かい描き心地の調整はしない。
- 作らないもの: モバイル専用の画面やナビゲーション、PWA、オフライン対応、端末ごとの作り込み、モバイルでの性能調整。

### 6. グローバル検索(2026-09-22 追加。Phase 2 の「プロンプト検索」の前倒し)

- App バーに検索欄を置き、1つの入力で **実行(Run)、画像(Asset)、プロンプトセット** を横断して検索する。
- 対象はテキストだけ。Run は `prompt`、Asset は「それを生んだ Run の prompt」、プロンプトセットは名前と項目の本文。部分一致(大文字小文字を区別しない)。
- アップロードした画像はテキストを持たないため、今は見つからない。画像の埋め込み(embedding)による検索は将来の拡張とし、API の形(`GET /api/search?q=`)はそのまま使えるようにしておく。類似画像検索は Phase 3 のまま(ADR-0001)。
- 全文検索インデックス(FTS)や形態素解析は入れない。件数が増えて遅くなったら検討する。
- 削除済みの Run / Asset は結果に含めない。
- **検索の入力と結果はサイドバーの検索パネルに一本化する(2026-09-26 改訂):** App バーの検索欄とポップオーバーはやめ、App バーには虫眼鏡のボタンだけを置く。押す(または `/` キー)とサイドバーの検索パネル(1章)を開いて入力欄にフォーカスする。結果の表示先を画面ごとに分ける実装(スタジオでは結果エリア、それ以外はページ遷移)をパネルと App バーの両方で持たないため。検索ページ(`/search`)は「すべての結果を見る」から開く。

### 7. 編集前との比較(2026-09-23 追加)

- Edit で生成した画像について、入力画像(編集前)と出力画像(編集後)を並べて見比べる **比較ビュー** を置く。Generate の出力(入力が無い)には出さない。
- 入口: Asset ビューアと Generated(Run 詳細)の「元になった画像: 表示する」の横に「編集前と比較する」。
- 表示モードは2つで、切り替えられる。
  - **並べて表示:** 左に入力、右に出力。パン(掴んでのスクロール)とズームは左右で同期する。スマートフォンの幅では使わず、下のスライダーにする。
  - **スライダー:** 2枚を重ね、縦の分割バーを左右にドラッグして、左側に入力、右側に出力を見せる。パンとズームは2枚で共通。
- 比較中は左のサイドバーを畳み、画像の表示領域を広げる。閉じると元に戻す。
- 入力画像が複数ある Run、出力が複数ある Run では、比較する入力と出力をそれぞれ選べる。既定は主たる親(position 0 の `image`)と、開いた出力(Run 詳細から開いた場合は先頭の出力)。マスクは選択肢に含めない。
- 入力と出力で縦横の寸法が違う場合は、両方を同じ表示枠に contain で収め、枠の中の同じ相対位置を同期させる。
- 差分の強調表示、オニオンスキン(半透明の重ね合わせ)、3枚以上の同時比較は作らない。

### 8. ブラウザのタブで進捗を示す(2026-09-26 追加)

生成を待つ間は別のタブで作業することが多く、GAKEI のタブに戻らないと状態が分からない。ComfyUI がタブの favicon で進捗を出すのと同じように、GAKEI も favicon で Run の状態を示す。**App バーのロゴも同じ状態を同じ動きで表示する**(遊び心。favicon の動きの意味を画面内で学べる)。ロゴの「田」の4マスを **1マス単位** で使い、通常時の図形は変えない。

- **表現。** 素材は `docs/assets/favicon-progress/`(`demo.html` で全パターンを確認できる)。
  - 待機中: 蓋(上辺)を外した空の箱。
  - 実行中で進捗が取れるとき: 左下 → 右下 → 左上 → 右上 の順に1マスずつ埋まる(素材の 4b)。埋めるのは3マスまでで、4マス目は成功時にだけ点ける。進捗は ComfyUI のステップ進捗(`value / max`。ADR-0013)と、OpenAI の途中経過画像(届いた枚数を「出力枚数 × `partial_images`」で割る)から求める。ComfyUI はサンプラーのノードごとに値が戻るので、マス数は Run の中で減らさない。ステップが多いとマスが長く増えず止まって見えるので、埋まったマスの色をランプに沿って1マスずつ流し、次に埋まるマスを薄く明滅させる(25% 刻みは変えない。2026-09-26)。
  - 実行中で進捗が取れないとき: 蓋を外したまま、光るタイルが時計回りに移る(素材の 2a と 4c)。4コマ。
  - 成功: 4マス満杯の箱に蓋が閉まる(0.7秒)→ 通常ロゴ。タブが非表示なら右上に通知ドットを出し、表示に戻ったら消す。
  - 失敗: 右下のマスだけ赤。表示に戻ったら通常ロゴ。キャンセルは通常ロゴに戻すだけ(待機中しか取り消せないので専用の表現は要らない)。
  - 成功と失敗の演出は、実行中・待機中だったのをそのタブで見た Run にだけ出す。完了済みの Run を開き直しただけ(リロード、履歴から開く)では出さない。
- **App バーのロゴ。** favicon と同じ描画関数から同じ状態を受け取り、1つの情報源で両方を動かす(favicon だけ、ロゴだけの状態を作らない)。枠線の色は今までどおり親要素の文字色を継承し、マスの色は素材のランプ(左上 Violet → 右下 Pink)を使う。ロゴの使用ルール「タイルの色の入れ替えはしない」の例外は、この進捗表示だけ。キューの状態のバッジ(件数)はそのまま残す。ロゴは件数を表さないので重複しない。
- **信号。** 生成画面で開いている Run の SSE(`status` / `progress` / `partial`)を優先し、無ければ App バーのキュー件数(4秒ごとのポーリング)から決める。見ていない Run が実行中なら回転で示し、件数は出さない。SSE が切れたら進捗不明として回転に落とす。
- **実装。** フロントだけで完結し、バックエンドと API は変えない。SVG を JS で組み立てて `data:` URL で `<link rel="icon">` を差し替える(SVG の中のアニメーションは Chrome の favicon で再生されない)。Safari は SVG の favicon を表示しないので、canvas で 64px の PNG に変換して差し替える(ブラウザで切り替え。枠線の色はそのときの配色に合わせる)。非表示タブではタイマーが1秒に1回まで間引かれるため、回転はコマが飛んでも読める4コマにする。
- **設定(2026-09-26 追加)。** タブのアイコンの動きが気になる人向けに、設定画面に「タブのアイコンで進捗を示す」の切り替えを置く(既定はオン)。オフにするとタブのアイコンは通常の favicon のまま変えず、App バーのロゴの動きはそのまま残す。ブラウザごとの好みなので保存先は localStorage(表示言語と同じ扱い)で、サーバーの設定にはしない。
- **作らないもの。** タブのタイトルへの `[42%]` の付与、OS の通知(Notification API)、音、上記以外の設定項目(速さ、パターンの選択など)、素材の他のパターン(点灯、水位、外周、残像)。必要になったら素材から足す。

## Options Considered

| 案 | 評価 |
|---|---|
| A: 3ペインのまま、見た目だけ整える | 変更は最小だが、履歴とリソースの置き場所の問題が残る |
| B: 画面構成を変え、サイドバーはストックだけ作る | ADR の変更が不要。プロンプトの打ち直しと系列の辿りにくさが残る |
| C: 画面構成を変え、3つとも作る(採用) | 作業量は大きいが、試行錯誤の管理(動機の3番目)に直接効く。データモデルの追加は証跡に影響しない2テーブルだけ |

## Trade-off Analysis

プロンプトセットは「迷ったら作らない」に反して見えるが、証跡のモデル(`run` / `run_input` / `asset`)に一切触れず、Run との結合も持たない。後から捨てても来歴データは無傷で残る。範囲が膨らむリスクは、パラメーターとテンプレートを持たせないことで抑える。

系列グラフは、データと再帰の辿り方が ADR-0003 で既に決まっており、追加するのは読み取り API と表示だけである。Edit を繰り返す使い方では、グラフがないと「主たる親」の記録が活きない。

## Consequences

- ADR-0001 のゴールに「プロンプトセット」を追加する。非ゴールのうち「モバイル最適化」は「最低限の表示と操作には対応する」に改める。それ以外の非ゴールは変えない。
- 当初の計画で Phase 2 としていた「世代ツリー表示」は、この ADR で MVP に前倒しとなる。兄弟比較と一括生成は Phase 2 のまま。
- フロントの依存に React Flow(`@xyflow/react`)が増える。
- 本線(PostgreSQL)へ移るときは、`prompt_set` に `project_id` と `created_by` を足す。
