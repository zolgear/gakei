# ADR-0048: 生成のアシスタント(チャットでプロンプトとプロンプトセットを作る)

**Status:** Proposed
**Date:** 2026-10-13

2026-10-13 に、ユーザーが次のように指示した。

- GAKEI の中で動く AI エージェントを作る。形はチャットで、まずは生成のアシストを行う。
- 最初にできること: プロンプトを作ること、プロンプトセットを作成・編集すること。

同日、次の4点もユーザーが決めた。

- 置き場所: 右のサイドバーのパネルにする。
- プロンプトセットへの書き込み: 提案を挟まず、エージェントが直接書き込む。
- 会話: サーバーの DB に保存する。
- 画像: 最初の版から、ストックの画像を添付できる。
- 生成: アシスタントにも生成させる。例えば「ランダムに5枚作る」「三面図を1枚ずつ作る」のような作業を任せられるようにする。

同日、ユーザーがこの ADR を承認した。生成の歯止め(9章)も入れる。

同日、ユーザーが次の段階としてストックの捜索(10章)を選び、承認した。

同日、ユーザーが、生成フォームに入っているパラメーターの読み込みと書き込みをアシスタントに許すよう指示した(11章)。書き込むのはブラウザのフォームだけで、サーバーには何も保存しない。ストックの整理(タグ、グループ)は後に回し、作るときはプロンプトセットと同じく、直接書き込んで「元に戻す」を付ける。

2026-10-15 に、ユーザーが生成結果の読み取り(12章)を指示し、承認した。生成した結果がいまいちだったときに Edit のプロンプトを頼むと、アシスタントはプロンプトと会話だけを見て考えていた。結果の画像(と、そのタグなど)を読んだ上で考えるようにする。

2026-10-25 に、ユーザーがストックの整理(13章)に着手するよう指示し、次の3点を決めた。

- 書き込む範囲: タグの付与と削除、グループへの振り分け、タイトルの変更。グループの提案(ADR-0056)を読み取りの道具にする。
- アシスタントが書き込んだタグとタイトルは、人の編集と同じに扱う(自動の再推定で上書きしない)。
- ストックで選んでいる画像を、送信のたびにアシスタントに伝える。

同日、実際の会話を見直したところ、検索の結果が文字数の上限で JSON の途中から切れ、アシスタントが一部の画像を見落としたまま書き込んでいた。ユーザーは直す案(14章)を承認し、次の3点を決めた。

- LLM に画像を送る前に、利用者に許可を求める。答えは「1度だけ許可」と「常に許可」。
- 画像を探すときは、まず検索の道具で行う。
- X 以上の画像の情報は、接続先が外部のときは送らない。接続先がローカルなら、この制限はかけず、ほかの決まりに従う。

## Context

- Issue [#8](https://github.com/zolgear/gakei/issues/8) は、GAKEI のバックエンドで動くエージェントを「着手前に ADR を起草する」としていた。この ADR はその最初の段階にあたる。範囲を生成のアシストに絞る。
- LLM の接続先は ADR-0032 で機能から独立させた。理由の一つが「プロンプトのアシストなど、これから作る機能」だった。使う機能は `register_usage` で足せる。
- 今の LLM の呼び出し(`annotation/engines.py`)は、1回のリクエストで1つの答えを得るだけである。ストリーミングも tool calling も使っていない。Responses と Chat Completions の両方に対応している。
- プロンプトセット(ADR-0009 2章)は証跡ではない。更新と論理削除ができ、版の履歴は持たない。MCP(ADR-0023)は、外部のエージェントの誤操作で失うものを作らないため、プロンプトセットの編集を提供していない。
- ADR-0001 は、Open WebUI のようなチャット型の UI を採らなかった。理由は、4K の画像を表示できないことと、Edit の UI が足りないこと。この ADR のチャットは生成フォームの横に置く補助である。生成と閲覧の UI を置き換えるものではない。

## Decision

### 1. 範囲

- アシスタントができること:
  1. 利用者と対話して、プロンプトを作る・直す・訳す。
  2. 作ったプロンプトを、利用者のボタン操作で生成フォームに入れる。
  3. プロンプトセットを読む・作る・編集する。
  4. 添付されたストックの画像を見て、プロンプトを作る。
  5. 生成・Edit の Run を作り、結果を見て次の Run を作る(9章)。
  6. ストックの画像を探し、見つけた画像を示す。見つけた画像は生成の入力にも使える(10章)。
  7. 生成結果の画像とタグを読んで、直すプロンプトを作る(12章)。
  8. ストックの画像にタグとタイトルを付け、グループに振り分ける(13章)。
- LLM に送る情報の絞り方は 14章で決める。
- **最初の版でしないこと:**
  - 削除(プロンプトセット、項目、Asset、グループ)。
  - 管理者設定と利用者の設定の変更。
  - グループの整理とタグの付与は、13章で扱った。
- MCP(ADR-0023)には、アシスタント用のツールを出さない。アシスタントの道具は GAKEI の中だけで使う。

### 2. 画面

- IconRail に「アシスタント」のパネル(ID `assistant`)を足す。中身は SidebarPanel に置き、既存のパネルと同じく開閉と幅を保存する。768px 未満ではドロワーに入る(ADR-0009 5章)。
- パネルの上部で、会話を選ぶ・新しく始める・名前を変える・消す。
- 送信欄に、ストックの画像を添付するボタンを置く。添付はサムネイルで見せる。
- 応答は、届いた分から順に表示する(ストリーミング)。止めるボタンを置く。
- アシスタントがプロンプトを出したときは、プロンプトのカードとして見せる。カードには「フォームに入れる(末尾に追加)」「フォームを置き換える」「コピー」のボタンを付ける。
  - フォームへの反映は、既存の `requestPromptInsert` を使う。置き換えるときに入力済みのプロンプトがあれば、確認する(`usePromptLoader` と同じ)。
- アシスタントが Run を作ったときは、Run のカードを出す。カードでは、進捗(SSE。既存の `useRunEvents`)と出力のサムネイルを見せる。サムネイルを選ぶとスタジオの結果エリアに出す(`?asset=`)。
- アシスタントがプロンプトセットを書き換えたときは、結果のカードを出す。カードには、対象のセット、変更前と変更後、「元に戻す」のボタンを付ける(4章)。
- 管理者が無効にしているときは、パネルを出さない。
- **開閉のショートカット(2026-10-25):** Alt+A(Mac は Option+A)。IconRail のボタンと同じく、閉じていれば開き、開いていれば閉じる。新規生成の Alt+N(ADR-0009)と同じ方式にする。
- **2026-10-24 に改めた(ユーザーの指示。Issue #8 のストックの整理に向けて):** アシスタントはサイドバーのパネルをやめ、どの画面にも重ねて出せる浮いた窓(背後を操作できるダイアログ)にする。サイドバーは1度に1つのパネルしか開けないため、アシスタントに頼みながらストックなどの変化を見られなかった。
  - 開き方: サイドバーのアイコンの列の一番下のボタン。どの画面(スタジオ、履歴、マップなど)からも開ける。IconRail のアシスタントのパネルは外す(保存された選択が `assistant` なら、何も開いていない扱い)。
  - 窓: 見出しをドラッグして動かし、端で大きさを変える。位置と大きさはブラウザに保存し、画面の外に出ないよう収める。たたむ(見出しだけにする)と閉じるを置く。たたんでも閉じても、応答の受け取りと会話は続く(会話はサーバーに保存済み。3章)。背後の画面は今までどおり操作できる(暗くしない、フォーカスを閉じ込めない)。
  - 768px 未満: 画面の下から出るシート(全幅、高さを変えられる)にする。
  - 中身(会話の選択、送信欄、プロンプト・Run・画像のカード)は今のパネルの中身をそのまま使う。

### 3. 会話の保存

- 新しいテーブルを2つ足す。会話は証跡ではないので、名前の変更と論理削除ができる。

  | テーブル | 列 |
  |---|---|
  | `assistant_conversation` | id、title、created_by_user_id、created_at、updated_at、deleted_at |
  | `assistant_message` | id、conversation_id、position、role(`user` / `assistant` / `tool`)、content(JSON)、created_at |

- `content` には、本文、添付の Asset ID、tool の呼び出しと結果を入れる。画像の中身(base64)は保存しない(ADR-0004)。
- 見えるのは本人の会話だけ(ADR-0025)。個人モードでは全部見える。
- 会話のタイトルは、最初の発言から作る。LLM は使わず、先頭を切り出す。
- LLM に送る履歴は、直近から数えて上限の文字数までにする。上限は実装で決め、定数にする。

### 4. プロンプトセットの書き込み

- アシスタントは、確認を挟まずにプロンプトセットを書き込む(ユーザーの決定)。
- 書き込みの道具は次のとおり。削除の道具は作らない。

  | 道具 | 内容 |
  |---|---|
  | `create_prompt_set` | 名前と項目でセットを作る |
  | `rename_prompt_set` | セットの名前を変える |
  | `add_prompt_set_items` | 項目を足す |
  | `update_prompt_set_item` | 項目のラベル・本文・並び順を変える |

- プロンプトセットには版の履歴が無い(ADR-0009)。そのため、書き込むたびに、変更前の値を tool の結果としてメッセージに残す。
- 結果のカードの「元に戻す」は、残した変更前の値に戻す。戻せるのは、その後に誰も対象を変えていないときだけにする(`updated_at` で比べる)。変わっていれば、戻さずにその旨を出す。
- 作ったセットを「元に戻す」と、そのセットは論理削除になる。これは利用者の操作であり、アシスタントの道具ではない。
- 書き込める範囲は、利用者が画面で書き込めるものと同じ(ADR-0025 の可視性)。プロンプトセットの API と同じドメイン関数を使う。今の `api/prompt_sets.py` にあるロジックは、`domain/prompt_sets.py` に移す。
- ADR-0023 の「プロンプトセットの編集は提供しない」は、外部のエージェントについての決まりである。そのまま残す。アシスタントは利用者が見ている画面の中で動き、「元に戻す」を持つ。この点で外部のエージェントと異なる。

### 5. 読み取りの道具

| 道具 | 内容 |
|---|---|
| `list_prompt_sets` | 本人に見えるプロンプトセットの名前と項目 |
| `get_form_context` | 今の生成フォームの、プロバイダー・モデル・操作(Generate / Edit)、プロンプト、パラメーター、入力画像、グループ |
| `propose_prompt` | プロンプトのカードを出す(2章)。フォームは変えない(フォームを変えるのは 11章の `update_form`) |
| `get_capabilities` | プロバイダーとモデルごとのパラメーターの定義(フォームと同じ `capabilities()`) |
| `get_run` | Run の状態と出力。待つ秒数を指定できる(9章) |
| `view_assets` | Asset の画像を見る(6章と同じ縮めたプレビュー)。生成の結果を確かめるため |

- `get_form_context` の値は、送信のたびにブラウザが送る。サーバーはフォームの状態を持たない。同じ発言の中で `update_form`(11章)を呼んだ後は、変更を重ねた値を返す。
- モデルごとのプロンプトの書き方(自然文かタグか)は、`get_form_context` のプロバイダーとモデルを見てアシスタントが判断する。モデルごとの規則を GAKEI には持たない。

### 6. 画像の添付

- 添付できるのは、本人に見えるストックの Asset だけ。1回の発言につき上限の枚数を設け、定数にする(当初は 4)。
- LLM には、派生画像のプレビューを縮めたものを送る。`ensure_derived` を通す(ADR-0036)。原本は送らない。
- 接続先のモデルが画像を読めないときは、LLM のエラーをそのまま出す。画像を読めるかどうかを GAKEI では判定しない(ADR-0024 の VLM と同じ扱い)。

### 7. LLM の呼び出し

- 管理者設定に「アシスタント」のページを足す。ページの種類は ADR-0031 の「機能」にする。
  - 有効・無効(既定は無効)、接続先(ADR-0032 の一覧から選ぶ)、モデル名、LLM のリクエストの1時間の上限、生成の上限(9章)。
  - `register_usage("assistant", ...)` で、接続先のカードに「アシスタント」と出す。
- Responses と Chat Completions の両方で、tool calling とストリーミングを使う。接続先の API 形式で切り替える。
- 1回の発言で、道具を呼ぶ回数に上限を設ける(当初は 40。9章)。上限に達したら、そこで止めて利用者に伝える。
- 1時間の上限は、利用者ごとに LLM のリクエストを数える。プロセス内で数え、再起動で 0 に戻る(ADR-0024 8章と同じ)。上限に達したら、待たせずに断る。
- システムプロンプトはコードに置く。利用者向けの文言ではないので、ロケールの JSON には置かない。応答の言語は、利用者の画面の言語に合わせるよう指示する。
- `FAKE_PROVIDER=1` では、決まった応答と道具の呼び出しを返すダミーのエンジンにする。自動テストは実 API を呼ばない。

### 8. API

| メソッドとパス | 内容 |
|---|---|
| `GET /api/assistant/conversations` | 本人の会話の一覧 |
| `POST /api/assistant/conversations` | 会話を作る |
| `GET /api/assistant/conversations/{id}` | 会話とメッセージ |
| `PATCH /api/assistant/conversations/{id}` | 名前を変える |
| `DELETE /api/assistant/conversations/{id}` | 論理削除 |
| `POST /api/assistant/conversations/{id}/messages` | 発言を送る。応答は `text/event-stream` で返す |
| `POST /api/assistant/undo/{message_id}` | 書き込みを元に戻す(4章) |
| `GET` / `PATCH /api/settings/assistant` | 管理者設定(更新は `require_admin`) |

- 発言の送信は POST なので、ブラウザは `EventSource` ではなく `fetch` で応答を読む。
- 利用者が途中で切ったら、LLM の呼び出しも止める。そこまでの応答は保存する。

### 9. 生成

- 生成の道具は次のとおり。中身は MCP と同じく `domain/run_create.py` の `create_runs` を呼ぶ(ADR-0023)。検証、料金の見積もり、キューへの登録は画面からの Run と同じ。

  | 道具 | 内容 |
  |---|---|
  | `generate_image` | Generate / Edit の Run を作る。プロバイダー、モデル、パラメーター、プロンプト、入力の Asset ID(主たる親と参照)、マスクの Asset ID、枚数、グループ ID を受ける。登録したら、すぐに `run_id` を返す |
  | `cancel_run` | 自分が作った、まだ終わっていない Run を取り消す |

- 指定の無い項目は、`get_form_context` で受け取った今のフォームの値を使う。利用者が「今の設定で」と言えば、そのまま生成できる。
- 結果を見て次を作る作業(三面図を1枚ずつ、など)は、`generate_image` → `get_run`(完了まで待つ)→ `view_assets`(出来を確かめる)→ 次の `generate_image` の順に、アシスタントが道具を呼んで進める。前の出力を次の入力にすれば、系列(ADR-0003)にもそのまま残る。
- 生成の前に利用者の確認は挟まない(プロンプトセットの書き込みと同じ)。
- **記録:** アシスタントが作った Run は `run.origin = 'assistant'`、`created_by_user_id` は会話の利用者にする。Run 詳細に「実行元: アシスタント」を出す。どの会話から作ったかは、会話の tool の結果に残す(Run の列には足さない)。
- **歯止め:** 生成の範囲は狭めない。ただし、暴走を止めるために次の2つを置く。どちらも管理者設定で変えられる。
  - 1回の発言で作れる Run の数(既定 20)。
  - 1時間あたりにアシスタントが作れる Run の数(利用者ごと。既定 60)。数え方は MCP の上限(ADR-0023 5章)と同じく、作った Run の件数を DB で数える。
  - 超えたときは Run を作らずに、道具のエラーとしてアシスタントに返す。アシスタントはそれを利用者に伝える。
- 1回の発言で道具を呼ぶ回数の上限(7章)は、生成の作業が収まるように 40 に上げる。`get_run` の待ちは1回 25 秒までにし、何度も呼んで待つ。
- 止めるボタン(2章)を押すと、LLM の呼び出しを止める。その発言で作った Run のうち、まだ `queued` のものは取り消す。`running` のものはそのまま終わらせる。
- 料金: `generate_image` の結果に、料金の目安(既存の pricing)を入れる。アシスタントは作った枚数と目安を利用者に伝える。

### 10. ストックの捜索

- 「夕方の海の画像を探して」「この画像に似たものを集めて」「このグループで、猫が写っているもの」のような頼みに答える。読み取りだけで、書き込みと課金は増えない。
- 道具は次のとおり。中身は MCP の同名のツール(ADR-0023 7章、ADR-0033)と同じドメインの関数を呼ぶ。MCP の `server.py` の中にある検索の組み立ては、両方から使えるようにドメインに移す。

  | 道具 | 内容 |
  |---|---|
  | `search_assets` | ストックを探す。`keyword`(プロンプト、タイトル、タグの文字列)と `semantic`(画像の埋め込みで意味の近い順)。種類、グループ、タグで絞れる。件数は最大 50 |
  | `find_similar_assets` | 指定した画像に似た画像を、近い順に返す |
  | `get_asset` | 1枚の画像の情報。タイトル、タグ、生成したときのプロンプトとモデル、主たる親 |
  | `list_groups` | 本人に見えるグループの一覧 |
  | `list_tags` | 本人の画像に付いたタグと件数。前方一致で絞れる |
  | `show_assets` | 見つけた画像をカードで示す。書き込みはしない |

- 見える範囲は REST と同じ(ADR-0025)。
- 埋め込みが無効のとき、`semantic` と `find_similar_assets` は道具のエラーを返す。アシスタントは `keyword` に切り替えるか、その旨を伝える。
- 検索の結果に画像の中身は入れない。結果は ID、タイトル、タグ、スコアなどの文字だけにする。中身を確かめたいときは、アシスタントが `view_assets`(6章)で見る。候補を見て絞り込み、最後に `show_assets` で示す、という流れにする。
- **画面:** `show_assets` は、サムネイルの格子のカードにする。Run のカードと同じく、サムネイルを選ぶとスタジオの結果エリアに出し(`?asset=`)、ドラッグすると生成フォームの入力に使える。カードに「すべて添付」を置き、次の発言の添付(6章、最大4枚)に入れられる。添付は上限まで入れ、入りきらない分はその旨を出す。
- `search_assets` と `find_similar_assets` の結果は、他の道具と同じく折りたたみの行で見せる。カードにするのは `show_assets` だけにして、候補の羅列でパネルを埋めない。
- アシスタントが見つけた画像を生成の入力にするときは、今までどおり `generate_image` に Asset ID を渡す(9章)。

### 11. 生成フォームの書き込み

- アシスタントは、ブラウザの生成フォームの値を書き換えられる(ユーザーの決定)。確認は挟まない。
- 道具は `update_form` の1つ。指定した項目だけを変える。

  | 項目 | 内容 |
  |---|---|
  | `provider`、`model` | プロバイダーとモデル |
  | `operation` | Generate / Edit |
  | `prompt` | プロンプト(置き換え) |
  | `params` | パラメーター。指定したキーだけを変え、`null` のキーは既定に戻す |
  | `inputs` | 入力画像(Asset ID と役割)。指定したら置き換える。`[]` で空にする |
  | `asset_group_id` | 出力を入れるグループ。`null` でなしにする |

- **書き込むのはブラウザのフォームだけ。** サーバーは値を検証して道具の結果に入れるだけで、フォームの値を保存しない。ブラウザは、その発言の応答を受けている間に届いた結果だけをフォームに反映する(`requestFormLoad`)。会話を開き直したときに、昔の書き込みを反映し直すことはしない。
- **検証:** プロバイダーとモデルが今使えること、パラメーターのキーがそのモデルの `capabilities()` にあること、入力画像が本人に見えることを確かめる。値の範囲の細かい検証はフォーム(と生成のとき)に任せる。通らない項目があれば、道具のエラーにして何も変えない。
- **画面:** 書き込みのたびに「フォームを変更」のカードを出し、変えた項目の変更前と変更後を示す。カードの「元に戻す」は、書き込む直前のフォームの値に戻す。変更前の値はブラウザが反映の直前に取り、そのページを開いている間だけ持つ(会話には保存しない。フォームの値は証跡でもサーバーの状態でもないため)。
- スタジオの外にいるときに書き込まれた場合は、次にスタジオを開いたときにフォームに入る(今の `requestFormLoad` と同じ)。
- `generate_image`(9章)の「指定の無い項目はフォームの値」は、`update_form` で変えた後の値を指す。

### 12. 生成結果の読み取り

- ブラウザは送信のたびに、フォームの状態(5章)と一緒に、スタジオの結果エリアに出ている画像の Asset ID(`result_asset_id`)を送る。結果エリアに画像が無いとき、またはスタジオを開いていないときは送らない。サーバーはこの値も保存しない。
- 道具 `view_result` を足す。1回の呼び出しで、次の2つを返す。
  - 文字の情報: `get_asset`(10章)と同じ内容。タイトル、タグ(自動タグを含む)、生成したときのプロンプト・モデル・パラメーター、主たる親。
  - 画像: `view_assets`(6章)と同じ縮めたプレビュー。`include_image = false` のときは送らず、文字の情報だけを返す。
- `asset_id` を省くと `result_asset_id` の画像を見る。渡せば、本人に見えるほかの画像も同じように見られる(見える範囲は ADR-0025)。結果エリアに画像が無く、`asset_id` も無いときは、道具のエラーを返す。
- 利用者が結果を直したいと頼んだとき(「顔が崩れている」「もっと明るく」など)は、アシスタントはまず `view_result` で結果の画像と元のプロンプトを見比べる。その上で、直す点だけを書いた Edit のプロンプトを作る。利用者が望めば、`update_form`(11章)でその結果を入力画像に入れる。システムプロンプトにこの手順を書く。
- 接続先のモデルが画像を読めないときは、6章と同じく LLM のエラーをそのまま出す。その後は `include_image = false` で、タグとプロンプトから考えられる。
- **履歴の参照(同日のユーザーの指示):** 「二つ前の結果」「さっきの2枚を比べて」のような頼みに答えられるよう、履歴から複数の画像を参照できるようにする。
  - 道具 `list_recent_results` を足す。本人に見える Run を新しい順に返す(実行元を問わない。画面・アシスタント・MCP)。1件ごとに、Run の ID、作った日時、状態、操作、モデル、プロンプト(長いものは切る)、出力の Asset ID(並び順)、入力の Asset ID を返す。件数は既定 10、最大 50。終わっていない Run と失敗した Run も含め、状態で見分けられるようにする。グループで絞れる(出力を入れる先にそのグループを選んだ Run と、出力が今そのグループにいる Run)。一覧の土台は REST・MCP の Run の一覧と同じドメインの関数を使い、見える範囲も同じ(ADR-0025)。
  - 「何個前」の数え方は Run の単位にする(1回の生成で複数枚を出した Run は1つと数える)。結果エリアの画像がどの Run の出力かは `view_result` の結果で分かるので、アシスタントはそれを起点に数えてもよい。どちらか曖昧なときは、候補を示して利用者に確かめる。
  - `view_result` は `asset_ids` で複数の画像(最大 4。添付と同じ)を一度に見られるようにする。比べるときは並べて見る。
  - 一覧の結果に画像の中身は入れない(10章と同じ)。見るのは `view_result` か `view_assets` で行う。

### 13. ストックの整理

- 「未整理の画像にタグを付けてグループに入れる」「選んだ画像に『背景』のタグを付ける」「この似た画像をまとめて新しいグループにする」のような頼みに答える。
- 書き込みは、プロンプトセット(4章)と同じく確認を挟まずに直接行い、「元に戻す」を付ける(ユーザーの決定)。削除の道具は作らない。グループからの取り外しとタグの削除は、画像やグループを消さないので含める。
- **書き込みの道具:** 中身は、REST と同じドメインの関数(`domain/annotations.py`、`domain/asset_groups.py`)を呼ぶ。見える範囲と書き込める範囲も画面と同じ(ADR-0025)。

  | 道具 | 内容 |
  |---|---|
  | `add_tags` | 複数の画像に、複数のタグを付ける |
  | `remove_tags` | 複数の画像から、複数のタグを外す |
  | `set_title` | 1枚の画像のタイトルを変える。空にもできる |
  | `create_group` | グループを作る。画像を渡せば、そのまま入れる |
  | `rename_group` | グループの名前を変える |
  | `move_to_group` | 複数の画像をグループに入れる。画像の所属は1つなので、別のグループからは移る(ADR-0022 3章) |
  | `remove_from_group` | 複数の画像をグループから外す |

- **人の編集と同じ扱い(ユーザーの決定):** タグとタイトルは、画面で人が編集したときと同じ関数で書く。付けたタグは `source = user`、外したタグは `removed = True`、タイトルは `title_source = user` になり、自動の再推定(ADR-0024 2章)で上書きしない。アシスタントが書いた印は付けない(4章のプロンプトセットと同じ。経緯は会話に残る)。
- **1回の量:** 1回の道具の呼び出しで扱う画像は最大 200 枚にし、定数にする。課金は無いので、発言ごと・時間ごとの上限は置かない。道具を呼ぶ回数の上限(7章)はそのまま効く。
- **元に戻す:** 書き込むたびに、対象の画像ごとの変更前の状態を tool の結果に残す。
  - タグは、変えた (画像, タグ) の行の変更前(行が無い、`auto` とスコア、`user`、`removed`)を残し、そのとおりに戻す。自動で付いていたタグを外して戻すと、自動のタグに戻る。
  - タイトルは、変更前のタイトルと `title_source` を残す。
  - グループは、画像ごとの変更前の所属(無し、または元のグループ)を残す。作ったグループを戻すと、メンバーを元に戻してからグループを論理削除する。名前の変更は変更前の名前に戻す。
  - 戻すのは、その後に誰も変えていない画像だけにする。画像ごとに、書き込んだ直後の状態と今の状態を比べる。変わっていた画像は戻さず、戻した枚数と戻さなかった枚数を出す(4章のセットは全体で比べるが、まとめて書く整理では一部だけでも戻せるほうが役に立つ)。
- **ストックの選択(ユーザーの決定):** ブラウザは送信のたびに、ストックの選択モードで選んでいる画像の ID(`selected_asset_ids`、最大 200)を、フォームの状態(5章)と一緒に送る。選んでいなければ送らない。サーバーは保存しない。`get_form_context` の結果に入れ、アシスタントは「選んだ画像」をこれで知る。
- **グループの提案(ユーザーの決定):** 読み取りの道具 `suggest_groups` を足す。ADR-0056 の `GET /api/asset-groups/suggestions` と同じドメインの関数を呼び、案ごとに画像の ID、件数、特徴的なタグ、既存のグループとの重なりを返す。保存はしない。アシスタントは案を見て、`create_group` や `move_to_group` で振り分ける。埋め込みが無効のときは、道具のエラーを返す。
- **画面:** 書き込みのたびに、整理の結果のカードを出す。カードには、操作(タグを付けた、グループに入れた、など)、対象の枚数とサムネイルの一部、「元に戻す」を置く。サムネイルは `show_assets`(10章)のカードと同じく、選ぶとスタジオの結果エリアに出す。書き込みの後は、ストックとグループの一覧を読み直す。
- **システムプロンプト:** 対象が曖昧なとき(「未整理の画像」が何を指すか、など)は、書き込む前に対象と件数を示して確かめるよう書く。タグの名前は、既にあるタグ(`list_tags`)に合わせるよう書く。

### 14. LLM に送る情報

#### 14.1 画像を送る前の許可(ユーザーの決定)

- 対象は、アシスタントが道具で画像を見るとき(`view_assets` と、`include_image` が真の `view_result`)。利用者が自分で添付した画像(6章)は、添付の操作を許可とみなし、聞かない。
- 道具が画像を読もうとしたら、その発言の処理を止め、許可のカードを出す。カードには、送る画像のサムネイル、送り先の接続先の名前、「1度だけ許可」「常に許可」「許可しない」を置く。
  - **1度だけ許可:** その呼び出しの画像だけを送る。
  - **常に許可:** ユーザーごとの設定(ADR-0049 6章の `user_preference`、キー `assistant.image_send`、値 `always`)に保存し、以後は聞かずに送る。ユーザー設定の画面で「毎回確かめる」に戻せる。
  - **許可しない:** 画像を送らず、道具の結果を「利用者が画像の送信を断った」にする。アシスタントは文字の情報だけで続ける。
- 待ち方: SSE の応答を開いたまま待つ。サーバーは許可を求めるイベント(要求の ID、Asset ID、接続先の名前)を送り、ブラウザは `POST /api/assistant/permissions/{request_id}` で答える(`once` / `always` / `deny`)。10 分答えが無いとき、止めるボタンを押したとき、接続が切れたときは「許可しない」と同じにする。待っている要求はプロセス内に持ち、再起動で消える。
- 答えは tool のメッセージに残す。会話を開き直したときは、カードに答えを出す(ボタンは出さない)。

#### 14.2 画像の捜索は検索の道具から(ユーザーの決定)

- 画像を探すときは、まず `search_assets`、`find_similar_assets`、`list_group_assets`(14.4)の文字の情報で絞る。`view_assets` は、文字では決められないときに、絞った少数にだけ使う。システムプロンプトと道具の説明に書く。

#### 14.3 X 以上の画像(ユーザーの決定)

- アシスタントの接続先の `locality`(ADR-0051 3章)が `external` のとき、段階が `x`、`xx`、`xxx` の画像(ADR-0049。人が選んだ段階を優先する)は、ID、種類、段階、グループだけを LLM に送る。タイトル、タグ、プロンプト、パラメーター、画像は送らず、`withheld: true` を付ける。
- すべての道具の結果に効かせる: 検索、似た画像、`get_asset`、`view_result`、`list_recent_results` のプロンプト、`list_group_assets`、`show_assets`、整理の結果、`suggest_groups` の特徴的なタグ。`view_assets` と `view_result` は、その画像を送らない(許可も聞かない)。結果には「外部の接続先には送らない」とだけ返す。利用者の添付にも効かせ、送らなかったことを画面に出す。
- `list_tags` の件数と `suggest_groups` の特徴的なタグは、X 以上の画像を数えずに作る。
- 未判定の画像は対象にしない(段階が分からないため)。レーティングの判定を使っていなければ、この絞り込みは効かない。そのことを `docs/assistant.md` に書く。
- 書き込みの道具は ID で働くので、X 以上の画像も、中身を見ずに整理できる。
- 接続先が `local` のときは、この絞り込みをしない。ほかの決まり(14.1 の許可、Mod の `ai.before_send`)はそのまま効く。
- `locality` で GAKEI の動作を変えるのは、これが初めてになる。ADR-0051 3章の「GAKEI はこの値で動作を変えない」に、この例外を書き足す。

#### 14.4 道具の結果の大きさ

- **件数で打ち切る:** 一覧を返す道具(`search_assets`、`find_similar_assets`、`list_recent_results`、`list_tags`、`list_group_assets`)は、結果の文字数の上限(`TOOL_RESULT_MAX_CHARS`)に収まる件数で打ち切る。JSON の途中では切らない。結果に `returned`、分かれば `total`、続きがあれば `next_offset` を入れ、`offset` で続きを読めるようにする。文字数での最後の切り捨ては残すが、そのときは `truncated: true` を必ず付ける。
- **1件を短くする:** 一覧の1件は、ID、種類、タイトル、タグの名前(人が付けたものを先に、最大 12 個)、段階、グループの名前にする。幅・高さ・作成日時・タグの出どころは `get_asset` だけで返す。
- **`list_group_assets` を足す:** グループの画像を、上の短い形で全部返す(`offset` で続きを読む)。グループの中身をまとめて整理するときに使う。
- **画面用の値を送らない:** 整理の結果の `preview`(焦点、段階)、`list_groups` の `cover_asset_id`・`position`・日時は、カードのために保存はするが、LLM には送らない。

#### 14.5 履歴の古い道具の結果

- 今の発言の中でも、直近の 3 件より前の道具の結果で 2,000 字を超えるものは、短くして送る。画像の ID の一覧と件数は残し(後の書き込みで使うため)、タイトルやタグなどを落とす。保存してある結果は変えない。

#### 14.6 件数の照合

- システムプロンプトに書く: `next_offset` があれば、書き込む前に続きを全部読む。対象の件数と書き込んだ件数が違えば、理由とともに伝える。

## Options Considered

### 書き込みのしかた

| 案 | 評価 |
|---|---|
| A. 直接書き込み、変更前を残して「元に戻す」を付ける(採用) | ユーザーの決定。手間が少ない。版の履歴が無いことは、変更前を残して補う |
| B. 提案を出し、利用者が適用する | 誤りを防げる。ただし手順が増え、対話の流れが止まる |
| C. プロンプトセットに版の履歴を足す | 戻しやすい。ただし ADR-0009 が作らないとした「バージョン管理」に当たる |

### 会話の保存先

| 案 | 評価 |
|---|---|
| A. サーバーの DB(採用) | 端末をまたいで続けられる。「元に戻す」に必要な変更前の値も、ここに残せる |
| B. ブラウザの localStorage | 作りは小さい。ただし端末をまたげず、「元に戻す」の材料がブラウザにしか残らない |

### 道具の実装

| 案 | 評価 |
|---|---|
| A. ドメイン関数を直接呼ぶ(採用) | MCP(ADR-0023)と同じ方針。REST を経由しない |
| B. MCP のツールを共用する | 定義は1つで済む。ただし MCP はプロンプトセットの編集を持たず、持たせる予定も無い |

### 生成の扱い

| 案 | 評価 |
|---|---|
| A. 生成させ、発言ごと・時間ごとの上限を歯止めにする(採用) | ユーザーの決定。繰り返しの作業を任せられる。暴走は上限と止めるボタンで抑える |
| B. 生成させず、プロンプトのカードからフォームに入れるだけ | 課金の心配は無い。ただし「5枚作る」「1枚ずつ作る」を任せられない |
| C. 生成の前に、毎回利用者の確認を挟む | 安全。ただし1枚ずつ作る作業では確認が続き、任せる意味が薄れる |

## Consequences

- ADR-0001 のゴールに「生成のアシスタント」を足す。
- LLM の接続先(ADR-0032)を使う機能が3つになる(自動タイトル・タグ、埋め込み、アシスタント)。
- tool calling とストリーミングの呼び出しを新しく作る。自動タイトル・タグのエンジンとは分ける。ただし、接続先の解決とクライアントのキャッシュは共用する。
- プロンプトセットのロジックが `domain/prompt_sets.py` に移る。REST の振る舞いは変えない。
- `run.origin` の値に `assistant` が加わる(ADR-0023 5章)。履歴と Run 詳細で、実行元を出し分ける。
- アシスタントが書き込んだプロンプトセットに、書き込んだのがアシスタントだという印は付けない。経緯は会話に残る。
- 後の段階で道具を足すときは、この ADR に章を足す。
- アシスタントが付けたタグとタイトルは人の編集と見分けられない。自動の再推定で戻らないので、誤りは「元に戻す」か人の編集で直す。
