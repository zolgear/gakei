# ADR-0062: SVG の出力(GPT Image 2.6)

**Status:** Proposed
**Date:** 2026-11-05

2026-11-05 に、ユーザーが GPT Image 2.6 の SVG の出力に対応すると決めた(#233 段4)。アイコンやロゴのような、小さく単純な図柄に向く。API はスクリプトを含まない文書を返すので、スクリプトは除いてよいとした。

## Context

- GPT Image 2.6(Sunburst / Flare)は、Generate で `output_format: "svg"` を受ける。API はまず参照用の画像を描き、別のテキストのモデル(書き手)がそれを見て SVG を書く。2.5 は 400 を返す。Edit は SVG を出力も入力もできない。
- 2026-11-05 に実機(`quality=low`)で次のことを確かめた。
  - 書き手のモデルを `svg.model` で必ず指定する(無いと 400 `SVG generation requires 'svg.model'`)。`gpt-5.6-luna` / `-terra` / `-sol` のほか、gpt-5 系のテキストのモデルを受ける。存在しないモデルは 404。
  - `svg.reasoning.effort` は none〜max。受ける値は書き手のモデルによって違う(gpt-5-mini は minimal〜high、gpt-5.5 は none〜xhigh)。
  - `n` は 1 だけ(2 は 400)。ストリーミング、途中経過画像、`output_compression`、`prompt_rewriter` は使えない。
  - 応答の `data[0].b64_json` は UTF-8 の XML。1024x1024 のコーヒーカップのアイコンで 1.5KB、`path`・`g`・`ellipse`・`title`・`desc` だけで、スクリプトや外部の参照は無かった。`width` / `height` は `size` と同じ。背景は透過。
  - 料金は、参照の画像の分(`usage`。2.6 の low で 824 トークン)に、書き手のトークンの分(`svg_usage`。luna で入力 1,556、出力 931、うち思考 170)が加わる。
- 今の GAKEI は、原本を Pillow で開ける画像に限っている(取り込み、派生、焦点、埋め込み、自動タグ)。派生は WebP。配信は同じオリジンから行う(ADR-0004)。SVG はスクリプトや外部の参照を持てる形式なので、そのまま同じオリジンから配信すると、開いた人のブラウザで動く物の入口になりうる。

## Decision

1. **項目。** 2.6 の Generate の「ファイル形式」に SVG を足す。SVG のときだけ次の2つを出し、枚数・途中経過・圧縮率は出さない(`conditional_params`)。
   - 「SVG を書くモデル」(`svg_model`): GPT-5.6 Luna / Terra / Sol。既定は Luna(最も安い)。選択肢は単価を持つものに絞る(料金を出すため)。
   - 「SVG の思考」(`svg_effort`): なし〜max。未指定なら書き手のモデルの既定。
2. **送り方。** プロバイダーが `svg_model` / `svg_effort` を API の `svg: {model, reasoning: {effort}}` に組み立てる。`run.params` にはフォームの項目のまま保存する(ADR-0003 の「送った値をそのまま」の例外。中身は同じ)。
3. **原本。** 生成の結果に限って SVG を原本にする。アップロードでは受けない。
   - 取り込みで無害化する。許す要素(図形、文字、グラデーション、パターン、クリップ、マスク、フィルター、`style`)と属性だけを残し、`script`・`foreignObject`・`image`・`a`・アニメーションなど、それ以外の要素は子ごと除く。`on*` の属性、文書の外を指す `href`、外部を参照する CSS(`url(` の先が `#` でないもの、`@import`)も除く。DTD(実体の定義)を持つ文書と、SVG の名前空間でない文書は断る。保存する原本は無害化した後の文書で、sha256 もそれで取る。
   - 大きさは文書の `width` / `height`(px)か `viewBox` から決める。読めなければ 1024×1024。
4. **派生と画素を読む処理。** SVG を resvg(MIT)で透過の画像に描き、そこから WebP の派生を作る(長辺 2048 まで。小さい SVG は拡大しない)。焦点、埋め込み、自動タグなど、画素を読む処理は、これまでどおり派生か、同じ描き方の画像を使う。依存に `resvg-py` を足す(ADR-0021 の表記に載る)。
5. **料金。** 参考価格は出さず、理由を出す(書き手のトークンは書いてみるまで分からない)。実行後の料金は、`usage` の画像の分に、`usage.svg_usage` の書き手の分(書き手のモデルの単価)を足す。単価の分からない書き手なら合計を出さない。
6. **表示と配信。**
   - ビューアは SVG のときだけ、最初から原本を出す(拡大しても粗くならない)。一覧は派生。
   - 原本の応答に `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; img-src data:; sandbox` と `X-Content-Type-Options: nosniff` を付ける。無害化したうえで、直接開かれても何も動かないようにする。
   - ダウンロードの名前の拡張子は `.svg`。
7. **入力にしない。** SVG は Run の入力(参照画像を含む)にできない(API の Edit が受けない)。サーバーは 422 で断り、フォームは送る前に止め、「入力に使う」も無効にする(GIF と同じ。ADR-0061 6章)。
8. **系列の ZIP。** 書き出しと取り込みで SVG を扱う。取り込みでも同じ無害化を通す(無害化した文書をもう一度無害化しても変わらないので、sha256 は変わらない)。

## Options Considered

### 書き手のモデルの選び方

| 案 | 評価 |
|---|---|
| A: GPT-5.6 の3つから選ぶ(採用) | 料金を出せる。既定は最も安い Luna |
| B: 文字で自由に入れる | どのモデルも受けるが、単価が分からず料金を出せない。入れ違いは 404 になる |
| C: 選ばせず Luna に固定する | 単純だが、凝った図柄で上のモデルを試せない |

### 無害化

| 案 | 評価 |
|---|---|
| A: 許す要素と属性だけを残す(採用) | API の出力は静的な図形だけなので、困らない。知らない要素は残さない |
| B: 危ないものだけを除く(拒否リスト) | 書き漏れがそのまま穴になる |
| C: 無害化せず、配信のヘッダーだけで守る | ダウンロードした先や、別のツールで開いたときに守れない |

### 派生の作り方

| 案 | 評価 |
|---|---|
| A: resvg で描く(採用) | Rust 製で、Windows・Linux(arm64 / x86_64)・macOS のビルド済みの wheel がある。スクリプトを動かさない |
| B: CairoSVG | Cairo のライブラリが要り、Windows で入れにくい |
| C: 派生を作らず、どこでも原本の SVG を出す | 焦点・埋め込み・自動タグが画素を読めない。一覧で大きな SVG を何枚も描くことになる |

## Trade-off Analysis

無害化した文書を原本にするので、API が返したバイト列そのものは残らない。API の出力は許す要素だけで書かれていたので、実際には同じ中身になる見込みが高く、残すことより安全を取った。書き手のトークンの料金は前もって出せないが、実行後の記録で確かめられる。

## Consequences

- 原本の形式に SVG が増える。Pillow で開く処理は、`derivatives.open_raster` を通す。
- 依存に `resvg-py`(MIT)が増える。メタデータにライセンスの記載が無いので、第三者ライセンス表記では同梱の LICENSE で確かめた種類を出す。
- ADR-0001 の非ゴール「高機能な画像編集」に、SVG のパスや色の編集はしないと注記する。ADR-0004 に SVG の原本を注記する。
