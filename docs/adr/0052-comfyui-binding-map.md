# ADR-0052: ComfyUI ワークフローの読み取りと差し込み先の図

**Status:** Accepted
**Date:** 2026-10-17

2026-10-17 に、ユーザーが次のように指示した。

- ComfyUI のワークフローの取り込みと差し込み先の設定は、必要最低限の機能はあるが、初見で動く設定を作るのが難しい。解析と差し込み先の自動設定も不安定なので、作り直す。
- ノード UI が欲しい。ワークフローから拾った変更できる値がどれか、どれを固定してどれを利用者に変えさせるかを、図で答え合わせしながら管理できるのが利点である。
- ゴールはノード UI を入れる形とし、足元から順に固める。

同日、ユーザーがこの ADR を承認し、第1段〜第3段と 7章を dev にマージした(#151〜#155)。

同日、規則による推定の試作、LLM による推定の比較、フォームと図の画面の試作で検証した(私物のワークフローを含むので、検証の資料はリポジトリに入れない)。

## Context

ADR-0013 の登録画面は、差し込み先(プロンプト、ネガティブ、seed、幅、高さ、枚数、画像の枠、マスク、出力、最終プロンプト)と公開パラメーターを、ノードと入力名のドロップダウンで1つずつ選ぶ。登録時の推定(ADR-0013 8章の analyze)は、代表的なノードの名前と、文字列を素通しするノードの判定に頼っている。

実在のワークフロー5本(Qwen Image 2.1 の t2i・Edit と、プロンプトの強化・透過を含む構成)で、次の外れ方を確かめた。

- **プロンプトが決まらない(5本中4本):** 文字列の入出力を持つ加工・分岐のノード(`StringFormat`、`ComfySwitchNode`、`PreviewAny`、テキスト生成)で遡りが止まる。配線の無い文字列の値(根)は1つしかないのに、候補を警告に並べるだけになる。
- **マスクの誤判定(Edit の3本):** `LoadImage` の MASK 出力がどこかに配線されていれば `image_alpha` と判定する。透過を保つための `JoinImageWithAlpha.alpha` に入っているだけでも当たるので、GAKEI がマスクを合成すると、塗った範囲が透明な画像として扱われる。
- **使われない枝:** `ComfySwitchNode` の直値を見ないので、今の設定では使われない `EmptyLatentImage` の枚数を提案する。
- **見落とし:** 同じ配線を横から表示する `PreviewAny` を最終プロンプトとして拾えない。
- 合成のグラフで、ほかに次を確かめた。1つの Primitive を2つのサンプラーが共有すると seed の参照が重複して保存の検証で落ちる。`image1`・`image2` の形の画像入力では枠の順を外す。配線された入力を差し込み先にしても保存できる(実行時に配線を定数で上書きする)。
- 公開パラメーターの候補は1本あたり 18〜57 件を順位なしで並べる。

後半の3つの外れは、誤った提案をそのまま保存できる形の失敗で、画面に何も出ないので利用者は気付けない。

規則の試作(出力から遡り、生きている枝だけを見る)は5本 × 10 項目で全項目を当て、誤った提案は 0 件だった。合成のグラフでも今より悪くならなかった。LLM(`gpt-6-luna`、reasoning effort low、ノードの要約を送る)は、実物5本と合成 12 本の 90 回すべてで全項目を当てた。1回あたり約6秒、約 $0.0005 だった。ただし、LLM が申告する確信度は外れた項目でも高く、当てにならない。ワークフローの JSON をそのまま送ると、テンプレートに残った文に対して安全方針による拒否が出た。

画面の試作では、読み取り結果をカードで示し、決めきれない項目だけを問う形と、生きている経路を縮約した読むだけの図を並べる形を比べた。図は「どの値を固定し、どれを利用者に変えさせるか」を一目で答え合わせできる。

ADR-0001 は「ノードエディタ、ワークフロー構築」を非ゴールにしている。差し込み先を選ぶための図がこれに当たるかを、この ADR で線引きする。

## Decision

### 1. 範囲と境界

- 登録・編集画面で、ワークフローのグラフを **読むだけの図** として見せ、図の上で差し込み先と公開パラメーターを選べるようにする。
- **境界は、図の操作がテンプレートを変えるかで引く。** 図の操作で保存するのは、これまでのフォームと同じ差し込み先(`Bindings`)と公開パラメーター(`ExposedParam`)だけで、テンプレートの JSON は1バイトも変えない。次は作らない(ADR-0001 の非ゴールのまま)。
  - ノードの追加・削除・移動の保存、配線の変更
  - テンプレートに書かれた入力の値の書き換え(値を変えたいものは公開パラメーターにして、Run ごとに差し込む)
  - ワークフローの新規作成、UI 形式への書き出し
- 図の配置は毎回自動で計算し、保存しない。ComfyUI の画面での配置とは一致しなくてよい。
- 保存の形式(`comfy_workflow` の列、`Bindings`、`ExposedParam`)と、Run の記録(`run.params`)は変えない。

### 2. 読み取り(analyze)の規則

ADR-0013 3章・8章の推定を、次の規則に置き換える。名前の表(代表的なノード)は補助にとどめ、グラフの構造を主にする。

- **生きている部分:** 保存ノード(出力)を錨にし、出力に届くノードだけを対象にする。`ComfySwitchNode` などの切り替えは、直値(Primitive から配線された直値を含む)で解いて、選ばれた側だけを辿る。別のノードの出力で切り替わるものは、両方の枝を生きているとみなす。
- **ノードの状態:** 各ノードを「出力につながる」「表示だけ(出力には届かないが、表示のノードにつながる)」「使われない」の3つに分ける。図(4章)と保存時の検証(3章)は同じ判定を使う。
- **プロンプト:** サンプラーの条件付け(`positive`)から、エンコーダー、文字列へと遡る。文字列の **根** を「文字列の入力がすべて直値のノードの直値」とし、根が1つなら自動で選ぶ。複数あるときは、タイトルの語、`PrimitiveString*` かどうか、書式の位置(`StringFormat` の先頭か)で順位を付け、差が小さければ利用者に問う。
- **ネガティブ:** `negative` から同じように遡る。空文字の既定値も差し込み先として扱う。
- **マスク:** 部分編集に使われる MASK だけを対応付ける。受け側のノードの出力が LATENT か CONDITIONING のとき(`SetLatentNoiseMask`、`InpaintModelConditioning` など)、または入力名が `mask` のときに限る。`JoinImageWithAlpha.alpha` のように、透過を保つためだけに使う MASK は対応付けない。
- **幅・高さ・枚数:** 切り替えを解きながら latent を遡る。Primitive から配線されていれば、その Primitive の値を差し込み先にする。計算するノード(解像度の選択など)から配線されていれば差し込まず、そのノードの入力を公開パラメーターの推奨にする。
- **seed:** 生きているサンプラーの seed を集め、同じ参照は1つにまとめる。
- **画像の枠:** 出力に届く `LoadImage` だけを枠にする。順は、画像を素通しするノードを越えて、受け側の番号付きの入力(`images.image_N`、`imageN`)の番号で決める。番号が無ければノードの id の順にする。
- **出力:** 生きている保存ノード。表示だけのノード(`PreviewImage`、比較のノード)は出力にしない。
- **最終プロンプト:** エンコーダーに入る文字列を表示するノード。同じ配線を横から表示するノードも含める(ADR-0030)。
- **タイトルの規約:** `gakei:prompt` などの規約(ADR-0013 3章)は最優先のヒントとして残す。
- **`/object_info`:** 必須にしない。接続できれば、型、選択肢、範囲、出力ノードの判定を上書きする。
- **確信度:** 項目ごとに、次の5つのどれかを返す。
  - `marked`: タイトルの規約で指定
  - `unique`: 構造で一意
  - `ranked`: 順位の差がはっきりしている
  - `ask`: 決めきれない(候補と問いの文を返す)
  - `absent`: 該当なし(理由を返す)
- **根拠:** 項目ごとに、理由の一文と、出力までの道筋(ノードと入力名の並び)を返す。
- **公開パラメーターの推奨:** 候補を、推奨(名前付きの Primitive、真偽値の切り替え、steps・cfg・sampler、計算するノードの入力)、その他、公開しない(固定の長い文、ファイル名など)の3段に分けて返す。

### 3. 保存時の検証

作成・更新のときに、差し込み先と公開パラメーターの役割を検証する。推定、手の選択、アシスタントの提案(6章)のどれにも同じ検証を掛ける。

- **エラー(422。保存しない):**
  - 型が合わない(プロンプトに真偽値の入力、など)
  - 配線された入力を差し込み先・公開パラメーターにした
  - 差し込み先が重複している
  - 出力に選んだノードに、生成した画像が届かない
- **警告(保存できる。画面に残す):**
  - 使われない枝の入力を選んだ
  - `image_alpha` のマスクの MASK が部分編集に使われていない
  - 出力に、保存ノードではなく表示だけのノード(`PreviewImage` など)を選んだ
- 登録済みのワークフローを開いたとき、保存されている差し込み先が今の読み取りと違えば示す。古い推定で保存した誤りに気付く入口にする。自動で書き換えない。
- 秘密に見える値の警告(ADR-0013 8章)は今のまま、登録を止めない。

### 4. 画面

- **表示は「一覧」と「図」を切り替える(2026-10-17 改訂):** 2つを同時には出さない。ファイル、基本情報、読み取りの要約、検証の一覧、保存は両方に共通に出し、差し込み先・公開パラメーター・検証の状態も共有する。既定は一覧。
- **一覧:** 項目ごとに1行で、値、理由の一文、確信度を示す。ノードはタイトル・クラス名・短い id(サブグラフの部分は名前に置き換える)で見せ、文字列の入力には既定値の冒頭を添える。`ask` の項目だけ、候補を比べる問いのカードを出す。今のドロップダウンは「詳細設定」に畳んで残す。
- **図:** 左に読むだけの図、右にパネルを並べる。パネルは「差し込み先」(項目ごとの簡潔なカード)と「ノード」(選んだノードの入力の一覧)のタブを持つ。
  - 既定は縮約した図(役割を持つノードと錨を残し、それ以外を束ねる)。すべてのノードの表示に切り替えられる。
  - ノードの状態(2章)を線と色の濃さで描き分ける。パネルで項目を開くと、その項目の道筋を図で強調する。
  - 図でできること: ノードを選ぶ、選んだノードの入力に役割(差し込み先、公開、固定)を割り当てる・外す、拡大縮小とパン。割り当ては図のポートではなく、パネルの入力の一覧で行う。
  - 入力ごとに「差し込む(GAKEI が毎回埋める)」「公開(利用者がフォームで変えられる)」「固定(テンプレートの値のまま)」のどれかが分かるようにする。
  - 図は既存の `@xyflow/react`(系列グラフ。ADR-0009)を使い、配置は層別で自前に計算する。向きは図の枠の形で選ぶ(横長なら左 → 右、縦長なら上 → 下)。
- **スクロール:** ページのスクロールのほかに、縦にスクロールする入れ物を作らない。図は画面に留め(パンで動かす)、パネルはページのスクロールで流す。図の上のホイールはページのスクロールに渡す。
- 768px 未満では一覧が主で、図は読むだけにする(図の下にパネルを置き、割り当ては「差し込み先」のカードで行う)。
- 保存後は、普通の Run で試すよう生成画面へ誘導する。検証だけの実行は作らない(ComfyUI に検証だけの API が無いため)。

### 5. 導入の順序

1. バックエンド: 2章の読み取りと3章の検証、ADR-0013 8章の外れ(seed の重複、`imageN` の枠の順、配線された入力)の修正。解析の応答に、確信度・理由・道筋・問い・ノードの状態・パラメーターの段を足す。保存形式は変えず、マイグレーションは無い。
2. フロント: 一覧(カードと問い)、検証の表示、公開パラメーターの3段(4章の図を除く部分)。
3. フロント: 図の表示(読むだけの図とパネル)と、図からの割り当て。
4. 任意: アシスタントでの推定(6章)。

各段は単独で出せるようにする。1 だけで、誤った提案をそのまま保存できる失敗は無くなる。

### 6. アシスタントでの推定(第4段)

- 管理者設定の「アシスタント」(ADR-0048)が有効なときだけ、登録・編集画面に「アシスタントで推定」のボタンを出す。押したときだけ呼び、自動では呼ばない。1時間あたりの上限に数える。
- 送るのは、サーバーで作ったノードの要約(id、種類、タイトル、配線、直値。文字列は先頭だけにする)で、テンプレートの JSON そのものは送らない。
- 応答は Structured Outputs で受ける。提案には必ず3章の検証を掛け、通らない項目は捨てて警告にする。画面では、読み取りと違う項目だけを理由の文と並べ、採るかは人が決める。LLM が申告する確信度は出さない。
- 外部の AI を呼ぶので、`ai.before_send`(ADR-0051)を通す。ワークフローの構造を送ることを Mod の側で区別できるよう、`purpose` に `workflow_analysis` を足す(ADR-0051 2章の表を、この段の実装と同時に改める)。拒否されたら理由を出し、規則の読み取りのままにする。
- Structured Outputs に対応しない接続先では、ボタンを出さない。
- **実装の細部(2026-10-17):**
  - API は `POST /api/comfyui/workflows/suggest-bindings`(管理者だけ。保存しない)。入力は `template` か `workflow_id` のどちらか(analyze と同じ)と、今の操作(`operation`)とワークフローの名前。
  - **Structured Outputs に対応する接続先:** GAKEI は接続先に対応を問い合わせない。アシスタントの接続先の Base URL のホストが OpenAI の公式(`api.openai.com`。組み込みの接続先で Base URL を変えていないときを含む)のときだけ対応とみなす。それ以外の接続先では、ボタンを出さず、API は 409 で断る。接続先ごとに対応を選べる設定は作らない(要るなら ADR-0032 を改めてから)。
    - **2026-10-21 追記:** ADR-0032 を改め、接続先ごとに構造化出力への対応を指定できるようにした(自動 / 対応する / 対応しない)。OpenAI 互換のプロキシ経由で OpenAI のモデルにつなぐ構成のため。上の判定は「自動」(既定)のときの判定として残る。「対応する」ならホストによらず対応とみなし、「対応しない」なら公式でも対応とみなさない。判定は領域の検出(ADR-0053 7章)と共通。接続先が対応しないためにボタンが出ないときは、アシスタントの管理者設定にその旨と「LLM の接続先」へのリンクを出す。
  - モデルはアシスタントの設定のまま。reasoning effort は low。Responses API なら `text.format`、Chat Completions なら `response_format` の `json_schema`(strict)で受ける。1時間の上限は、アシスタントの会話と同じ記録で、押した人ごとに数える。
  - **送る要約:** 1行が1ノードの JSON(id、`class_type`、独自のタイトル、入力、出力の行き先)。配線は `@ノード[出力]`、文字列の直値は先頭 60 文字と全体の文字数だけ、秘密に見える値(ADR-0013 8章の判定)は `***` にする。入れ子の入力は `a.b` の名前で平らにする。
  - **提案させる項目:** 差し込み先の 10 項目と操作(`generate` / `edit`)。項目ごとに理由の文を書かせる。公開パラメーターは提案させない(規則の3段で足り、検証では繰り返すたびに候補が揺れたため)。確信度も求めない。
  - **検証:** 提案を3章の検証(`check_workflow`)に掛け、エラーになった項目を捨てる(seed と出力は1つずつ、画像の枠は順が変わらないよう丸ごと)。`image_alpha` のマスクは、2章の規則で部分編集に使われていなければ捨てる。ほかの警告は項目に添えて返す。
  - **応答:** 提案の差し込み先、項目ごとの理由と規則の読み取りと同じかどうか、捨てた項目と理由、使ったモデル、usage(トークン数)。画面では「今 / 提案 / 理由 / 提案を使う」で、今の値と違う項目だけを並べ、同じ項目は数で示す。採った項目は「手で選択」として扱い、同じ検証に掛かる。
  - `FAKE_PROVIDER=1` では LLM を呼ばず、規則の読み取りを基にした決まった提案を返す(`ask` の項目は第1候補を選ぶ)。

### 7. 生成画面からの閲覧(2026-10-17 追記)

2026-10-17、ユーザーが次のように指示した: 生成画面で ComfyUI のワークフローを選んだとき、ワークフローを表示して確認できるリンクを出す。メインエリアにワークフローを表示して、パラメーターなどを確認できるようにする。

- 生成画面で ComfyUI のワークフローを選んだとき、モデルの欄の下に「ワークフローを見る」を出す。押すと、メインエリアのタブ(プレビュー・詳細・系列)に「ワークフロー」を足して開く。
- 中身は4章の図の表示と同じ読むだけの図(縮約・すべてのノード、ノードの状態の描き分け)と、選んだノードの入力ごとの扱い(差し込む / 公開 / 固定)と値。差し込む入力と公開パラメーターには、今のフォームの値を添える(未入力ならテンプレートの値)。
- 閲覧だけにする。割り当ての変更や保存はできない。管理者には登録画面(編集)へのリンクを出す。
- 管理者以外にも見せる。そのために、図に要る構造と値だけを返す閲覧用の API を、`require_user` で設ける(登録・編集の API は今までどおり管理者だけ)。テンプレートの値のうち秘密に見えるもの(ADR-0013 8章の判定)は伏せて返す。
- 無効にしたワークフロー・接続は、今までどおり生成画面に出ないので、閲覧もできない。

### 作らないもの

- グラフの構造の編集、テンプレートの値の書き換え、ワークフローの作成支援、配置の保存(1章)
- UI 形式の JSON の取り込み(ADR-0013 のまま。断るときの案内を具体的にする)
- 差し込み先の確認のためだけの実行
- ワークフローのプリセットの同梱・共有

## Options Considered

### 推定の方法

| 案 | 長所 | 短所 |
|---|---|---|
| 今の名前の表に規則を足し続ける | 小さい | 独自の構成のたびに外れる。外れても気付けない |
| **出力から遡る構造の推定 + 確信度(採用)** | 決めきれないものを埋めずに問える。図と検証が同じ判定を使える | 規則の実装が中くらい |
| LLM だけで推定する | 規則の手入れが要らない | LLM が無い環境で使えない。確信度が当てにならない。送る内容の管理が要る |
| `/object_info` を必須にする | 型が確実 | 接続していないと登録できない。プロンプトの根の判定には効かない |

### 画面

| 案 | 長所 | 短所 |
|---|---|---|
| 今のドロップダウン | 実装済み | 初見で何を選べばよいか分からない |
| カードと問いだけ | 狭い幅でも使える。ADR の変更が要らない | 固定・公開・差し込みの全体を一目で見られない |
| 全ノードの図で直接割り当てる | ComfyUI と同じ見え方 | 30 ノードで横 2000px ほどになる。ノードエディタに近い |
| **一覧 + 縮約した読むだけの図とパネル(切り替え。採用)** | 全体の答え合わせと、狭い幅の操作の両方ができる | 束ね方の規則が要る |

## Trade-off Analysis

図を足すと、ADR-0001 の非ゴール「ノードエディタ」に近づく。境界を「テンプレートを変えるか」で引けば、図の操作の結果はこれまでのフォームと同じ差し込み先だけになり、ComfyUI の領域(グラフを組む・直す)には入らない。値を変えたい利用者には、テンプレートを書き換えるのではなく、公開パラメーターとして Run ごとに差し込む道を示す。こうすれば、送った値は `run.params` に残り、証跡の原則(ADR-0003)にも合う。

規則による推定は、検証に使った5本を見ながら作ったので、ほかの構成での精度はまだ分からない。そのため、決めきれないものは推測で埋めずに問い、保存時の検証で誤りを止める。どちらも推定の精度に頼らずに効く。束ね方の規則も同じく、公式のテンプレートと大きなワークフローで確かめてから決める。

LLM による推定は精度が高かったが、規則の推定と検証が先にあれば、LLM は決めきれない項目の手助けにとどまる。そこで任意の最後の段にした。

## Consequences

- 初見の利用者は、読み取り結果を確認し、問われた項目だけに答えれば登録できる。
- 誤った差し込み先は、保存時の検証で止まるか、警告として残る。
- 登録済みのワークフローの保存形式は変わらず、移行も要らない。過去の Run の記録にも影響しない。
- 解析の応答の形が変わる。フロントの型は OpenAPI から作り直す。
- ADR-0001 の非ゴール「ノードエディタ、ワークフロー構築」に、読むだけの図はこれに当たらないことを追記する。
- ADR-0013 の 3章・8章の推定と「作らないもの」を、この ADR で置き換える。
