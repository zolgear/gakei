# ADR-0030: ComfyUI の最終プロンプト(PE の出力)を Run に記録する

**Status:** Proposed
**Date:** 2026-09-30

2026-09-30 にユーザーが次のように決めた。

- ComfyUI のワークフローが実行時に作るテキスト(Prompt Enhancer が書き直した最終プロンプト)を、Run の専用の列に記録する。
- 画面では Asset のパネルに「PE の出力」(2026-10-01 に表示名を「最終プロンプト」に改めた)として表示し、プロンプト欄への挿入・置き換えと、コピーを付ける。
- MCP と共有リンク(ADR-0029)にも出す。
- 最終プロンプトのノードは、ワークフローの登録時に利用者が選ぶ(1章)。

同日、この ADR の内容がユーザーに承認された。2026-10-01 に PR #42 のレビュー指摘を受けて改訂した(末尾の「2026-10-01 改訂」)。

Issue [#40](https://github.com/zolgear/gakei/issues/40)。

## Context

Qwen Image 2.1 のワークフローでは、Prompt Enhancer(PE。`TextGenerate` ノード)が利用者のプロンプトを書き直し、書き直した文で画像を作る。書き直した文は `PreviewAny` ノードを通ってテキストエンコーダーに渡り、`GET /history/{prompt_id}` の `outputs[ノードID].text`(文字列のリスト)に出る。

この文は実行時に作られるので、`run.params.comfyui_prompt`(ADR-0013 4章。送ったグラフ)にも、画像の PNG に ComfyUI が埋め込む `prompt` / `workflow` にも入らない。PE はサンプリングするので、同じ入力と seed でも、ComfyUI や PE のモデルを更新すると結果が変わりうる。いま GAKEI は `outputs[].images` だけを読み、この文を捨てている。そのため、生成の再現、PE がどう書き直したかの確認、PE の出力をもとにしたプロンプトの調整ができない。

ADR-0013 は「作らないもの」に「動画、音声、3D など画像以外の出力」を挙げている。この ADR は、テキストを Asset にはせず Run の記録として持つ形で、そこを改める。

## Decision

### 1. ワークフローの登録: 「最終プロンプト」のノード

- バインディングに任意の項目 **最終プロンプト**(`final_prompt`。ノード id 1つ、または無し)を足す。実行後、このノードの `outputs[id].text` を記録する。画像の出力ノード(`outputs`)とは別に持つ。
- **どのノードにするかは利用者が選ぶ。** PE の組み方(`TextGenerate` 以外のノード、カスタムノード、表示ノードの位置)はワークフローによって様々なので、GAKEI は種類で絞らない。登録画面の選択欄には、テンプレートのすべてのノードと「無し」を並べる(2026-09-30 にユーザーが指定)。
- 既存のワークフローは「無し」として読む(旧形式の bindings はそのまま使える)。
- 選択欄の初期値だけを推定する(ADR-0013 8章。利用者が変えたり「無し」にしたりできる):
  1. タイトルが `gakei:final_prompt` のノード
  2. それが無ければ、テキストエンコーダーのプロンプト入力から配線をさかのぼって最初に見つかる、テキストを表示する出力ノード(`PreviewAny` など。`/object_info` に接続できれば `output_node` のもの)
  - 見つからなければ「無し」。警告は出さない(PE の無いワークフローが普通なので)。
- 選べるのは、テンプレートに存在するノードだけ(`outputs` と同じ検証)。選んだノードが実行時に `text` を返さなければ、記録しないだけで Run は失敗にしない(2章)。

### 2. 記録(`run.text_outputs`)

- `run` に追記のみの列 **`text_outputs`**(JSON、null 可)を足す。形は次のリスト。今は `role = "final_prompt"` の1件だけを書く。
  ```json
  [{"role": "final_prompt", "node_id": "472", "class_type": "PreviewAny", "title": null, "text": "..."}]
  ```
- `node_id`、`class_type`、`title` は `run.params.comfyui_prompt`(送ったグラフ)から取る。ワークフローのテーブルは読まない(ADR-0013 4章と同じ。後でワークフローを編集しても記録は変わらない)。
- `text` はリストの要素を改行でつないだ文字列。1件あたり 100,000 文字で切り詰め、切り詰めたら `"truncated": true` を付ける。
- 書くのは `succeeded` になるときの1回だけ(`usage` と同じ時点)。失敗した Run には書かない。
- 最終プロンプトのノードを登録してあっても `text` が無かった(ノードが実行されなかった、出力の形が違う)ときは、列を null のままにして Run は成功にする。サーバーのログに警告を出す。画像が無いときの `comfyuiNoOutput` は変えない(テキストだけのワークフローは今までどおり扱わない)。
- ADR-0003 のルール1の「UPDATE してよい列」に `run.text_outputs` を加える(完了時の1回だけ)。ルール4(`params` には送った値だけ)は変えない。これは送った値ではなく結果なので、`params` にも `usage` にも入れない。

### 3. 表示

- **ビューアの Asset パネル:** プロンプトの下に「最終プロンプト」(当初の表示名は「PE の出力」。2026-10-01 改訂)を出す。初めは数行だけ見せて折り畳み、展開できる。ボタンは次の3つ。
  - プロンプトに挿入 / 置き換え: スタジオのプロンプト欄に入れる。動きは系列インスペクターの既存の「挿入」「置き換え」(`RunPromptActions`)と同じにする(置き換えは、入力済みの内容があれば確認する)。
  - コピー
- **Run の詳細、スタジオの系列インスペクター:** 同じ表示とボタンを出す。
- 見出しは「最終プロンプト」(英語は "Final prompt"。2026-10-01 改訂。当初は「PE の出力」)。ノードのタイトルがあれば、あわせて小さく出す(例: `472: PreviewAny`)。
- PE を OFF にするのは利用者の操作に任せる。GAKEI はどのパラメーターが PE の切り替えかを知らないので、挿入のときに自動で切り替えない。

### 4. API、MCP、共有リンク

- `RunSummary` / `RunDetail` に `text_outputs` を足す。Asset の `produced_by_run` にも出す。
- MCP の Run 取得ツールと、Asset 取得の `produced_by_run` に `text_outputs` を足す(ADR-0023)。
- 共有リンクのページ(ADR-0029 3章)の「見せるもの」に、Run のプロンプトの下の最終プロンプトを加える。

### 5. 作らないもの

- 最終プロンプト以外のテキスト出力の記録(デバッグ用の `PreviewAny` など)。列の形は複数件を持てるようにしておき、必要になったら `role` を足す。
- テキストを Asset にすること、テキストだけを出力するワークフロー。
- 実行中に WebSocket の `executed` イベントでテキストを先に見せること。完了後の `/history` からだけ読む。
- 最終プロンプトによる検索、ダウンロードする PNG への埋め込み(ADR-0014)。
- OpenAI の Run の、実際に使われたプロンプトの記録(別の話題として扱う)。

## Options Considered

### 記録する場所

| 案 | 評価 |
|---|---|
| **run の専用列 `text_outputs`(採用)** | 結果として意味がはっきりする。API、MCP、共有に出すときの扱いを個別に決められる。マイグレーションが1本要る |
| `run.usage` の JSON に入れる | マイグレーションは要らないが、usage は課金と実行時間の記録で、料金の計算や履歴のトークン表示が読む。MCP と共有では usage を見せていない |
| `run.params` に入れる | ADR-0003 のルール4(送った値だけ)に反する |

### どのノードを記録するか

| 案 | 評価 |
|---|---|
| **最終プロンプトのノードを登録時に1つ決める(採用)** | 画面で「PE の出力」(2026-10-01 に表示名を「最終プロンプト」に改めた)と名前を付けて出せる。推定で多くの場合は自動で決まる |
| 画像の出力ノードに選んだノードのうち、`text` を持つものをすべて記録 | 設定は増えないが、何のテキストかが分からず「PE の出力」として扱えない。デバッグ用の表示ノードも混ざる |
| 実行されたすべてのノードの `text` を記録 | 同上。量も読めない |

## Trade-off Analysis

バインディングの項目が1つ増えるが、推定で埋まるので、Qwen Image 2.1 のワークフローでは利用者の手間は増えない。汎用の「テキスト出力」にせず PE 用の役割に絞ったのは、画面で意味のある名前を付け、挿入・置き換えの対象をはっきりさせるため。列の形はリストにして、将来ほかの役割を足せるようにした。

## Consequences

- マイグレーション 0023 で `run.text_outputs` を足す。既存の Run は null。
- ADR-0003 のルール1に `text_outputs` を加え、`backend/app/worker/runner.py` の先頭のコメントも合わせる。
- ADR-0013 の「作らないもの」の「画像以外の出力」に、この ADR への参照を添える。
- ADR-0029 の「見せるもの」に最終プロンプトを加える。
- 自動テストは偽の ComfyUI(`backend/tests/comfyui_fake.py`)の `/history` に `text` を入れて確かめる。

## 2026-10-01 改訂

PR #42 のレビュー指摘を受け、ユーザーの承認を得て次のように改めた。

1. **DB に書けない文字を取り除く。** PostgreSQL の JSONB は `\u0000`(NUL)を含む文字列を受け付けず、対になっていないサロゲートは UTF-8 にできない。どちらも完了時の commit を失敗させ、画像はできているのに Run が failed になる(2章の「Run は成功にする」に反する)。ComfyUI から読んだ `text` と、グラフから取る `class_type`・`title` について、NUL は取り除き、対になっていないサロゲートは置き換え文字にする。
2. **空の最終プロンプトは記録しない。** `text` が `""` や `[""]` など、空白を除いて空になるときは、`text` が無いときと同じく記録しない(列は null、Run は成功。サーバーのログに警告を出す)。
3. **画面の表示名を「PE の出力」から「最終プロンプト」に改める**(英語は "PE output" から "Final prompt")。PE を OFF にしたワークフローでも、モデルに渡った文(元のプロンプト)が記録されるので、見出しを中身に合わせる。ワークフローの登録画面の項目名も「最終プロンプト」にそろえる。表示名だけを変えたので、この ADR の本文で PE の出力という概念を説明している箇所はそのままにしている。
4. **共有のページでも、ノードの id・種類・タイトルを出す。** レビューでは、ログイン不要の公開 API にこれらを出すのは ADR-0029 の「ComfyUI の内部の値を出さない」方針と食い違う、という指摘があった。ユーザーは、共有は再現できるものを渡すのが目的なので出してよいと判断した(公開 API とダウンロードする PNG の params は今のまま)。ComfyUI のパラメーター全体を共有のページで見せることは、ADR-0029 で別に改める。

## 2026-10-10 追記(ADR-0038)

SD WebUI の Dynamic Prompts(ADR-0038 7章)で、1枚ずつ展開されたプロンプトも `text_outputs` に書く。そのため2章の「`role = "final_prompt"` の1件だけ」を次のように広げる。

- 要素に `output_index`(null 可)を足す。null は Run のすべての出力に当たる(ComfyUI の最終プロンプトは今までどおり null の1件)。数値なら、同じ `output_index` の出力 Asset に当たる。
- `role` に `final_negative_prompt` を足す(SD WebUI の展開後のネガティブプロンプト)。
- SD WebUI は、展開しなかった出力も含め、出力ごとに記録する。表示では、Run のプロンプト(ネガティブはパラメーターの値)と同じものは出さない。
