# ADR-0013: ローカル ComfyUI をプロバイダーに加える

**Status:** Proposed(ブランチ `experiment/comfyui-provider` での検証を経て、2026-09-24 に main へ取り込む。利用者向けには実験的な機能と表示する)
**Date:** 2026-09-23

## Context

ローカル版(ADR-0008、ADR-0012)の利用者の多くは、同じ PC で ComfyUI も動かしている。ComfyUI で組んだワークフロー(t2i や inpaint)を GAKEI から呼べれば、OpenAI の画像 API と ComfyUI の実行を、同じ履歴、同じ系列グラフ、同じビューアで扱える。たとえば「OpenAI で生成した画像を、ローカルのモデルで部分的に描き直す」といった流れの来歴を、1本の系列として残せる。

一方で、ADR-0001 は「ComfyUI など他プロバイダー対応」を非ゴール(Phase 3)にしており、ADR-0005 も「ComfyUI アダプターは作らない。インターフェースに収まるかを机上で確認するに留める」としている。この ADR はその2つを改める。

ComfyUI の API で使うもの(2026-09-23 時点の ComfyUI のソースで確認):

- `POST /prompt`(API 形式のグラフを投入し、`prompt_id` を得る)、`GET /history/{prompt_id}`、`GET /view`(出力画像の取得)、`POST /upload/image`、`GET /system_stats`、`GET /object_info`。
- `GET /ws?clientId=…`(WebSocket)。`progress`、`executing`、`execution_success`、`execution_error` のイベントと、途中経過のプレビュー画像(バイナリのフレーム)が流れる。
- `LoadImage` は IMAGE と MASK を出力し、MASK は `1 - alpha` である。`LoadImageMask`(channel = alpha)も同じく `1 - alpha` を返す。GAKEI のマスクの規約(alpha = 0 が編集範囲。OpenAI の Edit と同じ)は、変換せずにそのまま通用する。

## Decision

### 1. 範囲

- 対象は **同じ PC で動くローカルの ComfyUI 1台** だけにする。**既定は無効**で、利用者が設定画面から接続先を入れて有効にする(7章)。
- 操作は2つ。
  - **Generate(t2i):** プロンプトから画像を作る。
  - **Edit:** 入力画像1枚以上と、任意のマスク1枚。入力画像の枚数は、ワークフローに登録した「画像の枠」の数と同じにする(3章)。マスクは1枚目の画像に対するもの。
- **グラフの構造は変えない。** GAKEI は登録済みのワークフローの、決められた入力に値を差し込むだけにする。ノードの追加、削除、配線の変更は行わない(ADR-0001 の非ゴール「ノードエディタ、ワークフロー構築」は変えない)。

### 2. 複数のプロバイダーを同時に使う

- OpenAI(または Fake)と ComfyUI を同時に有効にできる。どちらを使うかは Run ごとに選ぶ。Run 作成の API の `provider` を省略すると、これまでどおり主プロバイダー(設定 `PROVIDER`)を使う。
- 系列はプロバイダーをまたいでつながる。OpenAI の出力を ComfyUI の Edit の入力にしてよく、その逆も同じ。`run.provider` は既存の列で、すでに Run ごとに記録している。
- `GET /api/capabilities` は、プロバイダーの一覧を返す形に変える(破壊的変更)。ComfyUI については、登録済みのワークフロー1件をモデル1件として見せ、UI のフォームはこれまでどおり capabilities から組み立てる(ADR-0005)。

### 3. ワークフローの登録(`comfy_workflow` テーブル)

- ComfyUI の「Export (API)」で書き出した **API 形式の JSON** を、GAKEI の画面から登録する。UI 形式(`nodes` と `links` を持つ JSON)は受け付けず、API 形式で書き出すよう案内する。
- 登録するときに、差し込み先(バインディング)を対応付ける。
  - 必須: プロンプト、出力ノード(Generate)/画像の枠を1つ以上(Edit)
  - 任意: ネガティブプロンプト、seed、幅と高さ、枚数(batch_size)、マスク
  - GAKEI は候補を提案する。ノードのタイトルが `gakei:prompt` や `gakei:image` などの規約に合うものを最優先し、次に代表的なノード(`KSampler`、`CLIPTextEncode`、`EmptyLatentImage`、`LoadImage`、`LoadImageMask`、`SaveImage`)から推定する。規約はヒントであり、必須ではない。
- **画像の枠(Edit):** 入力画像を差し込む `LoadImage` の `image` 入力を、順序付きで1つ以上登録する。GAKEI の入力の n 枚目(`run_input.position` の順)を n 番目の枠に差し込む。1枚目が系列の主たる親になる(ADR-0003)。
  - 枠はすべて必須で、Run の入力画像はちょうど枠の数だけ要る。足りない枠をワークフローの値のまま送ると、ComfyUI 側の見知らぬ画像で実行されてしまうため。グラフの構造は変えないので、枚数に合わせて枠を増減することもしない。
  - 候補の提案: 可変長の画像入力(`TextEncodeQwenImage21` の `images.image_1`、`images.image_2` など)につながる `LoadImage` は、その番号の順に並べる。それ以外は、ノードの id の順にする。マスク専用の `LoadImageMask` は枠にしない。
  - 例: Qwen Image 2.1 の画像編集のテンプレートは、人物(枠1)と着せる衣服(枠2)の2枠になる。プロンプトの `<image1>`、`<image2>` が枠の順に対応する。
- 差し込み先以外の入力のうち、利用者がフォームに出したいもの(steps、cfg、ckpt 名など)を **公開パラメーター** として登録する。型と範囲は、接続できれば `/object_info` から補う。
- マスクの渡し方は2通りに対応する。
  - `LoadImageMask` があるワークフロー: マスクの PNG をそのまま渡す。
  - `LoadImage` の MASK 出力を使うワークフロー: 送信のときだけ、入力画像にマスクの alpha を合成した PNG を作って渡す。Asset の原本は変えない(ADR-0004)。
- `comfy_workflow` は **証跡ではない。** プロンプトセット(ADR-0009)と同じく、更新と論理削除ができる。Run との間に外部キーは張らない。

### 4. Run の記録(`run.params`)

ADR-0003 のルール4(`params` には API に送った値をそのまま保存する)を守るため、**Run を作る時点でグラフを確定し、`run.params` に保存する。**

- 利用者が指定した値(公開パラメーター、seed など)に加えて、サーバーが次の値を付け足す。
  - `comfyui_workflow`: ワークフローの id、名前、テンプレートの sha256
  - `comfyui_seed`: 指定がなければサーバーが決める(JavaScript の数値で正確に扱える 2^53 未満)
  - `comfyui_uploads`: 入力画像をアップロードするときのファイル名(枠の順)。`gakei_{sha256}.{拡張子}` と内容から決める
  - `comfyui_prompt`: 値を差し込んだ後のグラフ全体。これが ComfyUI に送る本文そのものになる
- 実行時は `comfyui_prompt` をそのまま送り、ワークフローのテーブルを読まない。あとでワークフローを編集または削除しても、過去の Run の記録と再実行の内容は変わらない。
- `comfyui_` で始まる項目はサーバーだけが書く。クライアントから送られたら 422 にする。
- `usage` には `prompt_id` と実行時間を入れ、`provider_request_id` には `prompt_id` を入れる。料金は表示しない(参考価格の対象外)。

### 5. 実行

- **プロバイダーごとに実行レーンを1本ずつ持つ。** runner は、プロバイダーごとに `queued` の Run を1件ずつ取り出して実行する。GPU で数分かかる ComfyUI の実行が、OpenAI の実行を待たせないようにするため。同じプロバイダーの中では、これまでどおり直列に実行する。
- **進捗とプレビューは WebSocket で受け取る。** ステップの進捗(`value / max`)を SSE の新しいイベント `progress` としてブラウザに流す。プレビュー画像は PNG に変換し、間引いて(0.5 秒に1回まで)既存の途中経過画像の仕組みで流す。途中経過画像は Asset にしない(ADR-0005)。
- WebSocket が切れたら `/history` のポーリングに切り替えて完了を待つ。タイムアウトは7章の設定(既定 1800 秒)。
- 出力は、登録した出力ノードの順、ノードの中では画像の順に Asset にする(`output_index`)。
- **キャンセルは待機中(`queued`)の Run だけ。** ComfyUI の `/interrupt` は使わない。`/interrupt` は ComfyUI で実行中のものを、誰が投入したかに関係なく止めるため、ComfyUI の画面から利用者が直接投入したジョブを巻き込む。
- 再起動で中断した Run は、これまでどおり `failed` + `interrupted` にする(ADR-0008)。ComfyUI 側で実行が続いて結果が出ても、取り込まない。
- 起動時に、有効でないプロバイダーの `queued` の Run は `failed` + `providerUnavailable` にする。

### 6. 接続できないとき、失敗したとき

- ComfyUI に接続できないときは、**Run を作らずに 409 を返す**。API キーが未設定のときと同じ考え方(ADR-0012)で、利用者の環境の問題を失敗の Run として残さない。接続の確認(`/system_stats`)は短いタイムアウトで行い、結果を数秒キャッシュする。
- 実行後の失敗は、`failed` の Run として残す(ADR-0005)。`error_code` は次のとおり。
  - `comfyuiUnavailable`: 実行の途中で接続できなくなった
  - `comfyuiValidation`: `/prompt` がグラフを拒否した(存在しない ckpt など。`node_errors` の要約を `error_message` に入れる)
  - `executionError`: ワークフローの実行中に失敗した
  - `comfyuiUpload`: 入力画像のアップロードに失敗した
  - `comfyuiNoOutput`: 出力ノードに画像がなかった
  - `timeout`: 時間切れ

### 7. 設定

**既定は無効。** ComfyUI を使わない利用者の画面に ComfyUI の項目を出さないため。有効にする手順は、設定画面から始める。

- **接続は設定画面で行う。** `/settings/comfyui` に接続先の URL を入れて保存すると有効になる。(2026-10-01: ワークフローの一覧は設定の ComfyUI のページ `/settings/comfyui` の一節に、登録・編集は `/settings/comfyui/workflows/new`・`/settings/comfyui/workflows/:id` に移した。ADR-0031)同じ画面で次の操作ができる。
  - **接続テスト:** 入力中の URL、または接続中の URL に `/system_stats` で接続できるかを確かめ、バージョンとデバイスを表示する。設定は変えない。いつでも押せる。
  - **URL の変更**
  - **切り離す:** 接続の設定を消し、ComfyUI を使わない状態にする。「切り離した」ことを設定として保存するので、環境変数 `COMFYUI_URL` が指定されていても、再起動で再び有効にはならない。
  - 保存先は DB の設定テーブル(`app_setting`。キーと値の組)。`DATA_DIR` ごとの設定になる。証跡ではないので、更新してよい。
  - 変更はサーバーを再起動せずに反映する。接続したらレーンを追加し、切り離したら ComfyUI をモデルの選択肢から外す。
  - ComfyUI の Run が `queued` か `running` の間は、変更を 409 で断る。実行中の Run の接続先が途中で変わらないようにするため。
  - 切り離しても、登録済みのワークフローと過去の Run は消さない。再び接続すれば、そのまま使える。ワークフローの登録と編集は、切り離している間もできる(`/object_info` による補完だけが効かない)。
  - URL は `http` か `https` だけを受け付ける。ループバック以外のアドレスは、画面で警告を出し、確認のチェックを入れないと保存できない(認証のない ComfyUI に、入力画像とプロンプトを送ることになるため)。サーバーのログにも警告を出す。
- **環境変数 `COMFYUI_URL` は既定値として起動時にだけ読む。** 画面で一度も設定していなければ、その値で有効になる。画面で接続または切り離しをしたら、それ以降は再起動しても画面の設定が優先し、環境変数は使わない。環境変数の値は DB に保存しない。`.env.example` ではコメントアウトしておく。
- **1回の実行を待つ上限(タイムアウト):** 既定は 1800 秒。設定画面の ComfyUI の欄で変えられる(2026-09-24。当初は環境変数だけで設定するとしていた)。優先順は接続先と同じで、画面で保存した値(`app_setting`)、環境変数 `COMFYUI_TIMEOUT_SECONDS`、既定の 1800 秒の順。画面では分単位で入力し、範囲は1〜180分。変更は再起動なしで、次に始まる実行から反映する。
- **ポートの衝突:** ComfyUI Desktop の既定のポートは 8000 で、GAKEI の既定と同じである。両方を使うときは、GAKEI を `--port` で別のポートにする。README に書く。ポータブル版の ComfyUI の既定は 8188 で、衝突しない。
- 本線では、この設定は `admin` だけが変えられるようにする(本線に着手するときに改めて決める。Consequences 参照)。

### 8. フォームと登録の補助(実装中に決めたこと。2026-09-24)

- **seed の欄:** 「ランダム」(サーバーが決める)と「固定」(値を指定し、乱数で振り直すボタンを添える)を切り替える。初期は「固定」で、利用者が選んだモードをブラウザごとに記憶し、次からはどのワークフローでもそのモードで始める。ワークフロー単位にはしない(チームではワークフローを管理者が用意し、固定かランダムかは使う人の作業によって変わるため)。「同じ設定で再実行」は、記憶したモードに関係なく、使った seed を固定して開く。
- **バッチの seed:** ComfyUI では1つの seed からバッチ全体のノイズを作るので、1枚を再現するには seed、枚数、何枚目かが要る。Asset の表示では「seed N ・ B 枚中 k 枚目」と書く。1枚ずつ別の Run にはしない。
- **フォームの並べ方:** ComfyUI のワークフローを選んだときは、公開パラメーターを「その他」に畳まずに、登録した順ですべて表示する(利用者が登録時に選んだものだけなので)。値を指定しない欄には、ワークフローの値を「既定値 (X)」と表示する。
- **登録時の推定(analyze):** タイトルの規約(`gakei:prompt` など)を最優先し、次に代表的なノードから推定する。`/object_info` に接続できれば、選択肢(新しい形式の COMBO を含む)と範囲を補い、既定値はワークフローに書かれた値を使う。プロンプトは、文字列を素通しするノードを越えてさかのぼる。出力は保存ノードを優先し、比較用のノード(`ImageCompare` など)は出力にしない。特定できなかったものは警告で知らせ、プロンプトを特定できないときは、配線をさかのぼって見つかった文字列の入力を候補として警告に並べる(自動では選ばない)。

- **秘密に見える値の警告(2026-10-01 追記):** カスタムノードには、API キーなどを入力に直接書くものがある。グラフに書かれた値は Run の記録(`run.params` の送ったグラフ)と、ComfyUI が原寸の PNG に埋め込むグラフに残る。登録時の推定(analyze)で、各ノードの入力の文字列の値を調べ、秘密に見えるものを警告に並べる(ノードの id、種類、入力の名前。値そのものは出さない)。登録は止めない(判定は推測で、誤りも漏れもありうるため)。判定は次のどちらか。
  - 入力の名前を語に分けたとき(`_`・`-`・大文字の切れ目で区切る)、`api_key`・`apikey`・`token`・`secret`・`password`・`credential`・`authorization`・`bearer`・`access_key`・`private_key` などに当たる(`max_tokens` のような別の語は当たらない)。値が空のものは除く。
  - 値が、よく知られた API キーの形(`sk-…`、`hf_…`、`ghp_…`、`AKIA…`、`AIza…`、`Bearer …` など)に当たる。
  - 同じ判定を、共有のページ(ADR-0029 3章・4章)で Run の送ったグラフと公開パラメーターに掛け、値を伏せ、その Run の画像の原本を出さない。
  - ComfyUI 公式の API ノードは、キーをグラフに入れずに実行時に渡すので当たらない。

### 作らないもの

- グラフの構造の編集、ノードエディタ、ワークフローの作成支援(ADR-0001 の非ゴールのまま)
- UI 形式の JSON の取り込み(API 形式への変換)
- 複数の ComfyUI サーバー、リモートの ComfyUI への正式な対応、ComfyUI 側の認証
- 実行中の Run のキャンセル(`/interrupt`)
- モデル、LoRA、カスタムノードの管理やインストール
- 動画、音声、3D など画像以外の出力。ただし、PE が書き直した最終プロンプト(テキスト)は Asset にせず Run に記録する(2026-09-30 追記。ADR-0030)
- 入力画像の枚数が Run ごとに変わるワークフロー(枠の数は登録時に決まる)。2枚目以降の画像へのマスク
- ComfyUI 以外のプロバイダー(Phase 3 のまま。2026-10-10 追記: Stable Diffusion WebUI の A1111 互換の API は ADR-0038 で対象にした)

## Options Considered

### ワークフローの管理

| 案 | 評価 |
|---|---|
| A: 画面から API 形式の JSON を登録し、差し込み先を対応付けて DB に保存する(採用) | 利用者がファイルの置き場所やタイトルの規約を覚えなくてよい。登録時に検証できる。画面と API が増える |
| B: ノードのタイトルの規約(`gakei:prompt` など)と、決まったフォルダーにファイルを置く | 実装が小さい。利用者が ComfyUI 側でタイトルを付け直す必要があり、既存のワークフローをそのまま使えない。規約は A の提案のヒントとして残す |
| C: UI 形式の JSON を受け付けて、API 形式に変換する | 保存したワークフローをそのまま使えるが、変換には `/object_info` とウィジェットの並び順の知識が要り、ComfyUI の更新で壊れやすい |

### Run に何を記録するか

| 案 | 評価 |
|---|---|
| A: 値を差し込んだグラフ全体を `run.params` に保存する(採用) | ADR-0003 のルール4 に合う。ワークフローを後で変えても、来歴と再実行が壊れない。Run 1件あたりの記録が数十 KB 増える |
| B: ワークフローの id と差し込んだ値だけを保存する | 記録は小さいが、ワークフローを編集すると、過去の Run が何を実行したか分からなくなる |

### 進捗の受け取り方

| 案 | 評価 |
|---|---|
| A: WebSocket で受け取り、切れたらポーリングに切り替える(採用) | ステップの進捗とプレビューを出せる。依存(`websockets`)はすでに uvicorn 経由で入っている |
| B: `/history` のポーリングだけ | 単純だが、数分かかる実行の間、何も表示できない |

### プロバイダーの切り替え

| 案 | 評価 |
|---|---|
| A: 複数のプロバイダーを同時に有効にし、Run ごとに選ぶ(採用) | プロバイダーをまたいだ系列を作れる。capabilities の API とフォームの形が変わる |
| B: 起動時の設定 `PROVIDER=comfyui` で1つに切り替える | 変更は小さいが、OpenAI と ComfyUI を行き来する使い方ができない。系列もつながらない |

### 接続先の設定

| 案 | 評価 |
|---|---|
| A: 既定は無効。設定画面で接続先を入れて有効にし、DB に保存する。環境変数は、画面で設定するまでの既定値としてだけ使う(採用) | ComfyUI を使わない利用者に項目が出ない。`.env` を編集せずに始められる。設定テーブルと、再起動なしで切り替える仕組みが要る |
| B: 既定で `http://127.0.0.1:8188` に接続する | 設定なしで使えるが、ComfyUI を使わない利用者にも「ComfyUI(接続できません)」が常に出る |
| C: 既定は無効。環境変数 `COMFYUI_URL` だけで有効にする | 実装は小さいが、`.env` の編集と再起動が要り、画面から始められない |

### 入力画像が2枚以上のワークフロー

| 案 | 評価 |
|---|---|
| A: 画像の枠を順序付きで登録し、枠の数ちょうどの枚数を要求する(採用) | グラフを変えずに済み、GAKEI の入力の順序と系列の考え方(1枚目が主たる親)にそのまま合う。枚数を変えたいときは、枠の数が違うワークフローを別に登録する |
| B: 2枚目以降の枠を任意にし、足りなければワークフローの値のまま送る | 柔軟だが、ComfyUI の input フォルダーにある見知らぬ画像で実行され、Run の記録(`run_input`)と実際の入力が食い違う |
| C: 入力の枚数に合わせて `LoadImage` を増減する | 枚数は自由になるが、グラフの構造を変えることになり、この ADR の前提(値を差し込むだけ)を崩す |

## Trade-off Analysis

この機能は ADR-0001 の「迷ったら作らない」と、非ゴール「ノードエディタ、ワークフロー構築」の境目にある。境目を越えないために、GAKEI が扱うのは「登録済みのグラフに値を差し込んで投げる」ことだけに限った。グラフを組む、直す、変換するといった作業は ComfyUI の画面に残す。

実装の大きさは、主に次の2点から来る。

- capabilities の形の変更: 複数のプロバイダーを同時に扱うため
- ワークフローの登録画面: 画面から登録するため

どちらも利用者が選んだ使い方(Run ごとの切り替え、画面からの登録)に直接対応しているので、削らない。代わりに、Edit の入力を登録した枠の数ちょうどに限り、マスクを1枚目だけにし、キャンセルを待機中に限ることで、ComfyUI 固有の処理を小さく保つ。

証跡の面では、ComfyUI の Run も OpenAI と同じ `run` / `run_input` / `asset` に記録するので、ADR-0003 のモデルは変わらない。新しいテーブル `comfy_workflow` は証跡ではなく、捨てても来歴は残る。

実現できるか、使い続ける価値があるかは、動かしてみないと分からない部分が大きい。そのため、実験用のブランチで実装して検証し、main に入れるかはその結果で決める。

## Consequences

- ローカル版で、OpenAI の画像 API とローカルの ComfyUI を同じ画面で使い分けられ、プロバイダーをまたいだ系列が残る。
- ADR-0001 の非ゴール「ComfyUI など他プロバイダー対応」から、ローカルの ComfyUI を外す。その他のプロバイダーは Phase 3 のまま。
- ADR-0005 の「ComfyUI アダプターは作らない」を、この ADR で置き換える。`ImageProvider` のプロトコルに、サーバーが params を確定するフックと、ステップの進捗のイベントが加わる。
- `GET /api/capabilities` の形が変わる。フロントの型は OpenAPI から作り直す。
- 本線(Azure、ADR-0002〜0007)では、同じ PC の ComfyUI という前提が成り立たない。本線での扱いは、本線に着手するときに改めて決める。
- 自動テストは、偽の ComfyUI(HTTP と WebSocket)だけを使い、実物に接続しない。
