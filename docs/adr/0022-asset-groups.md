# ADR-0022: グループ(ストックの手動整理)

**Status:** Proposed
**Date:** 2026-09-27

## Context

ストック(`GET /api/assets`)は kind による絞り込みと、削除しかない。ADR-0003 の採用/不採用(`asset_mark`)とタグは設計だけで、ローカル MVP には実装していない。生成と取り込みを重ねるとストックが数百枚になり、「この案件の画像」「参考画像」のようなまとまりを利用者が作れないと探せなくなる。

系列(lineage)は生成の来歴を表す軸で、利用者の意図による分類とは別の軸が要る。ADR-0001 の非ゴール表は「汎用 DAM(任意ファイル管理、フォルダ階層)」を作らない理由として「プロジェクト+フラグ+タグで足りる」としている。この「プロジェクト」に当たるものがまだ無い。

Issue [#6](https://github.com/zolgear/gakei/issues/6)。自動整理(タグや VLM による分類。[#5](https://github.com/zolgear/gakei/issues/5))は後続で、この ADR は手動整理の器だけを決める。

## Decision

### 1. 範囲

- **グループは階層なしのフラットな集まり。** **1 つの Asset が属するグループは 1 つだけ**(2026-09-28 に多対多から変更。複数に属せるのはタグの性質で、そちらは将来の #5 の範囲)。グループに入れる操作は常に「移す」で、元のグループからは外れる。フォルダ階層、グループの入れ子は作らない(グループ同士の並べ替えは利用者が決める。2章)。
- **グループは証跡ではない。** 名前の変更、メンバーの追加・削除、グループの削除は自由に行える(ADR-0003 の追記のみの規則の対象外。タグや `asset_mark` と同じ扱い)。
- グループは利用者全員で共有する(oidc モードでも個人ごとに分けない。ADR-0019 の「閲覧範囲は全員が全件」に合わせる)。作成・変更は管理者に限定しない。
- 対象は削除済みでない Asset で、kind は問わない(マスクも入れられる)。
- **使われ方は縛らない。** グループに入る入り口は 3 つを想定する(2026-09-27 追記)。(a) 生成時にグループを指定し、出力がそのグループに入る。(b) 生成後に利用者が手で整理する(ドロップ、選択モード、ビューア)。(c) 将来、種類(イラスト、キャラクター、素材など)ごとに自動で分類する(#5)。今回は (a) と (b) を作る。(c) を足すときも、自動で入れたメンバーを人が外せることを前提にする。

### 2. データモデル

```
asset_group(
  id UUID PK,
  name VARCHAR(100) NOT NULL,
  position INTEGER NOT NULL,                      -- 利用者が決める並び順(小さいほど上。2026-09-28 追加)
  created_by_user_id UUID NULL FK app_user.id,   -- none モードは NULL(ADR-0019 と同じ)
  created_at, updated_at TIMESTAMPTZ NOT NULL,
  deleted_at TIMESTAMPTZ NULL                     -- 論理削除(prompt_set と同じ。復元の余地を残す)
)
asset_group_member(
  asset_group_id UUID FK asset_group.id,
  asset_id UUID FK asset.id,
  added_at TIMESTAMPTZ NOT NULL,
  PRIMARY KEY (asset_group_id, asset_id)
)
UNIQUE INDEX ux_asset_group_member_asset_id (asset_id)   -- 1 つの Asset は 1 つのグループにだけ(2026-09-28 に通常の索引から変更)
```

- メンバーの削除は物理削除。グループの削除は `deleted_at` を立てるだけで、メンバー行は残す(復元 API は今は作らない)。削除済みグループに残っている Asset を別のグループに入れると、その行は移る(所属は常に 1 行)。
- Asset を論理削除してもメンバー行は残し、一覧では `asset.deleted_at IS NULL` で除く。Asset の復元(ADR-0008)でグループにも戻る。
- 表紙画像は列に持たず、`added_at` が最新のメンバーを一覧の応答で返す。
- **生成時の指定**は `run.asset_group_id`(NULL 可、FK `asset_group.id`)に持つ。作成時に一度だけ書く列なので ADR-0003 の追記のみの規則に反しない。Run が成功して出力の Asset を取り込んだ直後に、worker がその Asset をグループに入れる(`added_at` は取り込み時刻)。指定したグループが実行までに削除されていたら、入れずに成功させる(Run は失敗にしない)。
- **並び順は利用者が決める**(2026-09-28 追加)。`position` の昇順(同値は `created_at DESC`)で返し、新しいグループは先頭(既存の最小値 − 1)に入る。並べ替えは全件の順序を一度に受け取って 0 から振り直す。**順序が変わるのは明示的な並べ替えだけ**で、メンバーの追加・削除、名前の変更、生成時の追加では動かない(`updated_at DESC` で並べていた間は、画像を入れるたびにそのグループが先頭へ動いてしまった)。
- 名前は前後の空白を除いて 1〜100 文字。同名のグループを禁止しない(利用者が付けた名前をサーバーが拒む理由が弱い)。

### 3. API

すべて `require_user`(ADR-0019 の既定)。

| メソッド | パス | 内容 |
|---|---|---|
| `GET` | `/api/asset-groups` | 削除済みでないグループを `position ASC, created_at DESC` で全件(2026-09-28 に `updated_at DESC` から変更)。各行は `{id, name, member_count, cover_asset_id, created_at, updated_at}`(`member_count` と `cover_asset_id` は削除済みでない Asset だけを数える。ページングなし。prompt-sets と同じ) |
| `POST` | `/api/asset-groups` | `{name}` → 201、作成した行 |
| `PATCH` | `/api/asset-groups/{id}` | `{name}` → 更新した行 |
| `DELETE` | `/api/asset-groups/{id}` | 論理削除 → 204 |
| `PUT` | `/api/asset-groups/order` | `{group_ids: [UUID, ...]}`。削除済みでない全グループの id を望む順に並べたもの。過不足があれば 422。`position` を 0 から振り直し、一覧の順で返す(2026-09-28 追加) |
| `POST` | `/api/asset-groups/{id}/assets` | `{asset_ids: [UUID, ...]}`(1〜200 件)。**そのグループへ移す**: 別のグループに入っていれば外してから入れる(2026-09-28)。既に入っているものは無視し、削除済みや存在しない Asset は 404 で全体を拒む → 更新後のグループ行 |
| `POST` | `/api/asset-groups/{id}/assets/remove` | `{asset_ids}` → 入っていないものは無視 → 更新後のグループ行 |
| `GET` | `/api/assets?group_id=` | 既存の一覧に `group_id` を足す。`kind` と併用でき、並びとカーソルは既存のまま(`created_at DESC, id DESC`)。存在しない・削除済みのグループは 404 |
| `GET` | `/api/assets?ungrouped=true` | 削除済みでないどのグループにも入っていない Asset だけ(ストックの「グループなし」の節)。`group_id` と同時に指定すると 422 |

- `RunCreateRequest.asset_group_id`(任意)。存在しない・削除済みなら 404 `assetGroups.notFound`。`RunSummary` / `RunDetail` に `asset_group: {id, name} | null` を足す(削除済みグループなら null。**再実行でフォームに戻すためだけ**。画面には出さない。2026-09-28 変更)。
- `AssetDetail.group: {id, name} | null` を足す(2026-09-28 に `groups: []` から変更)。ビューアの詳細で表示と切り替え・解除に使う。`AssetSummary` には足さない(一覧が重くなる)。
- メンバーの追加・削除・名前変更でグループの `updated_at` を進める。
- 削除済みグループに対する `PATCH` / メンバー操作 / `group_id` 絞り込みは 404。

### 4. 画面

グループは「絞り込み」ではなく **入れもの** として見せる(Claude Code のサイドバーがセッションをグループの下に並べるのと同じ形。2026-09-27 に、絞り込みのチップ行と縦リストを試した上で改めた)。

- **ストックパネルはグループごとの節に分かれる。** 上から、「グループなし」の節、続いて各グループの節(利用者が決めた並び順。`position ASC`)(2026-09-27 に「グループなし」を先頭へ。新規作成の「+」をグループの並びの起点に置くため)。各節は見出し行(開閉の印、名前、件数、右端に「⋯」)と、その下のサムネイルのグリッド(既存の 2 列のタイル)でできている。「グループなし」は `GET /api/assets?ungrouped=true`、各グループは `GET /api/assets?group_id=` で取り、kind のチップは全節に共通の絞り込みとして残す(見出し「種類」を付ける)。
- **開閉**: 節は畳める。開閉の状態はグループごとに localStorage(`gakei:stock-group-open`、id → 真偽の JSON)に持ち、既定は開いた状態。畳んだ節は取得しない。各節は最初の 1 ページ(30 件)を出し、続きは「さらに表示」で足す。「グループなし」だけは末尾の番兵で自動的に続きを読む(既存の無限スクロール)。
- **空のグループ**は見出しの下に「ここに画像をドロップ」の枠を出す。
- **入れる**: タイルを節の見出し(または空の枠)に **ドラッグ&ドロップ** するとそのグループに入る(既存のドラッグ(入力に使う)と同じ `dataTransfer` の型を使う)。所属は 1 つなので、別の節へ落とすとそこへ移り、元の節からは消える。「グループなし」の見出し(または空の枠)に落とすとグループから外れる(確認は出さない)。ドラッグできない環境(タッチ)向けと一括操作向けに **選択モード** も残す: ヘッダーの「選択」でタイルをチェックし、下部の「N 枚を選択中」「グループに移す」(ポップオーバー: 一覧と「新しいグループ…」)「グループから外す」「選択を解除」。
- **出す**: 節のタイルにホバーで出る「外す」(×。既存の削除ボタンの並び)で、そのグループから外す(確認なし。Asset は消えない)。
- **並べ替え**(2026-09-28 追加): 節の見出し行をドラッグして別の節の見出しの上に落とすと、その位置に移る(落とす先の上半分なら前、下半分なら後ろ。挿入位置の線を出す)。画像のドラッグとは `dataTransfer` の型を分ける。「グループなし」は先頭に固定で動かさない。ドラッグできない環境向けに、見出しの「⋯」に「上へ移動」「下へ移動」も置く。並びはサーバーに保存し、ストックの節、フォームの選択、追加のポップオーバーで同じ順になる。
- **グループの操作**: 「グループなし」の見出し行の右端(他の節で「⋯」がある位置)に「+」のアイコンボタンを置く。文字のラベルは付けず、説明はツールチップと `aria-label`(ADR-0009 の「説明文はツールチップに」の原則)。押すとその見出し行の下にその場で名前の入力(Enter で作成、Escape で取り消し)を出し、作ったグループの節が「グループなし」の直後に空で現れる。パネルのヘッダーには置かない(ストックの見出しの横ではグループの並びから離れて見える)。節の見出しの「⋯」に「名前を変更」(その場で入力)と「削除」(確認ダイアログ。Asset は消えない)。
- **生成時の指定**: 生成フォームの **モデルの直下** に「グループ」の選択(なし / 各グループ)を置く。新規作成は選択肢にせず、選択欄の右に「+」のアイコンボタン(ストックの「グループなし」の見出しの「+」と同じ見た目と操作: ラベルなし、ツールチップと `aria-label`、押すと下に名前の入力、Enter で作成してそのまま選ぶ、Escape で取り消し)。選んだ値はフォームの状態として保持し(他のパラメーターと同じ扱い)、再実行(履歴の「同じ設定で」)でも戻る。加えて **最後に選んだグループを localStorage(`gakei:last-asset-group`)に覚え**、「新規生成」でフォームを新しくしても既定値にする(グループが消えていれば「なし」)。同じ案件で続けて生成する使い方を想定する。送信後に出力がそのグループの節に現れる(2026-09-27 に位置と作成の操作をストックと揃えた)。
- **単体の操作**: ビューア(`/assets/:id`)の詳細に「グループ」の節を足し、所属グループを 1 つのチップで出し、× で外す。「変更」で同じポップオーバーを開いて別のグループへ移す(未所属なら「グループに入れる」)。
- **グループは後から変わる情報で証跡ではない。** 履歴カード、Run 詳細(Generated 詳細)、系列グラフには出さず、ダウンロードする PNG の系列情報(ADR-0014)にも埋め込まない。所属グループが見えるのはストックの節とビューアの詳細だけ(2026-09-28 に、履歴カードと Run 詳細に出していた「生成時に指定したグループ」の表示をやめた)。
- 狭い幅(768px 未満)でも節の開閉、選択モード、下部の操作が使えること(ADR-0009)。ドラッグ&ドロップは PC だけでよい。
- 文言は `frontend/src/i18n/locales/{ja,en}.json` の `stock.groups.*`、`stock.selection.*`、`viewer.groups.*`、サーバー側は `backend/app/locales/{ja,en}.json` の `assetGroups.*`(ADR-0015)。

## Options Considered

### Option A: タグを先に実装し、グループはタグの一種にする
**Pros:** テーブルが 1 組で済む。ADR-0003 のタグ設計をそのまま使える。
**Cons:** 「まとまり」と「性質のラベル」は使い方が違う。グループは数が少なく一覧で選び、タグは多くて検索で使う。#5 の自動タグ付けを入れると、人が作った分類が自動タグに埋もれる。

### Option B: フラットなグループ(採用。所属は 1 つ)
**Pros:** 利用者が欲しい「案件ごとのまとまり」を最短で出せる。データモデルは自動整理を足しても変わらない。
**Cons:** タグを後で足すと整理の軸が 2 つになる。ADR-0001 の「プロジェクト+フラグ+タグ」に沿っているので許容する。

### Option C: フォルダ階層
**Pros:** ファイラーに近く直感的。
**Cons:** ADR-0001 の非ゴール(汎用 DAM)。1 つの Asset を複数の文脈に置けない。

### 見せ方: 絞り込み(フィルター)か、入れもの(コンテナー)か
最初はグループを kind と同じ「絞り込み」として、チップ行と縦リストで作った。しかし画面で見ると kind の絞り込みと見分けがつかず、利用者の頭の中の「この案件の画像をここに入れる」という操作にも合わなかった。ストックそのものをグループの節に分け、ドロップで入れる形に改めた(2026-09-27)。

### 一覧の取り方: `GET /api/asset-groups/{id}/assets` を新設するか、`GET /api/assets?group_id=` にするか
既存の一覧に `group_id` を足す方を採る。ストックパネルの無限スクロール、kind の併用、カーソルの実装をそのまま使え、フロントは引数を 1 つ渡すだけになる。

## Trade-off Analysis

- 名前の重複を許すので、同名のグループが並ぶことがある。並びが `updated_at DESC` なので、直近に触ったものが上に来て見分けはつく。制約が必要になったら足す。
- メンバー行を物理削除するため、「いつ誰が外したか」は残らない。グループは証跡ではないので割り切る。
- `member_count` を一覧のたびに数える。グループ数は少数で、メンバー表には主キーと `asset_id` の索引があるので、SQLite / PostgreSQL のどちらでも問題にならない量。
- マイグレーションは新規テーブルの作成だけで `batch_alter_table` を使わない。#4(PostgreSQL)でそのまま通る。

## Consequences

- ADR-0001 の非ゴール表「汎用 DAM」に、フラットなグループは「プロジェクト」に当たり非ゴールではない旨を追記する。
- Alembic `0012_asset_groups`。`backend/app/domain/models.py` に `AssetGroup` / `AssetGroupMember`、`backend/app/domain/asset_groups.py` に操作、`backend/app/api/asset_groups.py` にルーター。`AssetDetail` の変更で `npm run gen:api` が要る。
- #5(自動タグ・タイトル)は、この ADR のグループに「自動で入れる」規則(種類ごとの分類など)を足す形で設計する。#8(エージェント)はこの API をツールとして使う。
