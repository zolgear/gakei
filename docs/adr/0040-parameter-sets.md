# ADR-0040: パラメーターセット(生成の設定一式を名前を付けて保存し、フォームに読み込む)

**Status:** Proposed
**Date:** 2026-10-10

## Context

SD WebUI(ADR-0038)では、チェックポイント、サンプラー、ステップ数、CFG、サイズ、Clip skip、高解像度補助、Dynamic Prompts など、毎回そろえたい設定が多い。WebUI 自身は、画像に埋め込んだ生成情報から設定を戻せるが(ADR-0038 9章)、Dynamic Prompts を使った画像には展開後の文しか埋め込まれず、`{a|b}` の選択肢(テンプレート)が残らない(Forge で確認)。そのため、画像から設定を戻しても、元のテンプレートは戻らない。

プロンプトセット(ADR-0009 2章)はプロンプトの文字列だけを持ち、「範囲が膨らむリスクは、パラメーターとテンプレートを持たせないことで抑える」と決めている。2026-10-10 にユーザーから、プロンプトセットに近い形で、パラメーターも含めた設定一式を保存したいと要望があった。

GAKEI の Run には実行時のプロンプト(テンプレートのまま)とパラメーターが残り、「同じ設定で開く」で戻せる。ただし、Run を探して開く必要があり、名前を付けて使い回す用途には向かない。

## Decision

### 1. 範囲

- **パラメーターセット** を新しく足す。名前を付けた「生成のフォームの設定一式」で、プロンプトセットとは別のものにする(プロンプトセットの決定は変えない)。
- 持つもの: 名前、プロバイダー、モデル(任意)、パラメーター(フォームの値。ネガティブプロンプトを含む)、プロンプト(任意)。
- 持たないもの: 入力画像とマスク、グループ、Run との結び付き。
- プロバイダーに依らない(OpenAI、ComfyUI、SD WebUI のどれでも保存・読み込みできる)。主な用途は SD WebUI。

### 2. データ(`parameter_set` テーブル)

```
parameter_set(
  id UUID PK,
  name TEXT NOT NULL,
  provider VARCHAR(32) NOT NULL,
  model TEXT NULL,               -- 保存しなければ null(読み込み時は今のモデルのまま)
  prompt TEXT NULL,              -- 保存しなければ null(読み込み時は今のプロンプトのまま)
  params JSON NOT NULL,          -- フォームの値。サーバーだけが書く項目(`comfyui_*`、`sdwebui_*`)は入れない
  created_by_user_id UUID NULL FK app_user.id,
  created_at, updated_at, deleted_at
)
```

- **証跡ではない。** プロンプトセットと同じく、名前と中身を更新でき、削除は論理削除。Run とは外部キーを張らない。Run には実行時の値がこれまでどおり残る(ADR-0003)。
- 見えるのは作った本人だけ(ADR-0025)。

### 3. 保存

- **生成のフォームから:** 「設定を保存」で、今のプロバイダー・モデル・パラメーター・プロンプトを保存する。保存の画面で、名前と、含めるもの(モデル、プロンプト、seed)を選ぶ。既定は、モデルとプロンプトは含め、seed は含めない(使い回すときは毎回変えることが多いため)。既存のセットへの上書きもできる。
- **Run の詳細から:** 「パラメーターセットに保存」で、その Run のプロバイダー・モデル・パラメーター(利用者が指定した値。サーバーが足した項目は除く)・プロンプトを保存する。Dynamic Prompts の Run なら、プロンプトは展開前のテンプレートになる。
- 名前は必須。同じ名前は許す(プロンプトセットと同じ扱い)。

### 4. 読み込み

- 生成のフォームの「設定を読み込む」から一覧(検索つき)で選ぶ。サイドバーのアイコンレールにもパネルを足す(プロンプトセットと並べる)。
- 読み込むと、プロバイダーとモデル(保存していれば)を切り替え、パラメーターを置き換え、プロンプト(保存していれば)を置き換える。入力画像は変えない。今のプロンプトが空でなく、セットにプロンプトがあるときは確かめてから置き換える(ADR-0038 9章の読み込みと同じ確認)。
- **今の環境と合わないとき:** プロバイダーが有効でなければ読み込まない(理由を示す)。モデルが見つからなければ今のモデルのまま注意を出す。今の capabilities に無いパラメーターや範囲外の値は入れず、「読み込めなかった項目」として見せる(ADR-0038 9章の通知と同じ部品)。
- seed を含めたセットは、seed を固定にして入れる。含めていなければ、今の seed の設定のまま。

### 5. 画面とその他

- 狭い幅(768px 未満)でも保存と読み込みができること(ADR-0009)。一覧は全画面のシートで開く。
- グローバル検索(ADR-0009 6章)と MCP(ADR-0023)には、今は載せない。
- 書き出し・取り込み(ADR-0037)の対象にもしない。

## Options Considered

| 案 | 評価 |
|---|---|
| A: パラメーターセットを別に作る(採用) | プロンプトセットの単純さを保てる。プロンプトの使い回しとは別の用途として分けられる。テーブルと画面が増える |
| B: プロンプトセットの項目にパラメーターを持たせる | 画面は増えないが、ADR-0009 の「パラメーターを持たせない」を崩し、文字列を挿入するだけのプロンプトセットの操作(`@` での呼び出しなど)と意味が混ざる |
| C: 作らず、Run の「同じ設定で開く」で済ませる | 追加は無いが、名前が付かず、Run を探す手間が残る |

## Consequences

- SD WebUI で、テンプレートを含む設定一式を名前で呼び出せる。
- ADR-0001 のゴールに「パラメーターセット」を足す(プロンプトセットの行に並べる)。
- 新しいテーブルとマイグレーションが要る。証跡のモデルには触れない。
