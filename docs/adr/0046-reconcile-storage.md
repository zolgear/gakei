# ADR-0046: 画像を手で消した後に DB を合わせるメンテナンスのツール

**Status:** Proposed
**Date:** 2026-10-11

## Context

GAKEI の削除は論理削除だけで、原本のファイルも DB の行も消さない(ADR-0003 2章)。証跡として残すためで、この方針は変えない。

一方で、設定(OpenAI の接続先、認証、埋め込みのモデル、プロンプトセットなど)は残したまま、画像と履歴だけを初期化したいことがある。今はその手段が無い。データディレクトリから画像のファイルを消したり退避したりすると、DB には原本の無い Asset と Run が残る。一覧のサムネイルが壊れ、埋め込みや自動タグの一括実行も、読めない画像で失敗する。

2026-10-11 にユーザーが、画面の機能ではなく、利用者が手で画像を消した・退避した後に実行する同期のスクリプトを用意すると決めた。

## Decision

### 1. 範囲

- コマンドラインのツール `python -m app.tools.reconcile_storage` を作る。画面と API には出さない。
- 使い方: 利用者が、データディレクトリ(またはオブジェクトストレージ)から画像の原本を消すか退避する。その後、サーバーを止めてこのツールを実行する。DB から、原本が無くなった Asset と、それに伴う行を消す。
- 既定は `--dry-run` と同じで、消す件数を示すだけにする。実際に消すのは `--apply` を付けたときだけ。
- ADR-0003 の「追記のみ」「論理削除のみ」はアプリの機能の規則で、このツールはその例外にする。利用者が自分の判断でファイルを消した後に、DB をファイルに合わせる保守の手段であり、画面からは呼べない。

### 2. 消す対象

- **Asset:** 原本(`blob_key`)が保存先に無い Asset。論理削除済みかどうかは問わない。原本の有無は `AssetStore.content_exists` で調べる(ローカル FS、Azure Blob、S3 で同じ)。同じ内容を共有している Asset(ADR-0026)は、キーごとに調べる。
- **Asset に付いた行:** タイトルとタグ、埋め込み、知覚ハッシュ、焦点、グループのメンバー、共有の範囲、そのほか Asset を指す行。共有の範囲が空になった共有リンクも消す。
- **共有リンク:** 範囲が空になるものに加えて、起点の Asset が消えるものも消す(起点は必須の参照のため)。
- **残すもの(Asset を指さなくなっても):** タグの表記、グループ(中身が空になっても)。アップロードのチケットは行を残し、Asset への参照を null にする。ダウンロードのチケットは行を消す。
- **派生画像:** 同じ内容(sha256)を使う Asset が残っていれば消さない。
- **ほかの行からの参照:** 残る Asset の `source_asset_id`(スケッチの下地)と `origin_asset_id`(取り込みの元)が消す Asset を指していたら、null にする。
- **Run:**
  - 出力があった Run で、出力がすべて消えたものは消す(入力が残っていても消す)。
  - `run_input` のうち、消す Asset を指す行は消す。出力が残る Run は残し、系列では、その入力が無い Run として表示される。
  - 出力が一度も無い Run(失敗・中止)は、既定では消さない。`--include-runs-without-outputs` を付けたときだけ消す。全部を初期化するときに使う。入力が残っている Run も含めて、出力が一度も無い Run をすべて消す。
  - Run に付いた行(プロンプトの埋め込み、取り込みの記録など)も一緒に消す。
- **派生画像のファイル:** 消す Asset の派生(thumb / preview。すべての版)を保存先から消す。
- オブジェクトストレージでは、派生を消すのに削除の権限が要る(GAKEI 本体は削除しないので、このツールのときだけ)。
- 次は消さない: 設定、利用者、プロンプトセット、パラメーターセット、ComfyUI のワークフロー、タグの辞書、LLM の接続先、アバター、DB に無い保存先のファイル(件数を示すだけにする)。

### 3. 安全のための決まり

- サーバーを止めてから実行する(worker が行を書き換えるため)。docs と、ツールの説明にそう書く。
- SQLite のときは、`--apply` の前に DB を自動でバックアップする(`gakei.db.bak-<日時>`)。PostgreSQL のときは、バックアップを促す文を出す(`pg_dump` など)。
- `--apply` のときも、消す件数を示してから確認を求める。`--yes` で確認を省ける。
- DB の変更は1つのトランザクションで行う。派生画像のファイルは、DB をコミットした後で消す(ファイルが残っても害は無い)。
- 出力: Asset、Run、その他の行の件数、原本の無かったキーの例、DB に無い保存先のファイルの件数。

### 4. 元に戻したときの埋め込み

この ADR とは別の修正として、論理削除した Asset を元に戻したとき、使うモデルのベクトルが無ければ埋め込みの待ち行列に入れる(ADR-0033 5章の取り込み時の自動実行と同じ条件)。

## Options Considered

| 案 | 評価 |
|---|---|
| A. 画面に「ゴミ箱を空にする」を作る | 証跡を画面から消せるようになる。ADR-0003 の方針と合わない |
| B. 手で画像を消した後に、DB を合わせるツール(採用) | 証跡を消すのは、ファイルを消すという利用者の明示の操作の後だけ。画面の方針は変わらない |
| C. DB をまるごと作り直す | 設定も消える。設定を残したい要望に合わない |

## Consequences

- 利用者は、画像のファイルを消す・退避することで、設定を残したまま画像と履歴を初期化できる。
- 消した Asset と Run は元に戻せない(バックアップから戻すしかない)。
- テーブルを足すときは、Asset や Run を指す行をこのツールでも消すようにする(テストで外部キーを洗い出して確かめる)。

## Action Items

1. `app/tools/reconcile_storage.py`(既定は dry-run、`--apply`、`--yes`、`--include-runs-without-outputs`、SQLite の自動バックアップ)。
2. Asset と Run を指す外部キーを洗い出し、漏れがあればテストで落ちるようにする。
3. SQLite と PostgreSQL、ローカル FS とオブジェクトストレージ(moto)のテスト。ファイルを扱うので `windows` マーカーを付ける。
4. `docs/` に初期化の手順を書き、`CLAUDE.md` のコマンドの一覧に足す。
5. (別の修正)Asset を元に戻したときの埋め込み。
