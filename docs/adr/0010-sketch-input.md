# ADR-0010: スケッチ入力(GPT Image 2.5 の「Sketch」相当)

**Status:** Proposed
**Date:** 2026-09-23

## Context

ChatGPT Images 2.5 の目玉機能「Sketch」は、ChatGPT のチャット内で `@Sketch` と打つとキャンバスが開き、描いたラフを参照にして画像を生成する **ChatGPT アプリの UI 機能** である。API には Sketch 専用のパラメーターも入力種別も無い(公式アナウンスと開発者コミュニティの告知で確認。2026-09-23)。

API 側では、描いた絵を Edits エンドポイントの入力画像として渡すことがそのまま Sketch に相当する。OpenAI のプロンプトガイド(https://developers.openai.com/api/docs/guides/image-prompting)にも "Turn a drawing into a realistic image"(Sketch-to-render)として、ラフを入力画像に渡し、次の趣旨のプロンプトを使う例がある。

> Turn this drawing into a photorealistic image. Preserve the exact layout, proportions, and perspective. Choose realistic materials and lighting consistent with the sketch intent. Do not add new elements or text.

したがって、このアプリでは「描く場所」を用意すれば Sketch を実現できる。マスクエディタ(ADR-0001 ゴール 1、Canvas + Pointer Events)と同じ作りで足りる。

## Decision

- **スケッチエディタ** を入力エリアから開けるようにする。白紙(出力サイズと同じ寸法)に描く、または既存の入力画像の上に描く(上描き)。
- 描いた結果は下地と線を合成した 1 枚の PNG にし、`kind = sketch` の Asset として保存する(`POST /api/assets`)。保存後は通常の入力画像として扱い、Edit API に `image[]` で渡す。証跡は `run_input` の role `image` で足りるので、新しい role は作らない。
- 白紙は入力画像の末尾に追加する。上描きは元の画像と同じ position を差し替える(元の画像はストックに残る)。
- 上描きのスケッチは、下地にした Asset の id を `asset.source_asset_id` に記録する(`POST /api/assets` の任意項目。`kind = sketch` のときだけ受け付ける。追記のみ)。系列グラフは下地 → スケッチ → そのスケッチを入力にした Run と辿る。これが無いと、差し替えで系列が途切れる(2026-09-23 追記。実運用で発覚)。白紙のスケッチは null。
- ツールは最小: ペン(固定 6 色、太さ 3 段)、消しゴム、元に戻す、全消去、線レイヤーの表示オン/オフ(下地と見比べる用)、保存、キャンセル。説明ラベルは置かず、アイコンとツールチップで示す(ADR-0009)。
- OpenAI の推奨プロンプト(上の引用)を、保存時に任意でプロンプト欄へ挿入できる。
- **未使用スケッチの再編集(2026-09-25 追記)。** 入力に置いたスケッチは、まだどの Run の入力にもなっていなければ、線を消せる状態で編集を再開できる。保存しても系列のノードは 1 つのまま増やさない。
  - 保存は `POST /api/assets` の任意項目 `replaces_asset_id`(kind=sketch のときだけ。`source_asset_id` とは同時に指定できない)で行う。置き換え元が未使用(`run_input` に1行も無い)のスケッチなら、新しいスケッチの `source_asset_id` は置き換え元のものを引き継ぎ、置き換え元は同じトランザクションで論理削除する。置き換え元が使用済みなら証跡なので残し、`source_asset_id` を置き換え元にする(従来の上描きと同じ連鎖)。原本は不変のまま(ADR-0004)で、行の UPDATE は `deleted_at` だけ。
  - 系列グラフは、論理削除済みでどの Run の入力にもなっていないスケッチを `sketch_source` の辺では辿らない(置き換えで消えた下書きを出さない)。
  - 線レイヤーはサーバーに保存せず、ブラウザの IndexedDB にスケッチの Asset id をキーとして保持する。元に戻す履歴は保存しない。線レイヤーが無い場合(別のブラウザや消去後)、白紙のスケッチは合成画像を線レイヤーに読み込む(下地が白なので同じ結果になる)。上描きのスケッチは合成画像を下地として描き足す。どちらの場合も保存は置き換えになる。
  - `AssetDetail` に `used_as_input`(その Asset を入力にした Run があるか)を足す。フロントは、エディタを開くときにこの値を取り直して、再開するか従来の上描きにするかを決める。
  - 線レイヤーをキャッシュに保存してよいのは、保存時の「キャンバスの下地」(白紙なら null、既存 Asset なら its id)と、保存レスポンスの Asset の `source_asset_id` が一致するときだけ(2026-09-25 追記のさらに後の修正)。一致しないのは「線レイヤーのキャッシュが無い上描きスケッチ」を焼き込みで再開したときで、下地には合成画像そのもの(元画像ではない)を使うため、保存された線だけを新しい id で保存すると、次に開いたときに元画像 + 今回の線だけになり、それ以前の線が消える。一致しなければキャッシュせず、次回も合成画像を下地として開く(線は焼き込まれるが消えない)。
  - マスクの再編集も同じ仕組み(`replaces_asset_id`、kind=mask)を使う。マスクは `source_asset_id` を持たないので常に null のまま。置き換え元が未使用なら論理削除し、使用済みなら残す(スケッチのように連鎖はしない)。
- Asset の `kind` 列は文字列なので、`kind` の追加にマイグレーションは不要。ストックのフィルタに「スケッチ」を足す。(2026-10-04 追記: 既定ではスケッチとマスクをストックに出さない。出すかは「表示」の設定で選ぶ。ADR-0035)`source_asset_id` 列の追加にはマイグレーションが要る(null 可の列追加のみ)。

### 作らないもの

図形ツール、テキスト入力、レイヤー、色の自由指定、画像の移動・変形、Run に使った後のスケッチの再編集(使用済みのスケッチは証跡なので、描き直すときは上描きで新しいスケッチを作る。未使用のスケッチは上の追記のとおり再開できる)。

## Options Considered

| 案 | 評価 |
|---|---|
| A: スケッチエディタを作り、結果を入力画像として渡す(採用) | API 側に専用機能が無い以上これが Sketch の実体。マスクエディタの作りを流用でき、証跡のモデルに変更が要らない |
| B: 外部で描いた画像をアップロードしてもらう | 既に可能(アップロード・ドロップ・貼り付け)。ただし「その場で描いて試す」流れが切れる |
| C: 汎用の画像編集(レイヤー、図形、テキスト) | ADR-0001 の非ゴール。範囲が膨らむ |

## Consequences

- ADR-0001 の非ゴール「高機能な画像編集」の但し書きを「マスク用とスケッチ用の簡易ブラシのみ作る」に改める。
- `AssetKind` に `sketch` が増える。本線(Azure)でも同じ。
- スケッチの入力トークンは他の入力画像と同じ扱い(ADR-0009 の参考価格に含まれる)。
