# ADR-0032: LLM の接続先を、自動タイトル・タグから独立させる

**Status:** Proposed
**Date:** 2026-10-01

2026-10-01 に、ユーザーが次のように指示した。

- 自動タイトル・タグの中にある LLM の接続先の設定を、単体の設定として出す。
- 理由: プロンプトのアシストなど、これから作る機能でも LLM の接続が基盤になるため。

同日、次の2点もユーザーが決めた。

- 独立させる範囲: 画面と API を独立させる。保存先のキー名は変えない。
- ページの名前: 「LLM の接続先」にする。

## Context

LLM・VLM の接続先(名前、Base URL、キー、API 形式)は、ADR-0024 8章で自動タイトル・タグの一部として作った。そのため、作りが自動タイトル・タグに結び付いている。

| 層 | 今の場所 |
|---|---|
| API | `/api/settings/annotation/connections*` |
| ドメイン | `domain/annotation_settings.py` |
| 保存先(一覧) | `app_setting` の `annotation.connections` |
| 保存先(キー) | `secrets.json` の `annotation_connection_key.<id>` |
| 画面 | 設定の「自動タイトル・タグ」のページの一節 |

このままでは、LLM を使う機能を足すたびに自動タイトル・タグの設定を経由することになる。また、どの機能の接続先なのかが画面から分かりにくい。

## Decision

### 1. 画面

- 管理者設定に「LLM の接続先」のページ(`/settings/llm-connections`)を足す。置き場所は「OpenAI」の次。
- ページの種類は ADR-0031 2章の「接続」にする。接続先はカードで並べ、追加・編集・キーの登録と削除はダイアログで行う。
- 説明文に、VLM(画像を読むモデル)もこの接続先を使うことを書く。
- 組み込みの接続先「OpenAI の設定」は今までどおり。ADR-0017 のキーと Base URL を使い、API 形式だけ変えられ、削除できない。
- カードには、その接続先をどの機能が使っているかを出す。今は「自動タイトル・タグ」だけ。
- 使われている接続先は削除できない。今までと同じ。
- 自動タイトル・タグのページからは、接続先の一節を外す。使い方の表で接続先を選ぶ欄は残し、選択肢は LLM の接続先の一覧から取る。
  - 接続先が足りないときのために、「LLM の接続先」のページへのリンクを置く。
- 1時間の上限は、今までどおり自動タイトル・タグの設定にする。数えるのは接続先ごと(ADR-0024 8章)。上限は機能ごとの決まりなので、接続先には持たせない。

### 2. API

- 接続先の API を `/api/settings/llm-connections` に移す。

  | メソッドとパス | 内容 |
  |---|---|
  | `GET` | 一覧。組み込みを含み、キーの有無と、使っている機能を返す |
  | `POST` | 追加 |
  | `PATCH /{id}` | 変更 |
  | `DELETE /{id}` | 削除 |
  | `PUT /{id}/api-key` | キーの登録 |
  | `DELETE /{id}/api-key` | キーの削除 |

- 古い `/api/settings/annotation/connections*` は消す。使っているのは GAKEI の画面だけで、MCP のツールには無いため。
- 権限は今と同じにする。更新系は管理者だけで、参照は今の `GET /api/settings/annotation` に合わせる。
- キーは一部も返さない。設定済みかどうかだけを返す(ADR-0019 5章)。

### 3. ドメイン

- 接続先の型、検証、一覧の読み書き、キーの読み書きは `domain/llm_connections.py` に移す。
- 「使っている機能」は、使う側(今は自動タイトル・タグ)が答える関数で集める。LLM の接続先の側から特定の機能を知らないようにする。
- 推定のエンジンは、接続先を `domain/llm_connections.py` から引く。

### 4. 保存先は変えない

- `app_setting` の `annotation.connections` と `annotation.openai_api_style`、`secrets.json` の `annotation_connection_key.<id>` は、名前を変えずにそのまま使う。
- 名前を変えると、実データの移行が要る。移行に失敗すると、キーを失うおそれがある。名前は内部のもので、利用者には見えない。
- 名前が「annotation」のままである理由は、`domain/llm_connections.py` の冒頭に書く。

## Options Considered

| 案 | 評価 |
|---|---|
| A. 画面と API を独立させ、保存先の名前は残す(採用) | 次の機能がそのまま使える。実データの移行が無い |
| B. 画面だけ独立させる | 変更は小さい。ただし、次の機能を作るときに結局切り出しが要る |
| C. 保存先の名前も `llm.*` に改める | 名前は揃う。ただし、起動時に設定とキーのファイルを移す処理が要る |

## Consequences

- 自動タイトル・タグのページが短くなる。
- LLM を使う機能を足すときは、`domain/llm_connections.py` の接続先を選ばせ、「使っている機能」に答える関数を足す。
- ADR-0024 8章の「接続先(一覧)」の中身は変わらない。置き場所が、この ADR に移る。

## Action Items

1. バックエンド: `domain/llm_connections.py`、`/api/settings/llm-connections`、古い API の削除、テスト。
2. フロント: 「LLM の接続先」のページ、自動タイトル・タグのページから接続先の一節を外す、`npm run gen:api`。
3. ADR-0024 8章と ADR-0031 1章の表に追記する。`docs/auto-tags.md` を更新する。
