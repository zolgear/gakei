# ADR-0049: 画像のレーティング(WD Tagger による判定と、一覧でのマスク)

**Status:** Proposed
**Date:** 2026-10-14

2026-10-14 に、ユーザーが次のように指示した。

- タガーの情報を使って、画像のレーティングを判定する。
- 段階は グリーン、R、X、XX、XXX の5つ。Asset に判定を表示し、詳しいパラメーターは展開すれば確かめられるようにする。
- R 以上は、履歴とアセットの上でぼかしてマスクし、マスクの上にレーティングを出す。
- マスクするレーティングはユーザー設定で選べるようにする。

同日、ユーザーが次の4点を決めた。

- 段階は性表現の強さで分ける(暴力・流血は対象にしない)。WD の rating を基準にし、一般タグで段階を引き上げる。
- 判定は人が変えられる。人が選んだ段階は再判定で上書きしない。
- まだ判定していない画像はマスクしない。設定で「未判定もマスクする」を選べる。
- マスクする段階の設定はサーバーに、ユーザーごとに保存する。

同日、ユーザーがこの ADR を承認した。

2026-10-15 に、ユーザーが次のように指示し、5章を改めた(マップのマスクと、マスクに戻す操作)。

- マスクの設定が有効なら、マップもマスクする。マップでは1枚ずつではなく、マップ全体でマスクを外すか掛けるかを切り替える(目のアイコンなど)。
- 履歴でも、マスクを外したあとに、マスクに戻すアイコンを置く。
- 情報欄のレーティングの節を、タグの下へ移す(4章)。

同日、ユーザーがこの改訂を承認した。

## Context

- WD Tagger v3(ADR-0024 3章)は、一般タグとキャラクタータグのほかに rating の4つのラベル(`general`、`sensitive`、`questionable`、`explicit`)の確率を出す。今は rating を捨て、一般タグもしきい値(既定 0.35)未満は捨てている。
- 判定に必要な値は、タグの推定と同じ1回の推論で得られる。追加のモデルや外部 API は要らない。
- ADR-0003 の `asset_mark.rating` は採用の評価(星)であり、これとは別物。名前が衝突しないように、この ADR では `content_rating` と呼ぶ。
- 表示の設定は、今はすべてブラウザ(localStorage)にある。サーバーにユーザーごとの設定を置く場所はまだない。個人モード(`AUTH_MODE=none`)では `app_user` の行が無い(ADR-0019)。
- サムネイルは各画面がそれぞれ `<img src={assetUrl(id, 'thumb')}>` で描いていて、共通の部品が無い。

## Decision

### 1. 段階と判定の規則

段階は5つで、識別子は `g`、`r`、`x`、`xx`、`xxx`。表示は「グリーン」「R」「X」「XX」「XXX」とする。

**基準の段階:** rating の4つの確率を、弱い順に `general`→`g`、`sensitive`→`r`、`questionable`→`x`、`explicit`→`xx` と並べる。累積の確率が 0.5 以上になる最も強い段階を選ぶ(中央値)。最大の確率の段階を選ぶ方法よりも、確率が割れたときに強い側に倒れやすい。

例: general 0.45、sensitive 0.40、questionable 0.10、explicit 0.05 → sensitive 以上の累積は 0.55 → `r`。

**一般タグによる引き上げ:** 次のタグの確率が、それぞれのしきい値以上なら、段階を少なくともその段階まで上げる。下げることはない。判定に使う確率は、タグのしきい値(ADR-0024)で捨てる前の値を使う。

| 引き上げ先 | タグ(WD の表記) | しきい値 |
|---|---|---|
| `r` | swimsuit、bikini、underwear、panties、bra、lingerie、cleavage | 0.6 |
| `x` | nipples、topless、bottomless、nude、completely_nude | 0.5 |
| `xx` | pussy、penis、testicles、anus、clitoris、erection | 0.5 |
| `xxx` | sex、vaginal、anal、oral、fellatio、cunnilingus、paizuri、handjob、footjob、masturbation、group_sex、rape、cum、ejaculation、cum_in_pussy、sex_toy、dildo、vibrator | 0.5。ただし、それまでの段階が `xx` 以上のときだけ |

- `xxx` は、`xx`(性器や露骨な表現)に加えて、性行為を示すタグがあるときにする。性行為のタグだけでは `xxx` にしない(誤検出で一気に最上段になるのを避ける)。
- 規則(表と累積のしきい値)はコード(`domain/content_rating.py`)に置き、版 `RULES_VERSION` を持たせる。表を変えたら版を上げる。設定画面では変えられない(調整の手段を増やさない。迷ったら作らない)。
- 版を上げても、判定済みの画像は自動では判定し直さない。管理者設定の一括判定(4章)の対象を「古い版の判定」にも広げられるようにする。

### 2. 保存

新しい表 `asset_content_rating` を作る。証跡ではないので更新してよい(ADR-0024 のタイトル・タグと同じ扱い)。

| 列 | 内容 |
|---|---|
| `asset_id` | 主キー。Asset への外部キー |
| `level` | 表示に使う段階。人が選んでいれば人の段階、なければ自動の段階。未判定なら NULL |
| `source` | `auto` / `user` |
| `auto_level` | 自動判定の段階(人が上書きしても残す) |
| `status` | `queued` / `running` / `succeeded` / `failed`(NULL は未実行)。待ち行列を兼ねる |
| `error` | 失敗の理由 |
| `model` | 判定に使った WD のモデル |
| `rules_version` | 判定の規則の版 |
| `scores` | rating の4つの確率(JSON) |
| `signals` | 引き上げの表に載っているタグのうち、確率が 0.2 以上のものと、その確率(JSON)。しきい値を超えて段階を上げたものに印を付ける |
| `judged_at`、`updated_at` | 時刻 |

- 人が段階を選ぶと `source = user`、`level` を人の段階にする。「自動に戻す」で `source = auto`、`level = auto_level` に戻す。
- 再判定は `auto_level` 以下の列だけを書き換え、`source = user` なら `level` を変えない。

### 3. 判定の実行

- 判定は WD Tagger のモデルで行い、外部には何も送らない。
- 管理者設定「自動タイトル・タグ」に「レーティングを判定する」(`content_rating_enabled`、既定オフ)を足す。WD のモデルをダウンロード済みであることが条件。ONNX のタグ付け(`onnx_enabled`)とは独立にオンにできる(タグは要らずレーティングだけ欲しい場合)。使うモデルは `onnx_model` と同じ。
- 自動タイトル・タグの推定で ONNX が走るときは、同じ推論の結果からレーティングも書く(推論を2回しない)。
- それ以外のときは `asset_content_rating.status = 'queued'` の行を、今の annotator の worker が拾い、WD だけで判定する。ADR-0024 4章の推定と同じく、Run ではない。
- **取り込み時:** レーティングがオンなら、生成の出力・アップロード・スケッチの取り込みのたびに判定を待ち行列に入れる(タイトル・タグの `auto_on_ingest` とは別に、常に)。マスクが役に立つのは、判定が取り込みの直後に済んでいるときだけだから。マスク(マスク画像)は対象外。
- **一括判定:** 管理者設定から、未判定(と、古い版の自動判定)の画像をまとめて待ち行列に入れる。実行前に件数を示す。
- **1枚ずつの再判定:** Asset の詳細から実行する。
- 失敗したら `failed` と理由を残し、自動では再試行しない(ADR-0024 4章と同じ)。

### 4. 画面: 判定の表示

- **ビューアの情報欄:** 「レーティング」の節を、タグの節の下に置く(2026-10-15 にタイトルの下から移した)。
  - 段階のバッジ(グリーンも出す)と、自動か人か。
  - 段階を選ぶ操作と「自動に戻す」。
  - 展開すると次を出す: rating の4つの確率、引き上げのタグと確率(段階を上げたものに印)、モデル、規則の版、判定の時刻、自動の段階(人が上書きしているとき)。
  - 再判定のボタンと、待ち・失敗の状態。
- **カード(履歴、ストック、検索の結果など):** 判定済みなら小さなバッジで段階を出す。グリーンは目立たない色にする。
- 未判定の画像にはバッジを出さない。レーティングがオフ(管理者設定)なら、情報欄の節も出さない(ADR-0024 と同じく、使えない機能は隠す)。

### 5. 画面: マスク

- **対象:** ユーザー設定で選んだ段階の画像。既定は `r`、`x`、`xx`、`xxx`(R 以上)。「未判定もマスクする」は既定オフ。
- **見た目:** サムネイルを CSS でぼかし(`filter: blur()` と、ぼかしの縁のはみ出しを切る `overflow: hidden`)、中央に段階のバッジを重ねる。
- **一時的に見る:** マスクをクリック(タップ)すると、その画像だけマスクを外す。ページを読み直すと戻る(サーバーにもブラウザにも覚えない)。ビューアの大きな画像も同じで、マスクの上に「表示する」のボタンを置く。
- **マスクに戻す(2026-10-15):** マスクを外した画像(設定ではマスクする段階のもの)には、隅に目を閉じたアイコンだけを出し(文言と段階は出さない。同日のユーザーの指示)、押すとその画像をマスクに戻す。隅のバッジの位置に置き換えて出すので、ほかの印やボタンとは重ならない。ビューアと比較の大きな画像にも、右下に同じアイコンのボタンを置く。
- **出す場所:** 共通の部品(`AssetThumb`)を作り、次の場所で使う。
  - 履歴のカードと行、作業場の結果
  - ストックのタイルと画像の選択(ピッカー)
  - ビューアの大きな画像、出力のサムネイル、似た画像
  - 検索の結果、重複の候補、系列のノード、比較
  - アシスタントの画像カード(ADR-0048)
  - マップ(ADR-0033、0047。2026-10-15 に追加。下の「マップ」を参照)
- **マップ(2026-10-15):**
  - マップの元データ(`GET /api/embeddings/graph` のノード)に `content_rating` を加える。
  - マップは canvas に画像を描くので、マスクする画像はぼかした画像を描く(サムネイルを小さく縮めてから引き伸ばして作り、ブラウザのメモリにだけ置く)。タイルが十分大きいときは、段階のバッジも重ねる。
  - 1枚ずつは外さない。ノードのクリックは今までどおり選択(プレビュー)で、マスクを外す操作にしない。
  - ツールバーに目のアイコンのボタンを置き、マップ全体でマスクを外す・掛けるを切り替える。マスクする画像がマップに無ければ出さない。切り替えはメモリにだけ置き、ページを読み直すとマスクに戻る(1枚ずつの「一時的に見る」と同じ)。マップ全体で外しても、履歴などの1枚ずつの状態は変えない。
  - プレビューの大きな画像も、マップでマスクしているあいだはぼかし、段階を出す。
- **出さない場所:**
  - 共有リンクの公開ページ(ADR-0029): 共有するのは持ち主が選んだ画像で、見る人はログインしていない。
- **これは表示のマスクで、アクセスの制限ではない。** ぼかす前の画像もブラウザには届いている。サーバー側でぼかした派生画像を作ることはしない(派生の版、ADR-0036 を増やさない)。docs に書く。
- MCP とアシスタントが AI に渡す画像はマスクしない(表示ではないため)。代わりに、Asset の情報に `content_rating` を加える。

### 6. ユーザーごとの設定(サーバー)

新しい表 `user_preference` を作る。

| 列 | 内容 |
|---|---|
| `owner` | 認証モードでは `app_user.id` の文字列、個人モードでは `local` |
| `key` | 設定の名前(例 `content_rating.mask_levels`) |
| `value` | JSON |
| `updated_at` | 時刻 |

- 主キーは (`owner`, `key`)。個人モードでは `app_user` の行が無いので、外部キーにせず文字列で持つ。
- API は `GET /api/users/me/preferences` と `PATCH /api/users/me/preferences`。知らないキーと形の合わない値は 422。
- 今回のキーは `content_rating.mask_levels`(段階の配列、既定 `["r","x","xx","xxx"]`)と `content_rating.mask_unrated`(真偽、既定 false)の2つ。
- ユーザー設定の「表示」に「レーティングのマスク」の節を置く。ほかの表示の設定と同じく、保存ボタンを置かずに変えたらすぐ保存する。表示のページの「ブラウザに保存した設定を消す」の対象には含めない(サーバーの設定なので)。
- 既にある表示の設定(localStorage)は移さない。

### 7. API

- `AssetSummary`、`RunOutputRef`、および `AssetSummary` を継ぐ一覧の応答に `content_rating`(段階、未判定は null)を加える。一覧は1回の問い合わせでまとめて引く(`bulk_titles` と同じ形)。
- `AssetDetail` に `content_rating_detail`(2章の列と状態)を加える。
- `PUT /api/assets/{id}/content-rating` で人が段階を選ぶ(`{"level": "x"}`。`null` で自動に戻す)。`POST /api/assets/{id}/content-rating/judge` で再判定。
- `POST /api/settings/annotation/content-rating/backfill`(管理者)で一括判定。件数を返す。
- 見せる範囲は今の Asset と同じ(ADR-0025。本人のものだけ)。
- MCP の `get_asset`・`search_assets` とアシスタントのツールの結果に `content_rating` を加える。MCP からの書き込みは提供しない。

## Options Considered

- **WD の4段階をそのまま使う:** 実装は最も簡単だが、ユーザーの指示は5段階。explicit の中で性行為の有無を分けたいので、一般タグを併用する。
- **最大の確率で基準の段階を決める:** 確率が割れたとき(general 0.45、sensitive 0.40 など)に弱い側に倒れる。マスクの用途では強い側に倒れる方がよいので、累積(中央値)にした。
- **サーバーでぼかした派生画像を作る:** 元の画像をブラウザに渡さずに済むが、派生の種類と版が増え、マスクの設定を変えるたびに URL が変わる。アクセス制限が目的ではないので採らない。
- **設定を localStorage に置く:** 既存の表示の設定と揃うが、端末ごとに設定し直すことになる。ユーザーの選択でサーバーにした。
- **規則を設定画面で変えられるようにする:** 調整の手段は増えるが、画面と検証が重くなる。まずはコードの版で管理する。

## Trade-off Analysis

- 判定は WD Tagger の精度に依存する。WD はイラスト向けで写真には向かない(ADR-0024)。人が直せることで補う。
- マスクは表示のためのもので、ブラウザの開発者ツールや直接の URL では元の画像が見える。
- 取り込みのたびに判定するので、レーティングをオンにすると CPU の負荷が増える(WD の推論1回分。Raspberry Pi 5 の vit で数秒)。
- 判定が済むまでの数秒は未判定として扱われ、既定ではマスクされない。履歴は SSE と再取得で判定後の段階に更新する。

## Consequences

- 新しい表が2つ(`asset_content_rating`、`user_preference`)。マイグレーション 0034。
- サムネイルを描く場所が共通の部品に寄る。
- `user_preference` は、これからのユーザーごとの設定にも使える。
