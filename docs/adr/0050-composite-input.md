# ADR-0050: 入力画像の配置(複数の画像を移動・回転・拡大縮小して1枚の入力にする)

**Status:** Proposed
**Date:** 2026-10-15

2026-10-15 に、ユーザーが次のように指示した。

- 入力画像を回転・拡大縮小できる編集画面を作る。複数の Asset を配置して、1つのソースにできる。
- 用途は、キャラクターの立ち絵やオブジェクトを、ただの参照画像として渡すのではなく、おおよその座標と組み合わせを仮組みしてから、Edit で結合・仕上げをさせること。
- 正面の絵を好みの角度に変えて置き、そのとおりに生成させる、といった使い方をする。

## Context

- 今の Edit は、複数の入力画像を「参照」として渡せるが、どこに・どの大きさで・どの向きで置くかはプロンプトの言葉でしか伝えられない。仮組みの画像を1枚渡せば、構図をそのまま伝えられる。
- スケッチ(ADR-0010)は1枚の下地に線を描くだけで、画像の移動・変形は「作らないもの」にしている。ADR-0001 は「高機能な画像編集(レイヤーなど)」を非ゴールにしている。
- 上描きのスケッチは `asset.source_asset_id` で下地の Asset を1つだけ指す(ADR-0003 6項)。配置の結果は素材が複数なので、この列では表せない。

## Decision

### 1. 範囲(できること)

画面の名前は「配置」(英語は Arrange)。スケッチと並ぶ、入力画像を作る道具の1つにする。

- **キャンバス:** 大きさを選ぶ(入力の1枚目の大きさ、または生成のフォームで選んでいるサイズを既定にし、ほかの大きさも選べる)。背景は白か透明。
- **素材(レイヤー)を足す:** Edit の入力にある画像、ストックから選んだ画像。最大 16 枚(OpenAI の入力の上限と同じ)。
- **素材ごとの操作:**
  - 移動(ドラッグ)
  - 拡大縮小(四隅のハンドル。縦横比は保つ)
  - 回転(回転のハンドル。Shift を押すと 15° 刻み)
  - 左右反転・上下反転
  - 重ね順(前面へ・背面へ)、複製、削除
  - 選んだ素材の位置・倍率・角度は数値でも入力できる
- **全体:** 元に戻す・やり直す、キャンバスに合わせる、中央に寄せる。
- **狭い幅(ADR-0009):** タッチでの移動、2本指での拡大縮小と回転、ハンドルの操作ができること。
- **回転は画面の中の回転(2D)だけ。** 正面の絵を横向きにするような見る角度の変更(3D)はしない。向きを変えて置いた仮組みを手がかりに、角度の変更や結合は Edit のプロンプトで指示する。docs にプロンプトの例を書く。

### 2. 作らないもの

素材の切り抜き(トリミング)、背景の除去、遠近の変形(四隅を自由に動かす)、透明度・フィルター、文字・図形、描画(描き足しは、配置の結果に上描きのスケッチで行う)。必要になったら、この ADR を改めてから足す。

### 3. 保存

- 書き出しはブラウザで行う(スケッチと同じ)。canvas に素材を描き、1枚の PNG にして `POST /api/assets` に `kind = composite` で送る。同じ要求で、配置の記録(レシピ)を JSON で送る。
- **レシピ:** キャンバスの大きさと背景、素材ごとの Asset id・中心の座標・倍率・角度・反転・重ね順、作り方の版。サーバーは画像を描き直さない(描くのはブラウザだけ。レシピは「何をどう置いたか」の記録で、画素の証明ではない)。
- 新しい表を2つ作る。どちらも追記のみ(ADR-0003 1項)。
  - `asset_composition`: `asset_id`(主キー)、`recipe`(JSON)、`created_at`。
  - `asset_composition_source`: `asset_id`、`position`、`source_asset_id`。系列をたどるための索引。`position` は重ね順ではなく、素材を足した順(0 が主たる素材。4章)。
- **サーバーの検証:** 素材の Asset が見える範囲にあり(ADR-0025。本人のもの)、論理削除されておらず、`mask` でないこと。素材は 1〜16 枚。画像の形式と大きさの上限はスケッチと同じ。
- **作り直し:** 配置の結果を開くと、レシピから素材を読み込んで続きを編集できる。保存は新しい Asset になる。元の配置がまだどの Run の入力にもなっていなければ、スケッチと同じく置き換える(元を論理削除する。`replaces_asset_id`)。使用済みなら残す(証跡)。素材が論理削除されていて読めないときは、その素材を抜いて開き、そのことを示す。

### 4. 系列(ADR-0003 に 10 項を足す)

- 配置の結果は、素材の Asset を `asset_composition_source` で指す。系列グラフには、素材から配置の結果へ向かう辺(`composite_source`)を描く。Run は挟まない。
- **主たる素材:** 素材を足した順の最初(`position = 0`)。系列の木(ADR-0003 5項)はこの辺だけを主たる親として辿り、ほかの素材は Edit の参照の入力と同じく「参照」として描く。編集画面で「主にする」を選べば入れ替えられる(保存前だけ)。
- 系列の ZIP(ADR-0037)、共有リンク(ADR-0029)、ダウンロードの PNG への埋め込み(ADR-0014)、Mermaid の書き出しにも、上描きのスケッチの `sketch_source` と同じ扱いで辺を入れる。

### 5. 生成のフォームとのつなぎ

- 入力の行(スケッチ・マスクのボタンの並び)に「配置」を置く。開くと、そのときの入力画像をすべて素材として並べた状態から始める(重ならないよう、キャンバスに収めて横に並べる)。
- 保存すると、配置の結果を入力の1枚目(主たる入力)に置く。素材にした元の画像は、既定では参照として入力に残す(配置で縮めた画像だけでは細部が伝わらないため)。保存のときに「元の画像を入力から外す」を選べる。入力が1枚しか取れないプロバイダー(SD WebUI、ComfyUI)では、配置の結果だけにする。
- ストックとビューアの画像からも「配置で開く」を選べる(その画像を素材にして始め、保存後は生成のフォームへ移る)。

### 6. ほかの機能での扱い

- **ストック(ADR-0035):** スケッチ・マスクと同じく、既定では出さない。設定「スケッチとマスクをストックに出す」の対象に加え、文言を「スケッチ・マスク・配置」に改める。
- **レーティング(ADR-0049):** 取り込みのたびに判定する(スケッチと同じ)。素材のレーティングは引き継がない(合わせた結果で判定する)。
- **埋め込み(ADR-0033)、タイトル・タグ(ADR-0024):** スケッチと同じ扱いにする。
- **MCP とアシスタント:** 配置を作るツールは作らない(画像を描けないため)。Asset の情報には `kind = composite` が出る。
- **ADR-0001:** 非ゴール「高機能な画像編集」の但し書きを「マスク用とスケッチ用の簡易ブラシと、入力画像の配置(移動・回転・拡大縮小・反転)のみ作る」に改める。ADR-0010 の「作らないもの」の「画像の移動・変形」に、この ADR への注記を足す。

## Options Considered

| 案 | 判断 |
|---|---|
| A: ブラウザで描いて PNG を送り、レシピも記録する | 採用。スケッチと同じ作り。サーバーに描画の処理を増やさない |
| B: レシピだけ送り、サーバー(Pillow)で描く | 再現性は高いが、ブラウザの見た目とサーバーの結果を一致させる処理が二重になる。プレビューのためにブラウザでも描くので、結局2回作ることになる |
| C: スケッチの編集画面にレイヤーと変形を足す | スケッチは下地が1枚の前提で、線の保存(IndexedDB)とも絡む。画面と記録を分けたほうが単純 |
| D: 素材を `source_asset_id` で1つだけ指す | 素材が複数の場合を表せず、系列から素材が消える |
| E: 遠近の変形(3D 風の回転) | 見る角度の変更は画像生成モデルの方が得意。仮組みは 2D で足りる。作らない |

## Trade-off Analysis

- 仮組みを1枚にすると、構図ははっきり伝わるが、縮めた素材の細部は粗くなる。元の画像を参照として残す既定で補う(入力の枚数と費用は増える)。
- レシピは記録するが、画素の正本は保存した PNG。レシピから同じ画像が作れることは保証しない(フォントやブラウザの描画の差は無いが、作り方の版で変わりうる)。

## Consequences

- Asset の種類が1つ増える(`composite`。列は文字列なのでマイグレーションは表の追加だけ)。種類を列挙している場所(スキーマ、ストックの絞り込み、系列のノード、取り込みと書き出し)を直す。
- 素材の画像が論理削除されても、配置の結果とレシピは残る(証跡)。
- 系列に「Run を挟まない、親が複数の辺」が加わる。
