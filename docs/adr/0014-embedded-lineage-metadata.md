# ADR-0014: ダウンロードする PNG に系列情報を埋め込む

**Status:** Proposed(2026-09-24 に main へ取り込み。同日、6章で祖先をすべて埋め込むよう改訂)
**Date:** 2026-09-24

## Context

系列(リネージ)は DB だけにある(ADR-0003)。画像をダウンロードした時点で DB とのつながりが切れ、同じ画像を再びアップロードしても、元の Asset とは無関係な `upload` Asset になる(`ingest` は同じ sha256 でも毎回新しい行を作る)。ダウンロードした画像をチャットやファイル共有で受け渡し、あとで GAKEI に戻して Edit の入力にする、という使い方では系列が途切れる。

ComfyUI は出力 PNG のテキストチャンクにワークフローを埋め込み、画像からフローを復元できる。GAKEI の画像にも最小限の系列情報を持たせれば、ダウンロード後でも元の Asset に戻れ、DB を持たない別の GAKEI でもレシピ(設定)を復元できる。

制約:

- 原本は不変で、上書きも変換もしない(ADR-0004)。
- ADR-0001 は「C2PA 署名、IPTC 埋め込み」を非ゴール(Phase 3)にしている。証跡の正本は DB の記録である。
- 来歴の列は追記のみ(ADR-0003)。

この ADR は ADR-0001、ADR-0003、ADR-0004 に追記する。

## Decision

### 1. 埋め込む場所

- **保存している原本には書き込まない。** `GET /api/assets/{id}/content?variant=original&download=1` の応答にだけ埋め込む。画面表示用の `original`、`thumb`、`preview` は変えない。
- 対象は **PNG だけ**にする。JPEG と WebP は、従来どおりメタ情報なしでダウンロードする。
- ETag は `"{sha256}-original-gakei1"` として、原本の応答と区別する。

### 2. 形式

- PNG の **iTXt チャンク**を使う。キーワードは `gakei`、非圧縮、本文は UTF-8 の JSON。日本語のプロンプトを入れるので、Latin-1 の tEXt は使わない。
- 位置は IEND の直前。すでにある `gakei` チャンクは取り除いてから入れる。ComfyUI の `prompt` や `workflow` など、他のチャンクには触れない。
- Pillow で再エンコードせず、チャンク単位のバイト操作で行う。`gakei` チャンクを取り除けば、原本と同じバイト列に戻る。

### 3. 内容(`gakei.lineage/1`)

```json
{
  "schema": "gakei.lineage/1",
  "instance": "<GAKEI インスタンスの UUID>",
  "asset": {"id": "…", "sha256": "…", "kind": "generated", "output_index": 0, "created_at": "…"},
  "run": {"id": "…", "provider": "openai", "model": "…", "operation": "edit",
          "prompt": "…", "params": {"…": "…"}, "finished_at": "…"},
  "inputs": [{"asset_id": "…", "sha256": "…", "role": "image", "position": 0}],
  "source_asset": {"id": "…", "sha256": "…"}
}
```

- ID とレシピ(provider、model、operation、prompt、params)を入れる。`run` と `inputs` は `generated` のとき、`source_asset` は `sketch` のときだけ入れる。
- `params` は `run.params` から `comfyui_prompt` と `comfyui_outputs` を除いたもの。`comfyui_prompt` はグラフ全体で大きく、ComfyUI 自身が `prompt` チャンクに入れている。
- 追記のみのデータだけから作る。同じ Asset からは毎回同じバイト列ができる(ダウンロード日時などは入れない)。
- インスタンス ID は `app_setting` のキー `instance.id` に持ち、最初に必要になったときに生成する。`DATA_DIR` ごとに1つになる。

### 4. アップロード時の照合

`kind = upload` のとき、PNG の `gakei` チャンクを読む。

1. チャンクが無いか、壊れているか、スキーマが違うとき: 従来どおり新しい Asset を作る。
2. `instance` がこの GAKEI で、`asset.id` の Asset が存在し、削除されておらず、内容が一致するとき: **新しい行を作らず、既存の Asset を返す。** Edit の入力にすれば、系列は元の Asset からそのまま続く。
   - 内容の一致は、`gakei` チャンクを除いたバイト列の sha256 で比べ、一致しなければデコードした画素で比べる。
3. それ以外(他のインスタンス、外部で加工された、削除済み): 新しい `upload` Asset を作り、読み取った内容を `asset.origin_meta` に記録する。同じインスタンスの Asset を指していれば、`asset.origin_asset_id` も記録する。

チャンクには署名がないので、誰でも書き換えられる。照合を通らなかった内容は**自己申告**として扱い、`run_input` などの証跡に事実として書き込まない。画面では「未検証」と表示する。

### 5. 画面

- アップロードが既存の Asset に一致したときは、その旨を表示する。
- `origin_meta` を持つ Asset のインスペクターには、埋め込まれていた model、prompt、生成元(このインスタンスか、他か)を「未検証」として表示する。「この設定をフォームに読み込む」で、prompt と params をフォームに戻せる。入力画像は埋め込んでいないので戻らない。
- 系列グラフでは、`origin_asset_id` から新しい Asset への辺を破線で描く(辺の種類は `origin`)。

### 6. 祖先をすべて埋め込む(`gakei.lineage/2`。2026-09-24 追記)

`gakei.lineage/1` は、その画像を生んだ Run と入力の ID しか持たなかった。他の環境で取り込むと Asset のノードしか復元されず、「どのモデルで、どの親から作ったか」を2世代以上さかのぼれなかった。トレーサビリティの役割を果たすため、祖先をすべて埋め込む。

- 内容は系列グラフの形にする。

  ```json
  {
    "schema": "gakei.lineage/2",
    "instance": "<書き出した GAKEI>",
    "root": "<この画像の asset id>",
    "nodes": [
      {"type": "asset", "id": "…", "instance": "…", "sha256": "…", "kind": "generated",
       "mime": "image/png", "width": 1024, "height": 1024, "created_at": "…"},
      {"type": "run", "id": "…", "instance": "…", "provider": "openai", "model": "…",
       "operation": "edit", "prompt": "…", "params": {"…": "…"}, "status": "succeeded", "finished_at": "…"}
    ],
    "edges": [{"source": "…", "target": "…", "kind": "input", "role": "image", "position": 0}],
    "truncated": false
  }
  ```

- 祖先方向だけを辿る(Run の入力すべて、上描きの下地、`origin`)。兄弟の出力と子孫は入れない。ノードは最大 1000 件。本文が 1 MiB を超えるときは、遠い祖先から params、prompt の順に落とす。どちらかで削ったときは `truncated: true` にする。
- 取り込んだ画像(`origin_meta` を持つ `upload`)が祖先にいれば、その `origin_meta` のグラフもつなげて埋め込む。ノードごとに `instance` を持つので、環境をまたいで何度受け渡しても系列が積み重なる。
- 読み取りは `gakei.lineage/1` にも対応し、同じグラフの形に変換する。
- **受け取った側では、埋め込まれた祖先を DB の行(`run`、`run_input`、`asset`)にしない。** この環境で実行した記録ではなく、署名もないためである。系列グラフを返すときに `origin_meta` から組み立て、「埋め込み(未検証)」のノードとして返す。ノードの `instance` がこの GAKEI で、同じ ID の行があれば、その行を使う。
- 祖先の画像は埋め込まない。そのためノードは画像なしで表示する。ただし、その祖先の画像を書き出したファイルも取り込んであれば、その Asset のサムネイルを表示する。この対応付けのため、`asset.origin_ref_asset_id`(追記のみ。migration `0008`)を持つ。取り込んだファイルからチャンクを除いた sha256 が、埋め込まれていた `sha256` と一致したときだけ、埋め込まれていた asset id を記録する(外部で加工されたファイルは、別の画像なので対応付けない)。
- 世代の上限は実質的に設けない。系列グラフの API(`GET /api/assets/{id}/lineage`)の深さの上限と、祖先方向の既定値を 255 ホップ(1世代 = 2ホップ)にし、ノードの上限を 1000 件にする。量はノード数で抑え、上限で打ち切ったときは「一部のみ表示しています」と表示する。以前の既定(祖先 5 ホップ)では、取り込んだ画像の由来の辺も1ホップ使うため、3世代目で途切れていた。
- 加工せずに取り込んだ画像(`origin_ref_asset_id` が埋め込みの root と一致する)は、root と同じ画像である。系列グラフでは root のノードを作らず、取り込んだ Asset を root の位置に置き、root を生んだ Run から直接つなぐ(「由来(未検証)」の辺は、外部で加工された画像のときだけ出す)。書き出すときも同じく root のノードを入れず、取り込んだ Asset のノードに `origin_ref`(元の asset id と instance)を残す。受け取った側は、`origin_ref` の id でも取り込み済みの画像を探して対応付ける(2026-09-25 追記)。
- 埋め込みノードには DB の行が無いので、ビューアや Run の詳細ページへは移動しない。取り込み済みの画像に対応付いた Asset ノードだけ、その画像を開く。
- 埋め込みノードを選ぶと、インスペクターに埋め込まれていた内容(provider、model、prompt、params、生成元)を表示し、Run ノードからは「この設定をフォームに読み込む」が使える。

### 作らないもの

- JPEG(XMP)と WebP(VP8X)への埋め込み
- 署名と改ざんの検知(C2PA は Phase 3 のまま)
- 他のインスタンスの入力画像を、sha256 で自動的に探すこと
- メタ情報なしのダウンロードを選べるようにすること
- ComfyUI の `workflow` と `prompt` チャンクをワークフローとして取り込むこと(ADR-0013 の非ゴール)。表示のためだけに読むことは ADR-0018 で扱う(2026-09-26 追記)
- チャンクの無い、バイト列が同じ画像の再アップロードの重複排除

## Options Considered

### 埋め込む場所

| 案 | 評価 |
|---|---|
| 保存時に原本へ埋め込む | ADR-0004(原本は不変)に反する。sha256 も provider が返したバイト列と変わる |
| ダウンロードの応答にだけ埋め込む(採用) | 原本はそのまま。チャンクを取り除けば元のバイト列に戻るので、照合も簡単 |

### 埋め込む内容

| 案 | 評価 |
|---|---|
| ID だけ | プロンプトは外に出ないが、DB の無い環境では何も復元できない |
| ID とレシピ(採用) | ComfyUI と同じく、画像だけで設定を復元できる。プロンプトが画像と一緒に外へ出る |
| 標準の XMP / IPTC の項目 | 他のツールで読めるが、ADR-0001 の非ゴール(IPTC 埋め込み)に踏み込む。GAKEI 自身が読めれば足りる |

### 同じ GAKEI に戻したとき

| 案 | 評価 |
|---|---|
| 既存の Asset を返す(採用) | 系列がそのまま続く。新しい行もノードも増えない |
| 常に新しい Asset を作り、由来の辺を付ける | 系列グラフに「再取り込み」のノードが増え、同じ画像が2つに見える |

### 対象の形式

| 案 | 評価 |
|---|---|
| PNG だけ(採用) | 既定の出力(OpenAI の既定、ComfyUI の SaveImage)を押さえられる。チャンクの挿入だけで済む |
| PNG と JPEG | JPEG は APP1 に XMP を入れれば済むが、今は需要が分からない |
| 3形式すべて | WebP は拡張形式(VP8X)への変換が必要で、手間の割に使われていない |

## Trade-off Analysis

ADR-0001 は、画像が外に出た後の来歴証明(C2PA)を Phase 3 にしている。この ADR は来歴を**証明**するものではなく、GAKEI 自身が元の Asset に**戻る**ための参照である。署名を持たず、照合を通らない内容は証跡に入れないので、DB が正本であることは変わらない。

レシピを入れる代わりに、プロンプトが画像と一緒に組織の外へ出る。ComfyUI の出力と同じ性質であり、その点は利用者が選んだ(2026-09-24)。外に出したくない画像のために「メタ情報なし」のダウンロードを足すかは、使ってみてから決める。

## Consequences

- ダウンロードした PNG を GAKEI に戻すと、元の Asset として扱われ、系列が途切れない。
- 別の GAKEI や、外部で加工された画像でも、埋め込まれていたレシピを見てフォームに戻せる。
- `asset` に追記のみの列 `origin_asset_id` と `origin_meta` が加わる(ADR-0003 に追記)。
- `POST /api/assets` が既存の Asset を返すことがある。応答の `ingest_outcome` で区別する。
- `download=1` の PNG 原本は、保存している原本とバイト列が違う(ADR-0004 に追記)。
- 本線(ADR-0006)の監査イベント `asset.download_original` の意味は変わらない。
