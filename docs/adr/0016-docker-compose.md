# ADR-0016: Docker イメージと Compose ファイルを用意する

**Status:** Proposed
**Date:** 2026-09-26

## Context

ADR-0012 では、個人向けの配布方法として `git clone` と起動スクリプトを採用し、Docker は「Docker Desktop が必要で、個人の PC では敷居が高い」として採用しなかった。この判断は個人の PC については変わらない。

一方で、常時動いている自宅サーバーや NAS、社内の Linux サーバーに置いて使いたい場合は、Docker のほうが手軽である。Node や uv を入れる必要がなく、更新はイメージの作り直しで済み、データの置き場所もボリュームとして明示できる。

本線(ADR-0002)も「コンテナイメージは1種類」を前提にしているので、ローカルMVPの段階でイメージを作れるようにしておくことは、本線の方針とも矛盾しない。

## Decision

1. **リポジトリ直下に `Dockerfile`、`compose.yaml`、`.dockerignore` を置く。** 起動スクリプト(ADR-0012)は引き続き主な導入方法で、Docker はサーバーに置きたい人向けの追加の選択肢とする。
2. **イメージは多段ビルドで作る。**
   - 1段目は Node 24 で `npm ci` と `npm run build` を実行し、`frontend/dist` を作る。
   - 2段目は Python 3.12 の slim イメージに uv で依存関係(開発用を除く、`uv.lock` どおり)を入れ、バックエンドと1段目の `dist` をコピーする。リポジトリと同じ配置(`backend/` と `frontend/dist`)にし、アプリのパス解決を変えない。Node はイメージに含めない。
   - root 以外のユーザーで動かす。
   - `HOST=0.0.0.0`、`PORT=8000`、`DATA_DIR=/data` を既定にする。起動コマンドは `python -m app`(ランチャーではない。ビルドとブラウザは不要)。
   - `amd64` と `arm64` の両方でビルドできること(基底イメージが両方に対応していればよく、~~公開用のマルチアーキテクチャのビルドは行わない~~)。(2026-09-27 改訂: ADR-0021 でリリース時にマルチアーキテクチャビルドを GHCR に push することにした。CI(`ci.yml`)の確認ビルドは引き続き単一アーキテクチャのまま)。
3. **Compose は1サービスだけにする。** 部品(DB、リバースプロキシ、ComfyUI)は同梱しない。(2026-09-29 注記: ADR-0027 で PostgreSQL を同梱する構成に変わった。コメントアウトで元の SQLite のみの構成に戻せる。)
   - データは名前付きボリュームを `/data` にマウントする。SQLite、画像、画面で保存した API キーがここに入る。
   - ホスト側の公開先の既定は `127.0.0.1:8000` にする。コンテナ内は `0.0.0.0` で待ち受けるが、ホストの外には出さない。変数(`GAKEI_BIND`、`GAKEI_PORT`)で変えられる。
   - リポジトリ直下の `.env` があれば読む(なくても起動する)。ただし `HOST`、`PORT`、`DATA_DIR` はコンテナ用の値で上書きする(ローカルで起動する用の `.env` がそのまま使えるように)。
   - ホストで動く ComfyUI に届くよう、`host.docker.internal` をホストに向ける。接続先は設定画面で `http://host.docker.internal:8188` を指定する。
4. **レプリカは1つだけ。** ローカルMVPはジョブの実行を api プロセス内で行い、DB は SQLite なので、複数のコンテナで同じボリュームを共有してはいけない。(2026-09-29 注記: ADR-0027 で PostgreSQL も選べるようになったが、ジョブの実行が api プロセス内である点は変わらないため、この制約は PostgreSQL でも同じ。)
5. **認証がないことは変わらない。** LAN やインターネットに公開する場合は、利用者が認証付きのリバースプロキシなどを前段に置く。README に明記し、Compose の既定では公開しない。
6. ~~**イメージをレジストリに公開しない。** 利用者は clone して `docker compose up -d --build` でビルドする。公開は OSS 公開(ADR-0011)の後に改めて検討する。~~(2026-09-27 改訂: ADR-0021 でイメージを GHCR(`ghcr.io/zolgear/gakei`)に公開することにした。この項は ADR-0021 で置き換える。`compose.yaml` は clone してビルドする人向けのまま変えない)
7. **CI でイメージのビルドと起動を確認する。** Linux で `docker build` し、`FAKE_PROVIDER=1`(ADR-0017)で起動して `/api/capabilities` が応答することを確かめる。(2026-09-30 追記、Issue #43: 起動待ちはログイン不要の `GET /api/health` で行い、その後に `/api/capabilities` も確かめる。イメージの `HEALTHCHECK` も `/api/health` を使う)

## Options Considered

| 選択肢 | 評価 |
|---|---|
| A: 起動スクリプトのみ(現状) | サーバーでも動くが、Node と uv を入れる必要があり、常駐させる仕組み(systemd など)は利用者が用意する |
| B: Dockerfile と Compose を同梱し、利用者がビルドする(採用) | Docker があれば他に何も要らない。`restart: unless-stopped` で常駐できる |
| C: B に加えて GHCR にイメージを公開する | clone も不要になるが、リリースの運用と、同梱する依存のライセンス表記(ADR-0011)が必要 |

| データの置き場所 | 評価 |
|---|---|
| A: 名前付きボリューム(採用) | 権限の問題が起きない。バックアップは `docker run` 経由でやや手間 |
| B: バインドマウント(`./data`) | ホストから直接見えるが、コンテナ内のユーザーとホストのファイル所有者の不一致で書き込めないことがある。README で切り替え方を示す |

## Consequences

- サーバーに置く人は Docker だけで動かせる。
- `.env` を読むので、リポジトリ直下の `.env` にある API キーはコンテナにも渡る。
- コンテナから見て ComfyUI の接続先はループバックではないので、起動時の警告(ADR-0013)が出る。
- CI に Docker のビルドが加わり、所要時間が少し延びる。
- ADR-0012 の Options Considered の C(Docker)は、個人の PC 向けとしては引き続き不採用で、この ADR はサーバー向けの追加の手段として位置づける。
