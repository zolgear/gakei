# ADR-0043: サムネイルの表示を顔の位置に寄せる(焦点の記録と object-position)

**Status:** Proposed
**Date:** 2026-10-10

## Context

ストック、履歴、系列のノード、入力画像のタイル、検索などのサムネイルは、正方形などの枠に `object-fit: cover` で中央を切り取って表示している(約 20 か所)。縦長や横長の画像では、人物の顔が切れたり枠の外に出たりする。生成する画像の多くはイラスト・アニメ調の人物で、顔が見えないと見分けにくい。

サムネイルそのもの(ADR-0004。長辺 512px の WebP)は縦横比を保っていて、正方形ではない。切り取りは画面の CSS で行っている。

2026-10-10 にユーザーから、イラストの顔のおおよその位置を求め、サムネイルを顔中心に見せたいと要望があった(別のチャットで検討した案として、opencv の LBP カスケード lbpcascade_animeface を使い、縮小画像で検出し、見つからなければ中央にする方法が示された)。実行時の軽さを最優先し、精度は求めない。

## Decision

### 1. 焦点を記録し、表示でずらす

- サムネイルの画像は作り直さない。Asset ごとに **焦点**(画像の幅・高さに対する 0〜1 の位置 `x`、`y`)を記録し、画面では `object-fit: cover` の要素に `object-position: x% y%` を付けて、その位置が枠に入るように見せる。枠の縦横比が場所ごとに違っても、同じ焦点がそのまま効く。
- 焦点が無い(未計算、顔が見つからない)ときは今までどおり中央。
- 対象は生成画像、アップロード画像、スケッチ。マスクは対象外。

### 2. 顔の検出

- **opencv-python-headless** と、アニメ顔用の LBP カスケード **lbpcascade_animeface**(nagadomi、MIT)を使う。カスケードの XML は GAKEI に同梱し(バージョンと sha256 を記録)、第三者ライセンスの表記(ADR-0021)に載せる。実行時にダウンロードしない。
- 手順: 原本から長辺 320px 程度に縮小 → グレースケール → `equalizeHist` → `detectMultiScale(scaleFactor=1.1, minNeighbors=5, minSize=(24, 24))` → いちばん大きい顔の中心を焦点にする。
- 顔の中心にそのまま合わせると、枠の上端に髪が切れやすいので、焦点の `y` は顔の中心より少し上(顔の高さの 1/4 程度)に寄せてよい(実装で見た目を確かめて決める)。
- 検出できなければ焦点なし(= 中央)。失敗や例外も焦点なしにして、取り込みは止めない。
- 実写の顔、横顔、小さい顔は見逃しやすい。目立つ場合は、ONNX Runtime(既に依存にある)で動くアニメ顔の検出モデルへの差し替えを、別の ADR で検討する(重くなる)。

### 3. 計算のタイミングと保存

- 取り込み(`ingest`)で派生画像を作るのと同じ流れで計算する。縮小画像での検出は数ミリ秒の見込み。重い環境のために、取り込みを待たせない形(プロセス内の後回しの処理)にするかは、計測して決める。
- 保存先は新しいテーブル `asset_focal_point`(`asset_id`、`x`、`y`、`method`(`animeface-lbp` / `none`)、`version`、`computed_at`)。焦点は証跡ではなく、作り直してよい派生データなので、来歴の列(`asset`)には書かない(ADR-0003)。`version` は検出の手順を変えたときに上げ、古いものを作り直す目印にする。
- 既存の Asset のために、埋め戻しのツール(`python -m app.tools.backfill_focal_points --dry-run`)を用意する。サーバーを止めずに動かせること。
- オブジェクトストレージ(ADR-0028)でも動くこと(原本は `open_content` で読む)。

### 4. API と画面

- Asset の一覧・詳細の応答(サムネイルを出すところで使う形)に `focal_point: {x, y} | null` を足す。系列のノード、Run の出力、検索の結果など、サムネイルを出す応答にも必要なら足す。
- フロントは、サムネイルを `object-fit: cover` で出す部品に、焦点があれば `object-position` を付ける。共通の小さな関数(または部品)にまとめ、約 20 か所に当てる。ビューアの全体表示(`contain`)には付けない。
- 利用者が焦点を手で直す機能は、今は作らない。

### 作らないもの

- サムネイル画像を顔中心に切り抜いて作り直すこと
- 実写の顔の検出
- 焦点の手動の指定
- 顔以外の「見どころ」の推定(全体の主題の位置など)

## Options Considered

| 案 | 評価 |
|---|---|
| A: 焦点を記録し、CSS の object-position でずらす(採用) | サムネイルを作り直さない。枠の形が違う場所すべてに同じ記録が効く。焦点を変えても画像のキャッシュ(`Cache-Control: immutable`)に影響しない |
| B: 正方形のサムネイルを顔中心に切り抜いて作る | 表示側は変えずに済むが、派生画像の版(ADR-0036)を上げて作り直しが要り、正方形以外の枠には合わない |
| C: 検出器に ONNX のアニメ顔検出モデル(YOLO 系)を使う | 精度は高いが、モデルのダウンロードと推論が重い。軽さを最優先する今回は採らない |

| 検出器 | 評価 |
|---|---|
| opencv + lbpcascade_animeface(採用) | 軽い。イラストの正面の顔なら十分。opencv-python-headless の依存が増える(数十 MB。Linux の x86_64・aarch64、Windows に wheel がある) |
| 実写向けの Haar・YuNet | イラストに効かない |

## Consequences

- イラストの人物のサムネイルで、顔が枠に入りやすくなる。
- 依存に opencv-python-headless が加わる。Docker イメージと Windows の配布物が大きくなる。第三者ライセンスの表記に opencv と lbpcascade_animeface が加わる。
- 新しいテーブルとマイグレーションが要る。

## 実装時の記録(2026-10-10)

- **計算のタイミング:** 取り込みの後に、プロセス内の焦点の worker(`app/worker/focal.py`)が1件ずつ求める。取り込みの応答は待たせない。待ち行列はメモリの中だけに持ち(DB には積まない)、渡しそこねた Asset は埋め戻しのツールが拾う。Raspberry Pi 5 で実際の生成画像 48 枚を2回測ったところ、原本のデコードが中央値 55〜59ms(最大 108〜206ms)、縮小を含む検出が中央値 15〜20ms(最大 27〜34ms)だった。取り込みの中で同期に求めても派生画像の WebP の作成より軽いが、原本のデコードを含めると 0.1 秒近くになる画像もあるため、後回しにした。
- **焦点の y:** 顔の中心から顔の高さの 1/4 だけ上に寄せる(`FOCAL_Y_SHIFT = 0.25`)。正方形の枠で中心のままと見比べ、髪や頭の上が切れにくい方を選んだ。
- **検出の割合:** 実際の生成画像 48 枚のうち 26 枚で顔を見つけた(SD WebUI 10/22、旧形式のキーの画像 8/12、ComfyUI 4/6、OpenAI 3/6、アップロード 1/1、スケッチ 0/1)。見つからなかったものの多くは後ろ姿や顔の写っていない構図、実写調、模様の画像で、顔が見えているのに見逃したものは数枚(顔が小さい立ち絵、顔が大きく画面からはみ出す寄りの絵、横たわった・傾いた顔)。誤検出は、2つ目以降の候補に1件あったが、いちばん大きい顔を使うので焦点には影響しなかった。
- **カスケードの読み込み:** opencv は Windows で ASCII 以外の文字を含むパスを開けないことがあるため、XML は Python で読んで sha256 を確かめ、メモリから読み込ませる(`cv2.FileStorage` の `FILE_STORAGE_MEMORY`)。`detectMultiScale` は同じインスタンスを同時に呼ばないよう鍵を持つ。
- **保存:** 顔が見つからなかったときも `method='none'` の行を作り、同じ版では探し直さない。
- **応答:** `AssetSummary`(と、それを継ぐ検索・似た画像・重複の結果、`AssetDetail`)、`RunInputRef`、`RunOutputRef`、`RunSummary.primary_parent_focal_point`、`LineageAssetInfo`、`EmbeddingGraphNode`、`PublicShareAsset` に `focal_point` を足した。一覧は `IN` でまとめて引く。
