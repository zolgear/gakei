# ADR-0023: MCP サーバー(外部の AI エージェントから GAKEI を操作する)

**Status:** Proposed
**Date:** 2026-09-28

2026-09-28 にユーザーが、ツールの範囲(3章)とアクセストークン方式(2章)を承認し、上限の既定値を 30 件に決めた(5章)。

## Context

Claude Code や Claude Desktop などの AI エージェントは、MCP(Model Context Protocol)のサーバーを登録すると、そのサーバーのツールを呼べる。GAKEI には REST + OpenAPI の API があるが、エージェントに使わせるには、利用者が API の使い方を説明するか、エージェントが OpenAPI を読んで HTTP を組み立てる必要がある。MCP に載せれば、エージェント側の設定 1 つで「GAKEI で画像を生成し、ストックを探し、グループに整理する」ことができる。

一方で、エージェントは人より速く、繰り返し呼び出す。生成は課金を伴うので、勝手に大量生成されない仕組みが要る。認証モード(ADR-0019)ではブラウザの Cookie でログインするので、エージェント用の認証手段も要る。

Issue [#7](https://github.com/zolgear/gakei/issues/7)。GAKEI の中でエージェントを動かす機能(ホスト側エージェント)は [#8](https://github.com/zolgear/gakei/issues/8) で、この ADR の範囲外。

## Decision

### 1. 範囲と提供形態

- **GAKEI 本体が MCP サーバーになる。** 既存の FastAPI アプリに、Streamable HTTP の MCP エンドポイント `/mcp` を同居させる。別プロセスや stdio のサーバーは作らない。
- 実装は公式の Python SDK(`mcp`)を使う。セッションを持たないモード(stateless)で動かし、プロセスを再起動してもエージェント側の再接続が要らないようにする。
- ツールは REST の API を HTTP で呼ばず、REST と同じドメイン関数を直接呼ぶ。検証を二重に書かないよう、REST のハンドラーにある処理(例: Run 作成の検証)はドメイン関数に切り出して両方から使う。
- **既定は無効。** 管理者設定の「MCP」で有効にしたときだけ `/mcp` が応答する(無効のときは 404)。

### 2. 認証

| モード | `/mcp` の認証 |
|---|---|
| 個人モード(`AUTH_MODE=none`) | なし。REST と同じく暗黙の管理者として動く。待ち受けの既定が `127.0.0.1` であることに頼る |
| 認証モード(`AUTH_MODE=oidc`) | **アクセストークン**(`Authorization: Bearer <token>`)。Cookie では受けない |

- アクセストークンは、利用者がユーザー設定で発行する(名前を付ける。値は発行時に 1 回だけ表示)。DB には SHA-256 のハッシュだけを保存し、失効できる。トークンはそれを発行した利用者として動き、Run の実行者(`created_by_user_id`)もその利用者になる。
- トークンを受け付けるのは `/mcp` だけにする。REST API にトークンを広げるかは、必要になったら決める。
- DNS リバインディング対策として、`/mcp` は `Origin` ヘッダーがあるとき、次のどちらかに当たらなければ 403 で拒否する(MCP 仕様の推奨)。`Origin` が無い呼び出し(ブラウザ以外のエージェント)は通す。
  - `PUBLIC_BASE_URL` の origin と一致する。
  - `Host` ヘッダーと同じ host:port で、ホストが IP アドレスか `localhost`。ホスト名との単純な一致は許さない(リバインディングでは `Origin` と `Host` がどちらも攻撃者のドメイン名になるため)。ホスト名で公開し、ブラウザで動く MCP クライアントを使うときは `PUBLIC_BASE_URL` を設定する。
- SDK の transport security(Host/Origin の許可リスト)は使わない。LAN の IP で開く使い方があり、待ち受けのホスト名を事前に列挙できないため(2026-09-28 実装時に決定)。

```
api_token(
  id UUID PK,
  user_id UUID NOT NULL FK app_user.id,
  name VARCHAR(100) NOT NULL,
  token_hash VARCHAR(64) NOT NULL UNIQUE,
  created_at TIMESTAMPTZ NOT NULL,
  last_used_at TIMESTAMPTZ NULL,
  revoked_at TIMESTAMPTZ NULL
)
```

### 3. ツール

| ツール | 内容 |
|---|---|
| `get_capabilities` | 使えるプロバイダー、モデル、パラメーター、サイズ(フォームを組み立てる情報と同じ) |
| `generate_image` | Generate / Edit の Run を作る。入力は Asset ID(最大 16)、マスクの Asset ID、グループ ID。既定では完了まで待ち(上限あり)、出力を返す |
| `get_run` | Run の状態と出力。待ち時間を指定して完了を待てる |
| `cancel_run` | 待機中(queued)の Run を取り消す(REST の取り消しと同じ。実行中の Run は止めない) |
| `search_assets` | ストックの検索・一覧(キーワード、種類、グループ、件数) |
| `get_asset` | Asset のメタデータ、主たる親、生成した Run、サムネイル |
| `upload_image` | 画像を取り込み、Asset にする(エージェントの手元の画像を Edit の入力にするため) |
| `list_prompt_sets` | プロンプトセットの一覧と中身 |
| `list_groups` / `create_group` / `move_to_group` | グループの一覧、作成、Asset の移動(ADR-0022) |

- **削除と設定の変更は提供しない。** Asset・グループ・プロンプトセットの削除、プロンプトセットの編集、管理者設定の変更は画面で行う。エージェントの誤操作で失うものを作らない。
- ツールの説明文には、生成が課金を伴うことを書く。MCP のツール注釈(読み取り専用か、破壊的か)も付ける。

### 4. 画像の受け渡し(ADR-0004 との整合)

- **出力は Asset ID と URL で返す。** URL は原本の `GET /api/assets/{id}/content` と、画面のビューアを指す(`PUBLIC_BASE_URL` があればそれを基に、無ければリクエストの URL を基にする)。認証モードでは、この URL の取得にブラウザのログインが要る(トークンは `/mcp` でしか受けないため)。エージェントは URL を利用者に示すだけで、原本の中身は取得できない。
- 本文に画像を載せるのは **サムネイル(512px WebP)だけ**。エージェントが結果を目で確かめられるようにするためで、4K の原本やプレビューを base64 で返さない。サムネイルを付けるかはツールの引数で切れる。
- `upload_image` は base64 の画像を受ける(MCP のツール呼び出しで画像を渡す手段が他にないため)。サーバーでデコードして通常のアップロードと同じ取り込み(`ingest`)を通し、DB に base64 は入れない。大きさの上限は REST のアップロードと同じ。

### 5. 生成の上限と記録

- 管理者設定で **MCP 経由で作る Run の上限(1 時間あたりの件数)** を決める。既定は 30 件。0 にすると MCP からの生成を止め、参照系のツールだけ使える。上限を超えた呼び出しは Run を作らずにエラーを返す(REST の 409 と同じく、証跡を汚さない)。上限はインスタンス全体の件数で、利用者ごとではない。削除済みの Run も数え、画面から作った Run は数えない。件数を数えてから Run を作るので、同時に呼ばれると数件超えることがある(厳密な上限ではなく、暴走を止めるための歯止め)。
- MCP 経由で作った Run には実行元を記録する。`run.origin`(`NULL` は画面、`mcp`)と `run.api_token_id`(認証モードのみ)を足す。作成時に 1 回だけ書く来歴の列で、ADR-0003 の追記のみの規則に従う。Run 詳細に「実行元: MCP」を出す。

### 6. 画面

- **管理者設定 →「MCP」:** 有効/無効、1 時間あたりの上限、接続先 URL、Claude Code での登録例(`claude mcp add --transport http gakei <URL>`)。
- **ユーザー設定 →「アクセストークン」(認証モードのみ):** 発行(名前を付ける、値は 1 回だけ表示してコピー)、一覧(名前、作成日時、最終使用日時)、失効。
- **Run 詳細:** 実行元が MCP のとき、その旨を出す。

### 7. 使ってみたフィードバックによる改訂(2026-09-28、ユーザー承認)

Issue #7 のコメントで、実際に使って困った点が報告された。対応を次のとおり決め、上の各章の記述より優先する。

1. **生成はすぐ返す。**
   - `generate_image` は、Run を登録したらすぐ `run_id` と状態を返す(既定で完了を待たない)。
   - 完了は `get_run(wait_seconds)` で待つ。1 回の待ちは最大 25 秒程度に区切り、一般的な MCP クライアントのタイムアウトより短くする。
   - 自分が作った最近の Run を探せる `list_runs` を足す。実行元(`origin`)、作成時刻(`since`)、状態で絞り込める。~~既定は自分が作った Run だけ(`created_by=me`)で、`anyone` を指定すれば全員の Run も返す(閲覧範囲は全員全件。ADR-0019)。~~ 2026-09-28 に ADR-0025 で改めた: `created_by` 引数はなくし、常に自分(トークンの持ち主)が作った Run だけを返す。他のツールも、トークンの持ち主に見えるものだけを扱う。
   - `idempotency_key` は入れない。すぐに `run_id` を返すので、タイムアウトしたから再実行して二重に生成する、という事態がほぼ起きないため。
2. **アップロード用の URL を発行する。**
   - `create_upload_url` を足す。10 分間、1 回限り有効なアップロード URL を返す。クライアントは curl などで画像の本文をそのまま送る。
   - 取り込みは通常のアップロードと同じ(`ingest`)。作成者は URL を発行した利用者になる。
   - 未使用の URL は DB に置き、期限が過ぎたら無効にする。
   - URL は推測できないトークンを含み、DB にはそのハッシュだけを保存する。
   - 取り込みに失敗した(画像でない、大きすぎる)ときは URL を使用済みにせず、期限内なら送り直せる(実装時に決定)。
   - base64 の `upload_image` は、小さい画像向けに残す。
   - `upload_from_url`(サーバーが指定の URL を取りに行く)は作らない。LAN 内の任意の URL に届く穴(SSRF)になるため。
3. **画像の本体もトークンで取れるようにする。**
   - `GET /api/assets/{id}/content` は、Cookie に加えてアクセストークン(`Authorization: Bearer`)も受け付ける。
   - 受け付けるのは画像の本体を取るこの GET だけで、他の REST API には広げない。2 章の「トークンは `/mcp` だけ」を、この範囲で改める。
   - MCP が無効のときは、この GET でもトークンを受け付けない(トークンは MCP のためのもの。実装時に決定)。
   - 期限つきの署名付き URL は採らない。URL が漏れると誰でも開けるため。トークンなら、今ある失効の仕組みで止められる。
4. **透過の情報を返す。** `get_asset` に `has_alpha` と、透過ピクセル(alpha < 255)の割合を足す。
5. **size の指定場所を明記する。** `get_capabilities` とツールの説明に、`size` は `params.size` に入れると書く。
6. **料金の目安と、上限の残りを返す。**
   - `estimate_cost(provider, model, params, n)` を足す。既存の料金の目安(画面の見積もりと同じ計算)を使う。
   - Run の結果には、分かる場合だけ料金の目安を入れる。
   - 生成系と Run の結果に、1 時間の上限の残り回数を入れる。

## Options Considered

### Option A: 別プロセスの MCP サーバー(stdio)が REST API を呼ぶ
**Pros:** 本体に手を入れない。エージェントの PC で動くので、手元のファイルパスを直接読める。
**Cons:** 配布物が 1 つ増え、利用者が Python 環境や設定を用意する必要がある。REST を呼ぶための認証(トークン)は結局要る。GAKEI をサーバーに置いた場合も、各 PC にインストールが要る。

### Option B: 本体に Streamable HTTP の `/mcp` を同居(採用)
**Pros:** 追加のインストールが要らず、URL を登録するだけで使える。ドメイン関数を直接呼べるので、検証や記録が画面と同じになる。
**Cons:** エージェントの手元の画像は base64 で送る必要がある。本体の依存に `mcp` が加わる。

### 認証: MCP 仕様の OAuth か、アクセストークンか
MCP 仕様は OAuth 2.1 による認可を定めていて、エージェントがブラウザでログインしてトークンを得られる。ただし GAKEI が認可サーバー(または IdP の前段)として振る舞う必要があり、対応しているエージェントも限られる。まずはどのエージェントでも使える固定のアクセストークンにし、OAuth は必要になったら足す。

## Trade-off Analysis

決め手は「利用者が何もインストールせずに使えること」で、Option B を採る。代わりに手元の画像は base64 で送ることになるが、生成の入力に使う画像は多くない。課金の暴走は、既定無効・時間あたりの上限・実行元の記録の 3 つで抑える。削除を提供しないのは、MCP の誤操作は画面の誤操作より起きやすく、気づきにくいため。

## Consequences

- エージェントから GAKEI の生成とストックを使える。生成物は画面から作ったものと同じく系列と証跡に残る。
- 依存に `mcp` が加わる。
- 認証モードにアクセストークン(`api_token`)が加わる。漏れたトークンは失効で止める。
- Run に `origin` と `api_token_id` が加わる(既存の Run は `NULL` = 画面)。
