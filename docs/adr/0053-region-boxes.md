# ADR-0053: 領域の指示(入力画像に四角を描き、四角ごとに指示を書く。四角の検出は VLM)

**Status:** Accepted
**Date:** 2026-10-20

2026-10-20 に、ユーザーが次のように指示した。

- 入力画像の上に四角(バウンディングボックス)を描き、四角ごとに指示を書く機能を作る。
- 四角の指示を学習した画像生成モデルが出てきている。API に専用の項目が無くても、指示の形が決まっていれば、ほかのモデルにも同じ画面とデータで使える。
- 四角の検出は VLM で行う。手元で動かしたい場合も、手元の VLM を LLM の接続先として使う(検出の専用モデルは入れない)。
- 画像の生成と同じく、まず OpenAI で作り切る。ComfyUI と手元の VLM は、その後に足す。

## Context

- 2026-10 に、四角での指示を受けるモデルが続けて出た。どれも渡し方が違う。
  - **FLUX 3 Image(API)と FLUX.3 Image Klein(重みを公開):** プロンプトの文の後ろに、四角の JSON の配列を付ける。四角は `[上, 左, 下, 右]` で 0〜1000 に正規化する。要素ごとに、元の画像のどこにあるか(`src_bbox`)とどこに置くか(`tgt_bbox`)を持つ。これで移動、置き換え、足す、消す、そのまま残す(アンカー)を表す。四角は配置と大きさの目安で、マスクのような厳密な範囲ではない。
  - **MOSS-Image(重みを公開、Apache-2.0):** プロンプトを JSON にし、要素ごとに種類・説明・描く文字・四角を持つ。四角は画面の中心を原点にしたピクセルの `[y0, x0, y1, x1]`。生成のみで、入力画像を受ける編集はできない。
  - **Krea 3(API、ベータ):** 局所の編集(`regional_edit`)はあるが、四角を渡す項目は公開されていない。
  - **ComfyUI:** 本体に、四角を描くノード(Create Bounding Boxes)が入った。出力は、ピクセルの四角の一覧(`BOUNDING_BOXES`)、説明文の配列、プレビューの画像。外から四角を受ける入力(`bboxes`)もある。モデルごとの形には、別の変換ノード(FLUX.3 Layout Prompt、MOSS-Image Layout Prompt、Ideogram の JSON)で直す。
- 共通に使えるのは、四角と指示のデータと、それを描く画面である。モデルへの渡し方は、モデルごとに変換する必要がある。ComfyUI もこの作りになっている。
- 今の GAKEI は、場所の指示をマスク(ADR-0004 の Edit の入力)とスケッチ(ADR-0010)と配置(ADR-0050)で伝える。四角ごとに別々の指示を付ける手段は無い。
- OpenAI の画像の API は、四角を受ける項目を持たない。番号付きの四角を描いた画像と、番号を使った文の指示で伝えることはできる(効き方はモデル任せ)。
- 画像を見て物の位置を答える処理は、今の GAKEI には無い。サムネイルの焦点(ADR-0043)は顔の検出の中心だけを使い、四角は捨てている。モデルも OpenCV のカスケードで、一般の物は見つけられない。
- 2026-10-20 に、OpenAI の VLM(`gpt-5.6-luna`)で、アニメ調のイラスト 4 枚の四角を検出して確かめた(画像は `detail: high`、応答は JSON のスキーマ、座標は 0〜1000)。
  - 人物、動物、大きな物は 4 枚とも正しい位置だった。カップ、鳥、壁の写真立て、数十ピクセルのキーホルダーなど、小さな物もおおむね取れた。
  - 言葉での指定(「髪のリボン」「猫のしっぽ」「風船の紐」など)も、おおむね正しい位置で返した。
  - 縦に長い物は、下の端が短くなりがちだった(鉢植えの鉢、風船の紐の下半分)。
  - 物の多い絵では、一度に 28 個を挙げた。細かすぎる候補も混じる。
  - 1 枚に 7〜16 秒。入力は 1024px の画像で約 1,400 トークン、出力は 500〜1,600 トークン。
  - 座標をピクセルで答えさせても精度はほぼ同じだった。
- Qwen3-VL と Qwen3.5(小さい版は Apache-2.0)は、四角を JSON(`bbox_2d`、0〜1000)で答えるように学習されている。手元の VLM のサーバー(OpenAI 互換の API)で動かせる。
- 手元で動かす検出の専用モデル(YOLO 系など)は、イラスト向けに配布されている重みの多くが、学習の仕組みの AGPL-3.0 の主張を受ける。ライセンスの緩い仕組みで学習した、イラスト向けの重みは見つからなかった(Options Considered の F〜H)。

## Decision

### 1. 範囲

画面の名前は「領域」(英語は Regions)。マスク・スケッチ・配置と並ぶ、入力画像に付ける道具の1つにする。

- 生成のフォームの入力の1枚目(主たる入力)の上に、四角を描く。最大 16 個。
- 四角ごとに番号と色のバッジを付ける。画像の下(狭い幅では下の一覧)に、四角ごとの札を出す。
- 札で決めること:
  - **名前:** その四角が何かを表す短い言葉(「右手の白いカフス」など。任意)。検出の候補から札にしたときは、候補の名前を入れる(直せる)。
  - **種類:** 変える(既定)/足す/そのまま残す/消す/動かす。
  - **指示:** その四角で何をするかの文(任意)。
  - **描く文字:** 看板などに描かせる文字(任意。指示とは分け、そのまま渡す)。
  - **参照画像:** その四角に使う画像(任意。ストックか入力から選ぶ)。参照画像は Run の入力(`role = image`。利用者の入力の後ろに足す)にもなる。2026-10-20 に改めた: `role = reference` の入力はプロバイダーに送らない(表示のためだけの役割)ので、送る画像は `role = image` にする。入力にすでにある画像は、足さずにその画像を指す。
- 「動かす」の四角は、元の位置と移す先の2つの四角を持つ。
- 四角の定義(位置と名前)と指示は分ける(2026-10-21 にユーザーの指示で改めた。もとは「変える」「足す」の四角に指示・描く文字・参照画像のどれかを求めていた)。指示の無い四角も保存して送れる。指示の無い「変える」「足す」の四角は名前の付いた目印になり、足す文では場所と名前だけを示す。全体の指示から「四角 1」のような番号か名前で指せる。「そのまま残す」「消す」「動かす」は、指示が無くても種類の意味のとおりに伝える。
- 四角の移動、大きさの変更、削除、番号の並べ替え、元に戻す・やり直す。
- 四角は画像の座標で持つので、画像を拡大しても位置はずれない。
- 狭い幅(ADR-0009)では、タッチで四角を描き、動かせること。
- 全体の指示(今のプロンプト)はそのまま使う。四角の指示は、全体の指示に足す形で渡す。

### 2. 作らないもの

四角以外の形(多角形、自由な線、楕円)、四角の回転、四角の中だけのマスクの生成、四角を絵として描くこと(四角は指示であって、画像の編集ではない)、検出の専用モデルの同梱とダウンロード。形の細かい指定はマスクとスケッチで行う。

### 3. データ(どのモデルにも依らない形)

- 四角の座標は、主たる入力の画像に対する割合(0〜1)で、左上を原点にした `[x0, y0, x1, y1]` にする(入力画像の無い Run では出力の大きさに対する割合。6章)。モデルごとの形(0〜1000、中心を原点にしたピクセル、yx の順など)には、渡すときに変換する。
- 1つの四角は次の値を持つ: 番号、種類、四角(「動かす」では移す先)、元の四角(「動かす」だけ)、名前(`label`。任意、100 文字まで、前後の空白を除き、空なら無し。制御文字は断る)、指示、描く文字、参照画像の Asset id。名前は四角の定義なので `run.regions` に入れ、再実行で戻す。
- Run を作る要求(`RunCreateRequest`)に `regions` を足す。サーバーは、四角の数、座標の範囲、文字の長さ、参照画像が見える範囲にあるか(ADR-0025)を確かめる。

### 4. 記録(ADR-0003 に足す)

- **`run.regions`(JSON の列。追記のみ):** 利用者が付けた四角(3章の形)と、どの渡し方で送ったか(5章)と、変換の版。証跡なので、Run を作った後は変えない。再実行やパラメーターの読み込みでは、ここから四角を戻す。
- **`run.params`:** 今までどおり、API に送った値そのもの(ADR-0003 4項)。四角を文に変えて送ったなら、その文を含んだプロンプトが入る。
- **四角を描いた画像(5章の「画像と文」):** サーバーが描く。新しい Asset の種類 `regions` として保存し、Run の入力(`role = image`。利用者の入力の後ろ、参照画像の前)にする。2026-10-20 に改めた: `role = reference` の入力はプロバイダーに送らないので、送る画像は `role = image` にする。主たる入力(`position = 0`)は今までどおり利用者の1枚目。主たる入力の Asset を `source_asset_id` で指す(スケッチと同じ)。ストックには既定で出さない(ADR-0035。スケッチ・マスク・配置と同じ設定の対象にする)。
- **四角の検出の結果(7章):** Asset ごとに、検出の履歴として保存する(新しい表 `asset_region_detection`。2026-10-20 にユーザーの指示で改めた。もとは保存しないとしていた)。証跡ではないので消せる。Run の記録になるのは、利用者が使うと決めた四角(`run.regions`)だけ。

### 5. モデルへの渡し方

プロバイダーは `capabilities()` で、四角を受けられるかと、その渡し方を答える。受けられないプロバイダーでは、フォームに「領域」を出さない(ADR-0005 と同じく、フォームは `capabilities()` から組み立てる)。

| 渡し方 | 使う先 | 中身 |
|---|---|---|
| **画像と文** | OpenAI の Edit | 番号と色の付いた四角を描いた画像を入力に足し(`role = image`)、プロンプトの後ろに番号ごとの指示を文で足す。四角を学習していないモデル向けの、効き方の保証が無い渡し方 |
| **ComfyUI に差し込む**(後の段) | 四角の差し込み先を持つワークフロー(6章) | Create Bounding Boxes の `bboxes` 入力に、四角の要素の一覧(0〜1000 の座標。6章)を差し込む。モデルごとの形への変換は、ワークフローの中の変換ノードに任せる |
| **モデルの形で渡す**(別の ADR) | 四角の形を公開しているプロバイダー | 各モデルの公開の形に変換する(FLUX 3 ならプロンプトの後ろの JSON)。プロバイダーごとの ADR で決める |

- 最初に作るのは、OpenAI への**画像と文**だけ。四角の画面とデータと記録を、これで作り切る。
- 「画像と文」で足す文は、利用者の言語に合わせて文言の JSON(ADR-0015)に置く。足した文は `run.params` のプロンプトに入るので、何を送ったかは Run から分かる。
- 四角を描いた画像は、入力の画像の上に描くのではなく、主たる入力に四角と番号だけを重ねた別の画像にする(主たる入力は今までどおり1枚目に送る)。Edit の入力の枚数の上限(ADR-0004)に、この1枚も数える。上限を超えるときは Run を作らずに理由を返す。
- 2026-10-20 に改めた: 四角を描いた画像と、四角の参照画像(入力に無いもの)は、`role = image` の入力として、利用者の入力の後ろに、四角を描いた画像、参照画像(番号の順)の順で足す。`role = reference` の入力はプロバイダーに送らないため。参照画像も入力の枚数の上限に数える。足す文では、画像を送る順の番号(「3枚目の画像」など)で指す。
- 足した文は `run.regions` にも残す(`appended_text`)。再実行では、`run.prompt` の末尾からこの文を除いて、利用者が書いたプロンプトに戻す。
- 「そのまま残す」の四角は、文で「変えない」と伝える。モデルの形がアンカーに対応していれば、そこではアンカーとして渡す。
- 効きやすい描き方と文(線の太さ、番号の位置、文の順序)は、実装のときに `quality=low` で確かめて決め、`docs/regions.md` に書く。
- FLUX 3 や Krea 3 などの新しいプロバイダーは、この ADR では足さない。ADR-0001 の「他プロバイダー対応」を改める ADR を別に起こしてから足す。その ADR で「モデルの形で渡す」の変換を決める。

### 6. ComfyUI(後の段。ADR-0052 に足す)

OpenAI での「画像と文」が出来てから足す。2026-10-21 に、ComfyUI の本体のコード(`comfy_extras/nodes_bounding_boxes.py`、ノード `CreateBoundingBoxes`)を読み、ユーザーの選択で次のように決めた。実機での確認は後で行う(本体のコードとテンプレートの JSON で作る)。

- **生成と編集の両方で使う。** 四角を使うモデル(レイアウトの変換ノードの先にあるもの)は主に生成で使うので、入力画像の無い Run でも四角を描けるようにする。
  - 入力画像のある Run(編集など)は、今までどおり主たる入力の上に描く。座標は主たる入力に対する割合(3章)。
  - 入力画像の無い Run は、出力の幅×高さの白紙の上に描く。座標は出力の大きさに対する割合。幅・高さを後から変えても割合のまま持つ(四角は伸び縮みする)。白紙では検出は使えない(画像が無い)。
  - OpenAI の「画像と文」は、これまでどおり入力画像のある Run だけ。
- **差し込み先の種類に `bounding_boxes` を足す。** 差し込む先は `CreateBoundingBoxes` の `bboxes` 入力。ワークフローの読み取り(ADR-0052 の規則)でこのノードを見つけたら、差し込み先の候補にする。アシスタントの提案(ADR-0052 6章)の項目には足さない(規則で十分に見つかる)。
- **差し込む値:** ノードが受ける「要素」の一覧を JSON の文字列にして `bboxes` に入れる。要素は `{"type": "obj" | "text", "bbox": [ymin, xmin, ymax, xmax], "desc": ..., "text": ...}` で、`bbox` は 0〜1000 の整数(ノードがピクセルに直す。ピクセルの格子はノードの `width` / `height` 入力で決まる)。並びは番号の順(ノードは背景を先、前景を後に置く想定)。
  - 同じノードの `last_incoming` 入力を空にして差し込む(API 形式では配列の値が配線とみなされるので、`{"__value__": []}` で包む。ComfyUI は実行時に包みを外す)。ノードは `last_incoming` と同じ値が来ると、上流の値ではなくキャンバスの値(`editor_state`)を使うため。
  - `editor_state` にも同じ四角をピクセルで書く(ノードの `width` / `height` で、ノードと同じ計算・同じ丸め。`width` / `height` が定数でも整数の Primitive への配線でもなく決められなければ空にする)。出力 PNG に埋め込まれるのは送ったグラフで、ComfyUI に読み込み直すと `bboxes` は落ちるため、こうしておくと四角もキャンバスに戻る(2026-10-22)。
  - 四角が1つも無い Run では差し込まない(テンプレートのキャンバスの値がそのまま使われる)。
  - `run.params` には差し込んだ値が入る。`run.regions` の渡し方は `comfyui_bboxes`(重ねた画像も足す文も無い)。`run.regions` には、四角を描いた台(`frame`: 主たる入力 `input` / 白紙 `output`。古い記録は `input`)も残し、再実行で戻す。
- **種類と指示の渡し方(説明に寄せる):** `desc` には指示を入れ、指示が無ければ名前を入れる(どちらも無ければ空)。描く文字のある四角は `type: "text"` にして `text` に入れ、それ以外は `obj`。種類はノードに送らない。
  - ComfyUI で選べる種類は「変える」と「足す」だけにする。「そのまま残す」「消す」はノードの形で表せず(送ると物を足す指示になる)、「動かす」は元の四角を持てないため。`capabilities()` で選べる種類を答え、フォームはそれ以外を出さない。
  - 四角ごとの参照画像も ComfyUI では使えない(ノードに入口が無い)。`capabilities()` で答え、フォームに出さない。
- **形が変わったら止める:** 実行の前に、ComfyUI の `object_info` で `CreateBoundingBoxes` があり、`bboxes` 入力が文字列を受けることを確かめる。無ければ、Run を失敗にして理由を示す(黙って違う形で送らない)。値の形は `docs/regions.md` に書く。
- 差し込み先を持たないワークフローでは、フォームに「領域」を出さない。

### 7. 四角の検出

四角を自動で出す。出した四角は候補で、利用者が選ぶと札になる(候補の名前が札の名前に入る。指示は任意)。検出は VLM で行う。管理者が検出に使う接続を決めていなければ、検出のボタンを出さない(手で描くことはできる)。

- LLM の接続先(ADR-0032)から、画像を受けられる接続を1つ選ぶ。使う側として `register_usage` で登録する(使用中の接続を消せないようにする)。
- 最初は OpenAI(Responses API の構造化出力。生成のアシスタントと同じ作り)で作る。
  - **2026-10-21 追記:** 構造化出力に対応するかは、接続先ごとに管理者が指定できる(自動 / 対応する / 対応しない。ADR-0032 の同日の追記)。「自動」(既定)は今までどおり OpenAI の公式の接続先だけを対応とみなす。OpenAI 互換のプロキシ経由で OpenAI のモデルにつなぐ構成では、ホストが公式でなくても構造化出力が使えるため。判定は `llm_connections.supports_structured_outputs` の1か所で、ComfyUI のワークフローの推定(ADR-0052 6章)と共通。
  - 使えないときは、理由を1つに絞って管理者設定に出す(`GET /api/settings/region-detection` の `unusable_reason`: `disabled` / `connection_missing` / `api_key_missing` / `structured_outputs_unsupported`)。構造化出力のときは「LLM の接続先」で「対応する」にできることを案内する。指定を誤って、対応しない接続先にスキーマ付きで送ったときは、接続先のエラーをそのまま検出のエラーとして返す。
- 言葉で探せる(「カップ」「左の人の服」など)。言葉が無ければ、主な物を一通り挙げさせる。そのときは挙げる数の上限(20 個)を指示に入れる。
- 応答は JSON のスキーマで受ける。座標はモデルに 0〜1000 で答えさせ、3章の形に直す。範囲外の値と、空の四角は捨てる。画像は細部を見せる指定(OpenAI なら `detail: high`)で送る。
- 縦に長い物の下の端が短くなりがちなので(Context の確かめ)、候補は手で直す前提にする。四角を自動で広げることはしない(どの方向にどれだけ足りないかが物によって違う)。
- 外部の AI へ送る前の入口(ADR-0051)に、用途 `region_detection` を足す。接続先がローカル(ADR-0051 の接続先の区分)でも同じ入口を通す。
- **手元の VLM(後の段):** 手元の VLM のサーバー(OpenAI 互換の API)を LLM の接続先にすれば使えるようにする。モデルによって座標の形が違う(Qwen は `bbox_2d` の `[x0, y0, x1, y1]`、ほかに `[y0, x0, y1, x1]` のものがある)。構造化出力に対応しない接続のために、接続ごとに座標の形を選べるようにし、応答の JSON を緩く読む。どの形を選べるようにするかは、その段で手元のモデルで確かめてから決める。
- API は `POST /api/assets/{id}/regions/detect`(`require_user`。見える Asset だけ)。入力は任意の言葉。応答は候補の四角の一覧(四角、名前)。
- 検出は同期の要求で答える(10 秒を超えることがあるので、画面で待っていることを示し、取り消せるようにする)。
- **検出の履歴(2026-10-20 にユーザーの指示で足した):** 検出の結果は、Asset ごとに保存する。領域の画面を開き直したときに、検出し直さなくても前の候補を出せるようにするため。
  - 1回の検出を1行にする(探した言葉、接続先とモデル、候補の四角、日時、検出した利用者)。見つからなかった結果も残す。
  - 1つの Asset に残すのは新しい方から 20 回まで。超えたら古いものから消す。
  - 画面を開くと、最新の検出の候補を出す。履歴から前の検出に切り替えたり、消したりできる。検出のボタンは、いつも新しく検出する(前の結果を使い回さない)。
  - 見える範囲は Asset と同じ(ADR-0025)。検出が無効になっても、履歴は見られる。消せるのは、検出した本人と管理者。
  - 証跡ではない(ADR-0003 の来歴ではない)。系列の ZIP、共有リンク、Mod の `subject` には入れない。Asset を物理的に消すときは、一緒に消す。
- API: `GET /api/assets/{id}/regions/detections`(履歴、新しい順)、`DELETE /api/assets/{id}/regions/detections/{detection_id}`。検出の `POST` は、保存した行も返す。
- 画面では、候補を点線で出し、使う物をクリック(タッチ)で選ぶと札になる。
- `FAKE_PROVIDER=1` では、ダミーの検出(決まった位置の四角を返す)にする。

### 8. ほかの機能での扱い

- **再実行・パラメーターセット(ADR-0040):** 再実行では `run.regions` から四角を戻す。パラメーターセットには四角を入れない(四角は画像ごとのもの)。
- **MCP(ADR-0023):** Run を作るツールに `regions` を足す(REST と同じドメイン関数を通す)。検出のツールも足す。どちらも後の段でよい。
- **系列(ADR-0003)と系列の ZIP(ADR-0037):** `run.regions` は Run の記録として持ち出す。種類 `regions` の Asset は、スケッチと同じ扱いで系列に入れる。
- **Mod(ADR-0051):** `ai.before_send` の `subject` に、四角の数と指示(テキスト)を入れる(外へ送る中身なので、検査の対象にする)。四角の数は `region_count`、四角ごとの文は `text` の `region`(指示)と `region_text`(描く文字)。
- **埋め込みと自動タイトル・タグ(ADR-0033、ADR-0024):** 種類 `regions` の Asset は、埋め込みと、取り込み時の自動タイトル・タグの対象にしない(主たる入力とほぼ同じ絵で、重複の候補とマップを汚し、推定の費用もかかる)。2026-10-20 に足した。

### 9. ADR-0001 の扱い

- 非ゴール「高機能な画像編集」の但し書きに、「領域の指示の四角(ADR-0053)」を足す。四角は指示の範囲で、画像に描く図形ツールではない。
- 非ゴール「承認ワークフロー、コメント」に、四角の指示は人どうしのコメントではない(Run の入力の指示である)ことを注記する。

## Options Considered

| 案 | 判断 |
|---|---|
| A: どのモデルにも依らない四角のデータを持ち、渡すときにモデルごとに変換する | 採用。ComfyUI と同じ作り。新しいモデルには変換を足すだけでよい |
| B: 特定のモデルの形(FLUX 3 の 0〜1000 など)をそのまま持つ | 簡単だが、ほかのモデルに渡すときに形の間で変換することになり、元の値が分からなくなる |
| C: 四角をマスクに変えて渡す | 既存の Edit の入力で送れるが、四角ごとの指示を表せない |
| D: 四角を `run.params` だけに入れる | ADR-0003 4項に反する(API に送らない値を入れることになる)。ComfyUI と「画像と文」では、送る値と利用者が付けた四角が別の形になる |
| E: 四角を描いた画像をブラウザで作る(スケッチと同じ) | MCP と再実行で同じ画像を作れない。描くのはサーバーにする |
| F: 手元の検出に、イラスト向けの配布済みの検出モデル(YOLO 系)を任意のダウンロードで入れる | 見送り。表記が MIT でも、学習の仕組み(Ultralytics)が学習したモデルにも AGPL-3.0 が及ぶと主張している。GPL・AGPL を明示したもの(YOLOv6・v7・v9、YOLO-World、YOLOE など)と、重みが非商用のもの(YOLO-NAS)と、学習データが学術利用に限られるもの(Manga109 など)も使わない |
| G: 手元の検出に、写真向けの検出器(COCO の 80 種類。RT-DETR、D-FINE、RF-DETR、YOLOX など。Apache-2.0)を使う | 見送り。ライセンスは緩いが、イラストでは見落としが多い。言葉で探せない |
| H: RF-DETR(Apache-2.0)をイラストで学習し直して配る | 見送り。学習データの用意(権利の確認と注釈)に時間がかかる。配る重みを作るのは開発の範囲を超える(ADR-0001 はモデルの学習を非ゴールにしている) |
| I: 手元の検出に、言葉で探せる小さなモデル(Florence-2 など)を同梱する | 見送り。CPU で数秒以内に答えるのが難しい。手元で動かすなら、手元の VLM のサーバーを LLM の接続先にすれば済む(7章) |
| J: 手元の VLM(Qwen3-VL、Qwen3.5 など)を LLM の接続先として使う | 採用(後の段)。新しいモデルの置き場を作らずに済み、言葉でも探せる。サーバーは利用者が別に立てる |

## Trade-off Analysis

- 「画像と文」は、四角を学習していないモデルに伝える苦肉の策で、効き方は保証しない。docs に、効きやすい書き方と、効かないことがあることを書く。画面では、この渡し方であることを示す。
- 検出を VLM だけにしたので、自動で検出するには VLM の接続が要る。外部の VLM なら画像を外へ送り、費用もかかる。手元の VLM なら外へは送らないが、サーバーを別に立てる手間がかかる。検出は四角を付けるときの下書きで、無くても手で描けるので、この差は利便性の差にとどまる。
- 検出の結果は Asset ごとに保存するので、同じ画像の候補を出し直すのに費用はかからない。表が1つ増え、Asset を物理的に消す処理に加える必要がある。1つの Asset あたり 20 回までに抑える。
- ComfyUI の Create Bounding Boxes は本体に入って日が浅く、値の形が変わることがある。後の段で、差し込みの形を1か所に閉じ込め、形が変わったら分かるように失敗させる。

## Consequences

- Run に列が1つ増える(`run.regions`。マイグレーション)。検出の履歴の表が1つ増える(`asset_region_detection`。マイグレーション)。Asset の種類が1つ増える(`regions`)。種類を列挙している場所を直す。
- ADR-0051 の用途が1つ増える(`region_detection`)。値の追加なので、Mod の契約の版は上げない(docs/mods.md の規則)。
- 新しいモデルの置き場とダウンロードは増えない。
- 新しいプロバイダー(FLUX 3 など)を足すときに、四角の渡し方を変換として足せばよい。
