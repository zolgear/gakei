# ADR-0041: タグ辞書(タグの補完と日本語訳)

**Status:** Proposed
**Date:** 2026-10-10

## Context

SD WebUI(ADR-0038)の利用者の多くは、拡張機能 a1111-sd-webui-tagcomplete(Tag Autocomplete)を使い、Danbooru 系のタグを補完しながらプロンプトを書いている。この拡張機能は、配布されている辞書の CSV を読み込み、入力中の文字に合うタグを、カテゴリーの色・件数・別名・日本語訳と一緒に候補として出す。日本語で打って英語のタグを出すこともできる。

GAKEI には、プロンプトのタグ編集(ADR-0039)と、その候補(WD Tagger の語彙、約 1 万 1 千語)がある。ADR-0039 は「語彙の翻訳(日本語で打って英語のタグを出す)」と「WD Tagger 以外の語彙の取り込み」を作らないとしていた。2026-10-10 にユーザーから、Tag Autocomplete に類する機能として、辞書ファイルを登録し、タグの補完と日本語訳に使いたいと要望があった。WD Tagger のタグ(ADR-0024)の翻訳にも使えるか検討したい、とのこと。

辞書の形式(Tag Autocomplete の配布物で確認。2026-10-10):

- **タグの一覧:** ヘッダーなしの CSV、4 列。`タグ名, カテゴリー, 件数, 別名`。タグ名は `_` 区切り(`long_hair`)。別名は 1 つの欄にカンマ区切り(引用符で囲む)。Danbooru のカテゴリーは 0 一般、1 作者、3 作品、4 キャラクター、5 メタ。約 31 万行、約 8.7MB。
- **翻訳:** ヘッダーなしの CSV、2 列。`タグ名, 訳`。訳は 1 つの欄にカンマ区切りで複数あり、先頭が代表。約 4.2 万行、約 2MB。改行は CRLF のことがある。
- 両方を zip にまとめて配布されることがある。他のサイト(e621 など)の辞書も同じ 4 列の形だが、カテゴリーの番号の意味が違う。
- 辞書のデータは利用者が用意する。GAKEI のリポジトリには入れない(配布の条件は辞書ごとに違う)。

## Decision

### 1. 辞書の登録(管理者設定)

- 管理者設定に「タグ辞書」のページ(`/settings/tag-dictionary`)を足す。CSV か、CSV を含む zip をアップロードする。
- **種類は列の数で判定する。** 4 列ならタグの一覧、2 列なら翻訳。判定できない行が多いファイルは断る。zip の中は CSV だけを読み、ほかは無視する。展開後の合計の大きさに上限を設ける(例 100MB。zip 爆弾を防ぐ)。
- タグの一覧には「カテゴリーの体系」を持たせる(既定 `danbooru`。色と名前の対応に使う。今は danbooru だけ。他は番号のまま出す)。
- 登録した辞書は一覧で見せ(ファイル名、種類、行数、登録日時)、有効/無効の切り替えと削除ができる。複数の辞書を登録でき、有効なものを合わせて使う(同じタグは件数の多い方、翻訳は先に登録したものを優先)。
- 取り込みは時間がかかる(数十万行)ので、アップロードの後にプロセス内で行い、状態(取り込み中、完了、失敗)を画面に出す。取り込み中は前の辞書のまま動く。
- 保存先は DB のテーブル(`tag_dictionary`、`tag_dictionary_entry`、`tag_dictionary_alias`、`tag_dictionary_translation`)。前方一致の検索に索引を張る。PostgreSQL でも動くこと(ADR-0027)。辞書は証跡ではないので、削除は物理削除でよい。アップロードしたファイルそのものは保存しない。
- 辞書はインスタンス全体で共有する(利用者ごとではない)。登録と削除は管理者だけ。

### 2. 補完(候補)

- ADR-0039 の候補の API(`GET /api/tags/suggestions`)を、辞書があれば辞書で答えるように広げる。辞書が無ければ、これまでどおり WD Tagger の語彙と GAKEI のタグ。
- 1 件ごとに返すもの: タグ名(`_` を空白にしたもの)、カテゴリー、件数、代表の訳、一致の種類(タグ名・別名・訳)と、別名や訳で一致したときはその語(「別名 → タグ」と見せるため)。
- 一致の順: タグ名の前方一致 → 別名の前方一致 → 訳の前方一致 → 訳の部分一致。同じ段の中は件数の多い順。**日本語で打つと、訳から英語のタグを出す。** 最大 20 件。
- 候補の画面: カテゴリーの色の印(Tag Autocomplete の配色に近いもの。色だけに頼らずカテゴリー名も title に)、件数(短く。例 1.2M)、訳を小さく添える。

### 3. テキストモードでの入力アシスト

- タグモード(ADR-0039)のチップの入力欄に加え、**テキストモードのプロンプト欄でも**、カンマで区切られた入力中の語(キャレットの位置の語)に候補を出す。選ぶとその語をタグで置き換え、`, ` を補う。括弧のエスケープは ADR-0039 と同じ規則。
- 既存の `@` でのプロンプトセットの呼び出し(ポップオーバー)と同じ出し方・キー操作(↑↓、Enter/Tab で確定、Esc で閉じる)にする。`@` の呼び出しとはぶつからないこと。
- 文章で書くモデルで邪魔にならないよう、ユーザー設定(表示)に「プロンプトのタグ補完」を置く: 「SD WebUI と ComfyUI のときだけ」(既定)、「常に」、「使わない」。タグモードのチップの入力欄では、設定に関わらず候補を出す(ADR-0039 のまま)。
- `<lora:` と打ったら、SD WebUI の LoRA の一覧(ADR-0038 8章)から候補を出す(SD WebUI のときだけ)。

### 4. 日本語訳の表示

- タグモードのチップ、候補、Asset のタグ(ADR-0024 のチップ)に、辞書に訳があれば小さく添える(タグそのものは変えない)。画面の言語が日本語のときだけ。ユーザー設定で消せる。
- 訳はタグの表記を変えない、表示だけの補助。Run に送るプロンプトにも、Asset のタグにも入らない。

### 5. WD Tagger のタグの翻訳(ADR-0024 6章との関係)

- ADR-0024 6章の `tag_language = localized` では、WD Tagger の英語のタグの訳を VLM か LLM で作り、タグとして足している。**辞書に訳があるタグは、辞書の代表の訳を使い、LLM を呼ばない。** 辞書に無いタグだけを従来どおり LLM に頼む(LLM が無効なら訳さない)。
- 辞書の訳は長い作品名などを含むことがあるので、タグとして足す訳は 1 語の長さ(ADR-0024 のタグの上限)に収まるものだけにする。
- 既に付いている訳のタグは変えない(再推定のときに、ADR-0024 の規則で入れ替わる)。

### 作らないもの

- 辞書の配布やダウンロード(利用者がファイルを用意する)
- 利用者ごとの辞書、辞書の中身の編集画面
- ワイルドカード(`__name__`)の補完(WebUI 側のファイルが見えないため)
- タグの意味の説明(wiki)の表示
- 英語以外への翻訳(訳の CSV を登録すれば、その言語の訳として表示はできるが、言語の区別は持たない)

## Options Considered

### 辞書の置き場所

| 案 | 評価 |
|---|---|
| A: DB のテーブルに取り込む(採用) | 前方一致を索引で引け、プロセスが複数でも同じ。メモリを使わない。取り込みに時間がかかる |
| B: CSV をファイルで保存し、起動時にメモリに読む | 実装は小さいが、31 万行で数十〜100MB のメモリを常に使う。Raspberry Pi などの小さい環境で重い |

### テキストモードでの補完

| 案 | 評価 |
|---|---|
| A: ユーザー設定で、既定は SD WebUI と ComfyUI のときだけ(採用) | タグで書くことの多いプロバイダーで自然に出て、OpenAI の文章では邪魔にならない |
| B: モデルごとに覚えたタグモード(ADR-0039)のときだけ | 判定は正確だが、テキストモードで書く人には出ない |
| C: 常に出す | 文章のプロンプトで、単語ごとに候補が出て邪魔 |

## Consequences

- ADR-0039 の「作らないもの」から、語彙の翻訳(日本語で打って英語のタグを出す)と、WD Tagger 以外の語彙の取り込みを外す。
- ADR-0024 6章の訳の作り方に、辞書を先に使う規則が加わる。LLM の呼び出しが減る。
- 新しいテーブルとマイグレーションが要る。証跡のモデルには触れない。
