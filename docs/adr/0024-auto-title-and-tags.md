# ADR-0024: タイトルとタグ(人の編集と、LLM・VLM・ONNX タガーによる自動付与)

**Status:** Proposed
**Date:** 2026-09-28

2026-09-28 にユーザーが次の3点を決めた。推定には VLM とホスト内の ONNX タガーの両方を使う(3章)。取り込み時の自動実行と一括実行の両方を用意する(4章)。人も編集でき、自動で付いたものは見た目で区別する(2章)。同日、自動のタグは色とデザインで表し「自動」の文字は出さないこと、タイトルは Open WebUI のようにプロンプトから LLM で推測することを追加で指示された(2章、3章)。同日、この内容(ADR-0001 の非ゴール表の改訂を含む)がユーザーに承認された。

## Context

ストックが増えると、画像を探す手がかりがプロンプトしかない。アップロード画像には、そのプロンプトすら無いことが多い。他のツールの埋め込みメタ情報(ADR-0018)が無い画像も多い。現在の Asset には名前もタグも無く、キーワード検索の対象は Run のプロンプトと埋め込みメタ情報だけになっている。

ADR-0001 は「自動タグ付け」を「類似画像検索、自動品質採点」と並べて Phase 3 以降の非ゴールとしていた。この ADR はそのうち自動タグ付けだけを前倒しし、ADR-0001 の非ゴール表を改める。類似画像検索(埋め込みベクトルによる検索)と自動品質採点は引き続き作らない。

Issue [#5](https://github.com/zolgear/gakei/issues/5)。

## Decision

### 1. 範囲

- Asset に **タイトル**(1 つ)と **タグ**(複数)を持たせる。対象は生成画像、アップロード画像、スケッチ。マスクは対象外。
- タイトルとタグは **人が付けられる**。そのうえで **自動で推定する** 仕組みを足す。
- タイトルとタグは証跡ではない。ADR-0003 の「採用/不採用とタグは証跡ではないので更新可」に従い、更新と削除ができる。来歴の列(`asset`、`run`、`run_input`)には書き込まない。
- **埋め込みベクトルは保存しない。** CLIP による分類や類似検索には広げない(ADR-0001 の非ゴールを守る)。
- 推定結果をもとにグループ(ADR-0022)へ自動で振り分ける機能は作らない。タグで絞り込み、選んだ画像をグループへ移す操作で足りるとする。

### 2. 人の編集と自動の区別

- 自動で付いたタイトルとタグには `source = auto` を記録する。人が付けたものは `source = user`。
- 画面では **色とデザインで区別し、「自動」などの文字のラベルは出さない。** 例として、自動のタグは淡い色と点線の枠のチップ、人のタグは塗りのチップにする。自動のタイトルは控えめな色で出す。色だけに頼らないよう、枠線の形も変える。自動の結果は正しいとは限らないことを、見た目で示すための区別。
- **人の判断を優先する。** 人がタイトルを編集すると `user` になり、以後の再推定でも上書きしない。
- 人が自動のタグを消した場合も、そのことを記録する。同じタグを再推定で付け直さない。
- 人がタグを足した場合、そのタグは `user` になる。
- 再推定では、`auto` のタイトルと、人が消していない `auto` のタグだけを入れ替える。
- 編集できるのは、その Asset が見える利用者(ADR-0025。認証モードでは本人だけ。見えない Asset は 404)。タグの一覧と件数も、本人に見える Asset だけで数える。一括実行と設定の変更は管理者だけ。一括実行の推定は Asset に対する処理なので全 Asset を対象にし、未実行の件数もインスタンス全体で数える(画面に他人のタイトルやタグは出ない)。

```
asset_annotation(
  asset_id UUID PK FK asset.id,
  title VARCHAR(200) NULL,
  title_source VARCHAR(8) NULL,         -- auto | user
  auto_status VARCHAR(16) NULL,         -- queued | running | succeeded | failed(NULL は未実行)
  auto_engines VARCHAR(32) NULL,        -- 実行したエンジン(vlm、onnx、vlm+onnx)
  auto_models JSON NULL,                -- 使ったモデル名(例 {"vlm": "...", "onnx": "wd-vit-tagger-v3"})
  auto_error VARCHAR(500) NULL,
  auto_requested_at TIMESTAMPTZ NULL,
  auto_finished_at TIMESTAMPTZ NULL,
  updated_at TIMESTAMPTZ NOT NULL
)

tag(
  id UUID PK,
  name VARCHAR(100) NOT NULL UNIQUE,    -- NFKC、前後の空白除去、小文字化した表記
  created_at TIMESTAMPTZ NOT NULL
)

asset_tag(
  asset_id UUID FK asset.id,
  tag_id UUID FK tag.id,
  source VARCHAR(8) NOT NULL,           -- auto | user
  score FLOAT NULL,                     -- ONNX タガーの確信度(VLM と人は NULL)
  removed BOOLEAN NOT NULL,             -- 人が消した(再推定で付け直さない)。画面には出さない
  created_at TIMESTAMPTZ NOT NULL,
  PRIMARY KEY (asset_id, tag_id)
)
```

### 3. 推定のエンジン

タイトルとタグで、使うエンジンを分ける。どのエンジンも管理者設定でそれぞれ有効にする。

| エンジン | 付けるもの | 入力 | 実行場所 | 費用 |
|---|---|---|---|---|
| **LLM**(テキスト) | タイトル | プロンプト | OpenAI 互換 API(OpenAI、または手元の Ollama・LM Studio など) | 従量課金。短い文章だけなので安い |
| **VLM** | タグ。プロンプトが無い画像にはタイトルも | 画像(と、あればプロンプト) | 同上 | 従量課金(手元のサーバーなら無料) |
| **ONNX タガー**(WD Tagger v3) | タグ | 画像 | GAKEI のプロセス内(onnxruntime、CPU) | 無料。モデルのダウンロード(数百 MB)が要る |

VLM と ONNX タガーを両方有効にすると、両方のタグを合わせて付ける。

**タイトル(LLM):**
- Open WebUI が最初のメッセージから会話のタイトルを作るのと同じく、プロンプトから短いタイトルを LLM に推測させる。
- 生成画像では Run のプロンプトを使う。1 回の Run に 1 回だけ呼び、その Run の出力すべてに同じタイトルを付ける。アップロード画像では、埋め込みメタ情報のプロンプトを使う。
- プロンプトが無い画像(多くのアップロード画像)は、VLM が有効なら VLM が画像から付ける。VLM も無効なら、タイトルは付けない。
- タイトルは 30 文字程度までとし、言語は設定で選ぶ。
- モデル名は VLM とは別に設定できる。既定は `gpt-5.6-luna` を候補とし、実装時に公式ドキュメントで確かめる。

**VLM と LLM の接続:**
- 接続先は、既定では OpenAI の設定(キー、Base URL。ADR-0017)を使う。手元の VLM サーバーを使うときは、推定専用の Base URL とキーを別に設定できる。
- 接続先の既定と別指定の仕組みは、LLM と VLM で共通。
- 呼び出しは Responses API を既定とし、Chat Completions も選べる(手元のサーバーには Chat Completions しか持たないものがあるため)。
- モデル名は設定で変えられる。既定のモデルは、実装時に公式ドキュメントで画像入力に対応していることを確かめて決める。
- 送るのは 1024px 以内に縮めた画像。原本は送らない。
- 手がかりとして、生成画像なら Run のプロンプト、アップロード画像なら埋め込みメタ情報のプロンプトも送る。
- 応答は JSON(タグ最大 10 個。プロンプトが無い画像ではタイトル 1 つも)で受ける。
- タイトルとタグの言語は設定で選ぶ(既定は日本語)。

**ONNX タガー:**
- SmilingWolf の WD Tagger v3(Apache-2.0)を使う。対象はイラスト向けで、写真には向かない。これは設定画面に明記する。
- モデルは次の 3 つから選ぶ。
  - `wd-vit-tagger-v3`(既定、約 380MB)
  - `wd-swinv2-tagger-v3`
  - `wd-eva02-large-tagger-v3`(約 1.3GB)
- モデルは配布物に含めない。管理者が設定画面のボタンで Hugging Face からダウンロードし、`DATA_DIR/models/` に置く。取得元のリビジョンを固定し、ハッシュを確かめる。
- タグは英語で、`_` を空白に置き換える。確信度がしきい値(既定 0.35)以上の一般タグとキャラクタータグを、多い順に最大 20 個付ける。rating(年齢区分)のタグは付けない。
- `onnxruntime` を通常の依存に加える(aarch64 と x86_64 と Windows に wheel があり、約 20MB)。モデルは初回の推定で読み込み、しばらく使わなければ解放する。

### 4. 実行のタイミング

- **取り込み時の自動実行:** 管理者設定でオンにすると、生成の出力、アップロード、スケッチの取り込みのたびに推定を待ち行列に入れる。既定はオフ。
- **一括実行:** 管理者設定から、推定を一度も実行していない画像(削除済みを除く)をまとめて待ち行列に入れる。実行前に件数を示す。
- **1 枚ずつの再推定:** Asset の詳細から実行する。人が決めたタイトルやタグは保つ。
- 待ち行列は `asset_annotation.auto_status = 'queued'` の行そのもの。Run と同じく、プロセス内の worker が 1 件ずつ処理する(ADR-0005、ADR-0008 と同じ構成)。起動時に `running` の行を `queued` に戻す。
- 推定は Run ではない。画像 API の実行ではなく、来歴にも加わらないため。
- VLM の呼び出しには 1 時間あたりの上限を設ける(既定 100 件)。上限に達すると失敗にはせず、次の枠まで待つ。
- 推定に失敗したときは `failed` と理由を記録し、自動では再試行しない。

### 5. 検索と画面

- **検索:** キーワード検索の対象にタイトルとタグ名を加える。ストックに「タグで絞り込む」を足す。MCP の `search_assets` にもタグの絞り込みを加え、`get_asset` はタイトルとタグ(`source` 付き)を返す(ADR-0023)。MCP からの書き込みは今回は提供しない。
- **ストックと履歴のカード:** タイトルがあれば出す。
- **Asset の詳細(ビューアの情報欄):** 次を置く。
  - タイトルの編集
  - タグの追加と削除
  - 推定の状態
  - 再推定のボタン
  
  自動と人の区別は 2 章の見た目で示す。
- **管理者設定 →「自動タイトル・タグ」:** 次を設定する。
  - 取り込み時の自動実行
  - LLM(タイトル)と VLM(タグ)の有効化、それぞれのモデル、共通の接続先、API 形式、言語、1 時間の上限
  - ONNX タガーの有効化、モデルの選択とダウンロード、しきい値
  - 未実行の件数と一括実行
- LLM と VLM を有効にする画面には、プロンプトや画像が外部の API に送られることを書く。

### 6. タグの言語と重複(2026-09-28 追記、実機テストを受けて)

実機のテスト(Issue #5 のコメント)で、ONNX の英語タグと VLM の日本語タグが同じ意味で重複した(candy とキャンディ、halloween とハロウィン)。同日、ユーザーは、日本語のタグが付いたのは良かったとして、タグの言語を設定で選べるようにし、ローカライズするなら英語のタグを訳して足すよう指示した。

- **タグの言語は設定で選ぶ**(管理者設定 `tag_language`、既定 `localized`)。
  - `native`(エンジン任せ): 各エンジンがそれぞれの言語でタグを付ける。WD Tagger は英語のまま。VLM にはタグの言語を指定しない。翻訳はしない。
  - `localized`(ローカライズ): 3章の言語の設定(`language`)に合わせる。VLM のタグは `language` で付ける。WD Tagger の英語のタグは残し、その訳をタグとして足す(`language` が英語なら訳さない)。
    - VLM が有効なら、ONNX のタグの訳も同じ VLM の呼び出しで返させる(API の呼び出しを増やさない)。このとき VLM には、訳と同じ意味の新しいタグを付けないよう頼む。
    - VLM が無効で LLM が有効なら、LLM(テキスト)で ONNX のタグを訳す。この呼び出しも 1 時間の上限に数える。
    - どちらも無効なら訳さない(英語のタグだけ)。
  - 訳したタグは `source = auto` で、`score` は元の ONNX のタグの値を引き継ぐ。
- **VLM は ONNX のタグと重複させない。** ONNX と VLM を両方有効にしたときは、ONNX を先に動かし、その結果のタグを VLM に渡す。VLM には、同じ意味のタグを別の言語で付け直さず、足りない観点だけを付けるよう頼む(`native` でも同じ)。
- **待ち時間を減らす。** LLM(タイトル)は ONNX と並行して動かし、VLM(または翻訳の LLM)は ONNX の後に動かす。どれか 1 つが失敗したら全体を `failed` にする(4章)。ONNX のモデルの読み込みと推論は別スレッドで行い、推論のスレッド数は CPU コア数の半分に抑える(API の応答を妨げないため)。
- タグとタイトルは利用者のデータで、画面の文言ではない。そのため言語ファイル(ADR-0015)には載せず、画面の言語を切り替えても変わらない。
- タイトルは、LLM の出力からマークダウンの記号(強調、見出し)、前後の引用符・かぎ括弧、末尾の句点を取り除いてから保存する(出力が揺れるため、プロンプトの指示だけに頼らない)。

### 7. ONNX タガーのメモリ(2026-09-29 追記)

メモリ 4GB・GPU なしの VM で `wd-eva02-large-tagger-v3` を選んだところ、読み込みで OOM になり GAKEI のプロセスが落ちた。落ちると処理中の行が `running` のまま残り、起動時に `queued` に戻る(4章)ので、同じモデルを読み込んでまた落ちるおそれがある。

- onnxruntime のセッションは、重みの prepacking とメモリパターンを切って作る。実測(Raspberry Pi 5)で最大 RSS が 25〜33% 下がり、推論時間の増加は 5〜10%、タグは変わらなかった。
- 各モデルにメモリの目安を持たせ、設定画面のモデルの選択肢に出す。GPU の無い環境では `wd-swinv2-tagger-v3` を推奨すると書く。既定のモデルは変えない。
- モデルを読み込む前に空きメモリ(Linux の MemAvailable と cgroup の上限の残り)を目安と比べ、足りなければ読み込まずにその推定を `failed` にする(理由を記録し、自動では再試行しない。4章のとおり)。空きメモリを読めない環境では確かめない。4章の「起動時に `running` の行を `queued` に戻す」は変えない。

### 8. 接続先とモデルの組、ComfyUI の画像の上書き(2026-09-30 追記)

ComfyUI(ADR-0013)の画像は、基本的に手元の GPU で作る。ところが推定の LLM と VLM の接続先は1組だけで(3章)、既定では OpenAI の設定を使う。そのため、手元で作った画像とプロンプトも OpenAI に送られる。推定専用の接続先を手元のサーバーにすると、今度は OpenAI で作った画像まで手元のサーバーで推定することになる。

2026-09-30 にユーザーが次のように指示した(Issue [#41](https://github.com/zolgear/gakei/issues/41))。
- ComfyUI の画像では、推定の LLM を上書きし、手元の LLM を指定できるようにする。
- 設定の配置は整理する。
- LiteLLM のような中継サーバーを使うなら、接続先は1つで、モデル名を変えるだけで足りる。一方、Ollama などでは接続先とモデルが組になる。その両方を想定する。

同日、この章の内容がユーザーに承認された。

#### 接続先(一覧)

- 推定の接続先を、名前付きで複数登録できるようにする。項目は次の4つ。
  - 名前
  - Base URL
  - キー(任意)
  - API 形式(Responses / Chat Completions)
- 組み込みの接続先「OpenAI の設定」を1つ持つ。これは ADR-0017 のキーと Base URL をそのまま使い、編集も削除もできない。
- キーは、今の推定専用キーと同じく DB ではなく `DATA_DIR` のファイルに置き(接続先ごとに1つ)、画面には値を出さない。キーが無ければ、今と同じくダミーのキーを送る。
- どこかで使っている接続先は削除できない。

#### 使い方(用途ごとに「接続先 + モデル名」を選ぶ)

- 用途は、タイトル(LLM)とタグ(VLM)の2つ。それぞれで、接続先とモデル名を組にして選ぶ。
  - LiteLLM など中継サーバーを使う場合: 接続先は同じものを選び、モデル名だけを変える。
  - Ollama などを使う場合: 用途ごとに別の接続先を選べる。
- **既定:** すべての画像に使う組。今の設定(3章)はこれに当たる。
- **ComfyUI の画像:** ComfyUI の Run(`run.provider = 'comfyui'`)の出力にだけ使う組。
  - 用途ごとに「既定と同じ」か、別の組を選ぶ。既定は「既定と同じ」。
  - アップロード、スケッチ、ほかのプロバイダーの画像は、常に「既定」を使う。
  - ComfyUI を接続していなくても設定できる。切り離した後も、過去の ComfyUI の画像を再推定できるようにするため。
- タグの訳を LLM で作るとき(6章)は、その画像に使うタイトルの組を使う。
- LLM と VLM を使うかどうか(有効化)、言語、タグの言語、1時間の上限の値、ONNX タガーは、今までどおり全体で1つ。

#### 送り先を混ぜない

- ComfyUI の画像で別の組を選んだら、その画像は既定の組の接続先には送らない。
- 別の組の接続先で失敗しても、既定の組には切り替えない。その推定は `failed` にする(4章)。

#### 1時間の上限

- 回数は接続先ごとに数える。手元のサーバーへの呼び出しで、OpenAI への呼び出しの枠を使わないようにするため。
- 上限の値は、共通の `hourly_limit` を使う。

#### 記録

- 推定の記録には、実際に使ったモデル名を残す。

#### 設定画面の配置

管理者設定の「自動タイトル・タグ」を、次の順に並べ直す。

1. 有効化と実行
   - 取り込み時の自動実行
   - LLM と VLM の有効化
   - 未実行の件数と一括実行
2. 接続先: 一覧と、追加・編集・削除
3. 使い方: 行がタイトル(LLM)とタグ(VLM)、列が「既定」と「ComfyUI の画像」の表。各マスで、接続先とモデル名を選ぶ。狭い幅(768px 未満)では、列ごとに縦に積む。
4. 言語: タイトルとタグの言語、タグの言語
5. 1時間の上限
6. ONNX タガー

画面には、選んだ接続先に画像とプロンプトが送られることを書く。

#### 今の設定からの移行

- マイグレーションで、今の設定を新しい形に移す。
  - 推定専用の Base URL が設定されていれば、接続先「推定専用」を1件作る。今のキーと API 形式もこの接続先に移す。
  - 今の LLM と VLM のモデル名を、「既定」の組のモデル名に入れる。接続先は、「推定専用」を作った場合はそれ、作らなかった場合は「OpenAI の設定」にする。
- 移行した後も、推定の結果は今と変わらない。

## Options Considered

### タイトル: 画像から VLM で作るか、プロンプトから LLM で作るか
プロンプトがある画像では、プロンプトが作者の意図そのもので、テキストだけの LLM は安く速い。ユーザーの指示(Open WebUI と同じ感じ)に従い、プロンプトからの推測を主とし、VLM はプロンプトが無い画像の補いに回す。

### Option A: VLM だけ
**Pros:** 依存が増えない。タイトルも作れ、写真にも使える。
**Cons:** OpenAI を使うと 1 枚ごとに課金される。手元で動かすには別に VLM サーバーを用意する必要がある。

### Option B: ONNX タガーだけ
**Pros:** 無料で、外部に画像を出さない。
**Cons:** タイトルを作れない。イラスト向けで、写真には向かない。

### Option C: VLM と ONNX タガーの両方(採用)
**Pros:** 費用と品質の兼ね合いを利用者が選べる。イラストは無料のタガーで、写真やタイトルは VLM でと使い分けられる。
**Cons:** 設定項目と依存(onnxruntime)が増える。

### CLIP によるゼロショット分類
語彙を決めておけば CLIP で画像ごとのタグを選べる。ただし語彙の管理が要り、埋め込みを保存すると類似検索に近づくので採らない。

## Trade-off Analysis

決め手はユーザーの判断で、費用をかけずに済む手段(ONNX タガー)と、タイトルを作れる安い手段(プロンプトからの LLM)を用意し、写真などに VLM を使えるようにする。代わりに設定画面は大きくなる。両エンジンとも既定では無効で、取り込み時の自動実行も既定でオフなので、有効にするまで費用も依存の読み込みも発生しない。人の判断を優先する規則により、自動の結果が人の整理を壊すことはない。

## Consequences

- ストックをタイトルとタグで探せるようになる。
- 依存に `onnxruntime`(と、それが引き込む `numpy`)が加わる。Docker イメージも同じだけ大きくなる。モデル本体は `DATA_DIR` に置く。
- DB に `asset_annotation`、`tag`、`asset_tag` が加わる。既存の Asset はタイトルもタグも無い状態から始まる。
- LLM と VLM を OpenAI で使うと、呼び出しごとに課金される。
- ADR-0001 の非ゴール表から「自動タグ付け」を外す。
