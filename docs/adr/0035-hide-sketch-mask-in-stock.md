# ADR-0035: スケッチとマスクをストックに出すかを選べるようにする(既定は出さない)

**Status:** Proposed
**Date:** 2026-10-04

Issue #11。スケッチとマスク(`kind = sketch` / `mask`)を、ストックに出すかどうかを利用者が選べるようにする。既定は「出さない」。

## Context

- スケッチとマスクは、エディタで保存した時点で Asset になる(ADR-0010。`POST /api/assets`)。
  - どちらも生成の途中で使う補助の画像である。
  - 使用済みのものは証跡として残るので、作業を続けるほどストックに溜まる。
  - 作品や素材(`generated` / `upload`)と同じ一覧に並ぶと、一覧が散らかる。
- 現状は次のとおり。
  - ストックのパネルは既定(種類「すべて」)で 4 種類をすべて出す。種類のチップには「スケッチ」「マスク」がある(ADR-0010、ADR-0022 4章)。
  - ストックピッカー(入力画像の追加とアバターの選択)は、マスクをクライアント側で除いている。スケッチは常に出る。
  - グループの `member_count` と `cover_asset_id` は、種類を問わずに数える(ADR-0022)。
- ADR-0003 により、画像と `run_input` の記録は変えない。変えるのは見せ方だけである。
  - スケッチとマスクは Run の入力として記録されている。
  - そのため、ストックに出さなくても、系列グラフと Run 詳細の入力から辿って開ける。
- サーバーには、ユーザーごとの設定を持つ仕組みが無い。
  - `app_user` に設定の列が無い。個人モードでは `app_user` の行も作られない。
  - 表示の好みは、どれもブラウザ(localStorage)に持っている。ADR-0031 は「表示」ページの項目をすべて「即時」(ブラウザに保存してその場で反映)とする。

## Decision

### 1. 設定

- ユーザー設定の「表示」ページに、スイッチ「スケッチとマスクをストックに出す」を足す。
  - 既定はオフ。
  - ADR-0031 の「即時」の項目にする。保存ボタンは出さず、切り替えるとストックがその場で変わる。
- 値はブラウザの localStorage(`gakei:stock-show-sketch-mask`、真偽)に持つ。
  - 既存の表示の好み(`faviconPrefs.ts` など)と同じ作りにする。
  - 「ブラウザに保存した設定」を消す操作(ADR-0031)の対象にも入る。
  - 端末ごとの設定になる。ログインしていても、別のブラウザでは既定(オフ)に戻る。

### 2. API

- `GET /api/assets` の `kind` を、繰り返して指定できるようにする(`?kind=generated&kind=upload`)。
  - 指定した種類のどれかに当たる Asset を返す。
  - 1 つだけの指定は従来どおり動く。
  - 省いたときは従来どおり全種類を返す。API の既定は変えない。MCP や既存の呼び出し元の挙動は変わらない。
- `GET /api/asset-groups` に、同じ形の `kind`(繰り返し可、任意)を足す。
  - 指定したときは、`member_count` と `cover_asset_id` をその種類だけで数える。
  - 省いたときは従来どおり、種類を問わない。
- 除くのはサーバーの問い合わせで行う。
  - 一覧はカーソル方式のページングである。クライアント側で除くと、1 ページの件数が減ってしまう。
  - そのため、フロントは見せる種類を `kind` で明示して取る。

### 3. 画面

- **ストックのパネル**: 設定がオフのときは次のとおりにする。
  - 種類のチップから「スケッチ」「マスク」を外す。
  - 「すべて」は `kind=generated&kind=upload` で取る。
  - グループの節も同じ種類で取る。見出しの件数と表紙は `GET /api/asset-groups?kind=generated&kind=upload` の値を使い、出しているタイルの数と合わせる。
  - 設定がオンのときは従来どおりにする(チップは 5 つ、`kind` を省く)。
  - 「スケッチ」「マスク」のチップを選んだ状態で設定をオフにしたときは、「すべて」に戻す。
  - 件数を種類のチップに合わせることはしない。件数は「その設定で出す種類の合計」で、チップの選択では変わらない(従来どおり)。
- **ストックピッカー**: マスクは従来どおり常に出さない。
  - スケッチは設定に従う。
  - 一覧も、設定に応じた種類を `kind` で明示して取る。クライアント側でのマスクの除外は、サーバーでの除外に置き換える。
  - 検索欄に入力したときの結果(`GET /api/search`)は、クライアント側で同じ種類に絞る(従来の kind での絞り込みと同じ)。
- 系列グラフ、Run 詳細の入力、ビューアは変えない。設定がオフでも、そこからスケッチとマスクを開ける。

### 4. 対象にしないもの

- 検索(キーワード、文章、画像、似た画像)、マップ、重複、履歴、MCP は変えない。
  - 検索は利用者が明示して探す操作なので、当たったものを出す。
  - マップ、重複、文章での検索、似た画像は、すでにマスクを除いている。スケッチは埋め込みの対象で、従来どおり出る。
  - 履歴は Run の一覧で、スケッチとマスクを一覧の行としては出さない。
  - MCP の `search_assets` は、`kind` を省けば従来どおり全種類を返す。
- 既存のスケッチとマスクは、消しも移しもしない。設定をオンにすれば再び見える。
- サーバー側のユーザーごとの設定(テーブルと API)は作らない。表示の好みは、他と同じくブラウザに持つ。

## Options Considered

| 案 | 評価 |
|---|---|
| **A. localStorage の即時の項目、API は `kind` の複数指定(採用)** | ADR-0031 の「表示」ページの規則に揃う。API の既定を変えないので、MCP と既存の呼び出し元に影響しない。サーバーで除くので、ページングが崩れない |
| B. サーバーにユーザーごとの設定を持つ | 端末をまたいで同じ設定になる。しかし、新しいテーブルと API が要り、個人モード(`app_user` の行が無い)の扱いも決めなければならない。表示の好み 1 つのためには重い |
| C. `GET /api/assets` の既定を `upload,generated` にする | フロントの変更は少ない。しかし、API の意味が変わり、MCP や外部の呼び出し元からスケッチとマスクが黙って消える。設定(ブラウザ側)とも結び付かない |
| D. フロントで取得後に除く | API を変えずに済む。しかし、カーソル方式のページングで 1 ページが薄くなる。スケッチだけが続くと、空のページが続く |
| E. `exclude_kind` を足す | 実現できる。しかし、`kind` の複数指定のほうが、見せる種類をそのまま書けて分かりやすい。グループの件数の問い合わせにも同じ形で使える |

## Trade-off Analysis

- 設定は端末ごとである。別の端末では、既定のオフで始まる。既定が「出さない」なので、困るのはスケッチとマスクを見たい少数の利用者だけで、その人は端末ごとに 1 回オンにすればよい。
- `kind` を複数指定にすると、OpenAPI の型が配列に変わる。フロントは `npm run gen:api` で追随する。単数で書いた外部の呼び出しは、クエリ文字列としてはそのまま動く。
- グループの件数を種類で数え直すと、問い合わせに条件が 1 つ増える。グループの数は多くないので、負担は小さい。

## Consequences

- ストックに出るのは、既定では生成画像とアップロードだけになる。
- スケッチとマスクは、系列グラフと Run 詳細から辿って見る。設定をオンにすれば、従来どおりストックにも出る。
- ADR-0010(「ストックのフィルタに『スケッチ』を足す」)と ADR-0022 4章(kind のチップ)に、この ADR への参照を書き足す。
