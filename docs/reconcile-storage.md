# 画像と履歴を初期化する(画像を手で消した後に DB を合わせる。ADR-0046)

GAKEI の削除は論理削除だけで、画面から消しても原本のファイルと DB の行は残る(ADR-0003)。設定(OpenAI の接続先、認証、埋め込みのモデル、プロンプトセットなど)を残したまま、画像と履歴だけを初期化したいときは、画像の原本を手で消す(退避する)。その後に、DB を保存先に合わせるツールを実行する。

```bash
uv run python -m app.tools.reconcile_storage [--apply] [--yes] [--include-runs-without-outputs]
```

一部の画像だけを消した後にも使える。消した画像に付いていた行と、それに伴う履歴だけを DB から消す。

## 何を消すか

- **画像(Asset):** 原本が保存先に無い画像。論理削除済みかどうかは問わない。同じ内容の画像が原本のファイルを共有しているとき(ADR-0026)は、ファイルが残っていれば残す。
- **画像に付いた行:** タイトルとタグ、埋め込み、知覚ハッシュ、サムネイルの焦点、グループのメンバー、共有リンクの範囲、MCP のダウンロード URL の記録など。
- **残る画像からの参照:** スケッチの下地や、取り込んだ PNG の元を指していたら、その参照を外す(画像そのものは残る)。
- **履歴(Run):**
  - 出力があった Run で、出力がすべて消えるもの。
  - Edit の入力が消える Run で、出力が残るものは残す。系列では、その入力が無い Run として表示される。
  - 出力が一度も無い Run(失敗・中止)は、既定では残す。`--include-runs-without-outputs` を付けたときだけ消す。全部を初期化するときに使う。
  - Run に付いた行(プロンプトの埋め込み、系列の ZIP から取り込んだ記録)も一緒に消す。
- **共有リンク:** 起点の画像が消えるもの、範囲の画像がすべて消えるもの。
- **派生画像(サムネイル・カード・プレビュー):** 消した画像の派生を、すべての版について保存先から消す。同じ内容の画像が残っていれば消さない。

次は消さない: 設定、利用者、プロンプトセット、パラメーターセット、グループ(中身が空になっても残る)、タグの表記、ComfyUI のワークフロー、タグの辞書、LLM の接続先、アバター。DB に無い保存先のファイルは、件数を示すだけで消さない。

消した画像と履歴は元に戻せない(バックアップから戻すしかない)。

## 手順

1. **GAKEI を止める。** 動いたままだと、裏の処理(自動タグ、埋め込みなど)が行を書き換える。
2. **画像の原本を消すか退避する。** ローカルの保存先なら `DATA_DIR/assets/` の下、オブジェクトストレージならコンテナ(バケット)の `assets/` の下にある。全部を初期化するなら `assets/` をまるごと別の場所に移す。`derived/`(派生)はツールが消すので触らなくてよい。
3. **dry-run で件数を確かめる。** 何も付けずに実行すると、消す件数を示すだけで何も変えない。

   ```bash
   uv run python -m app.tools.reconcile_storage
   uv run python -m app.tools.reconcile_storage --include-runs-without-outputs   # 全部を初期化するとき
   ```

   画像、履歴、共有リンクの件数、一緒に消す行の件数(表ごと)、参照を外す件数、原本が無かったキーの例、DB に無い保存先のファイルの件数が出る。思ったより多ければ、保存先の設定(`STORAGE_BACKEND` など)や `DATA_DIR` が合っているかを確かめる。
4. **`--apply` で消す。** 件数を示してから確認を求めるので、`y` を入力する(`--yes` を付けると確認を省く)。

   ```bash
   uv run python -m app.tools.reconcile_storage --apply
   ```

5. GAKEI を起動する。

## 安全のための決まり

- **SQLite** のときは、消す前に DB を自動でバックアップする(DB と同じフォルダに `gakei.db.bak-<日時>`)。戻すときは、GAKEI を止めて、このファイルを `gakei.db` に置き換える(同じフォルダの `gakei.db-wal` と `gakei.db-shm` があれば消す)。
- **PostgreSQL** のときは自動ではバックアップしない。確認の前に注意を出すので、`pg_dump` などで先に取っておく([postgresql.md](postgresql.md))。
- DB の変更は1つのトランザクションで行う。途中で失敗すれば、DB は元のまま。
- 派生画像は、DB の変更を確定した後で消す。消せずに残っても害は無い(件数を示す)。オブジェクトストレージでは、削除の権限(S3 の `s3:DeleteObject`、Azure の BLOB の削除)が要る。
- 保存先を読めない(接続できない)ときは、何も変えずに中止する。

## Docker での実行例

```bash
docker compose stop gakei
# 画像の原本を消すか退避してから
docker compose run --rm gakei python -m app.tools.reconcile_storage
docker compose run --rm gakei python -m app.tools.reconcile_storage --apply
docker compose up -d gakei
```
