# Stable Diffusion WebUI に接続する

GAKEI から、Stable Diffusion WebUI の系統(AUTOMATIC1111、Forge など)の HTTP API(`/sdapi/v1/*`。以下「A1111 互換の API」)を呼んで画像を生成できる。OpenAI や ComfyUI と同じ履歴・系列・ビューアで扱える。設計は [ADR-0038](adr/0038-sd-webui-provider.md)。

利用者向けには **実験的な機能** である。主に Forge と AUTOMATIC1111 で確かめている。それ以外の実装(reForge、SD.Next など)は、A1111 互換の範囲で動けば使える。

## できること

- WebUI のチェックポイントを「モデル」として選び、プロンプトから生成する(Generate。WebUI の txt2img)
- 入力画像を1枚選んで描き直す(Edit。WebUI の img2img)。マスクを描けば、その範囲だけを描き直す(inpaint)
- ネガティブプロンプト、サンプラー、スケジューラー、ステップ数、CFG スケール、seed、サイズ(8 の倍数、長辺 2048px まで。次の項)、枚数(1〜8)、バッチ回数(1〜16)、VAE、Clip skip(1〜12、既定 1)を指定する
- **サイズ** は、幅と高さが 8 の倍数で、長辺 2048px まで・総画素数 256×256〜2048×2048・縦横比 1:4〜4:1 の範囲。フォームに 8 の倍数でない値を入れると、欄を離れたときに **8 の倍数に切り捨てる**(803 なら 800。送るときも切り捨てた値を送る)。WebUI は 8 の倍数でない寸法を受け付けても内部で 8 の倍数に切り捨てて描くので、先に GAKEI で切り捨て、送った値・Run の `params`・出力の画像の寸法をそろえる。API や MCP から 8 の倍数でないサイズを送ると 422 になる。
- **Clip skip**(`clip_skip`)は、テキストエンコーダーの最後の何層を飛ばすか(1 は飛ばさない)。VAE と同じく、WebUI の設定に任せず毎回送る(`override_settings.CLIP_stop_at_last_layers`。実行の後に WebUI の設定を元に戻す)。
- **バッチ回数**(`n_iter`)は、WebUI のバッチ回数(Batch count)。枚数(`batch_size`)枚を1回として、それを何回くり返すか。1つの Run の画像は **枚数 × バッチ回数** で、上限は 64 枚(超える組み合わせは 422)。フォームでは枚数の隣に置き、その下に合計の枚数を出す(64 枚を超えると赤字で注意する)。一度に描く枚数(VRAM を使う量)は枚数で決まるので、VRAM が足りないときは枚数を減らしてバッチ回数を増やす。seed は WebUI が1枚ごとに 1 ずつ足していく(各画像の seed は Run 詳細で見られる)。1回の実行を待つ上限(既定 600 秒)は全体に掛かるので、多く描くときは上限を延ばす。Dynamic Prompts の「組み合わせをすべて作る」を使うときは、WebUI がバッチ回数を使わないので、枚数と同じく無効になる(GAKEI は `n_iter` を 1 で送る)。
- 低めの解像度で描いてから拡大して描き直す(高解像度補助。hires fix。Generate だけ。後の節)
- 実行中の進み具合と途中経過の画像を表示する
- WebUI で作った画像に埋め込まれた生成情報を、フォームに読み込む(WebUI の「PNG 内の情報を表示 → txt2img に転送」に当たる。後の節)

チェックポイントは、その1回の実行だけ切り替え、終わったら WebUI の設定を元に戻す(`override_settings_restore_afterwards`)。WebUI の画面を直接使っている人の選択を変えたままにしない。WebUI が出力フォルダーに画像を保存することもない(`save_images` は false で送る)。原本は GAKEI が持つ。

LoRA は、プロンプトに `<lora:名前:重み>` と書けば、そのまま WebUI に届く。名前を覚えていなくても、プロンプト欄の「LoRA」から接続先の LoRA を選んで入れられる(次の節)。LoRA のファイルの管理はしない。

## LoRA を選んでプロンプトに入れる

SD WebUI のモデルを選んでいるとき、プロンプト欄の下の操作列に「LoRA」が出る(ADR-0038 8章)。

1. 「LoRA」を押すと、接続先の LoRA の一覧が出る(狭い画面では全面のシート)。名前(別名があれば併記)で探せる。
2. 各行の右に、学習時の記録から分かるベースモデルを **SDXL / SD1.5 / 不明** で出す。チェックポイントのベースモデルは API から分からないので、合わない LoRA を隠したり警告したりはしない。SDXL のチェックポイントに SD1.5 の LoRA を使うと効かないか崩れるので、目印を見て選ぶ。
3. LoRA を選び、重み(既定 1.0、0.1 刻み、-2〜2)を決めて「プロンプトに入れる」を押すと、プロンプトの末尾に `<lora:名前:重み>` を足す(区切りのカンマは自動で入る)。名前は WebUI の `name` を使う。タグモード(ADR-0039)では、LoRA は1つのチップになる。
4. **トリガーワードの候補** は、LoRA の学習データのタグ(`ss_tag_frequency`)を出現数の多い順に最大 20 個出したもの。タップでプロンプトに足す。括弧はタグモードの候補と同じく `\(` `\)` にエスケープする。学習の記録が無い LoRA では出ない。候補は手がかりで、作者が決めたトリガーワードとは限らない。

- 一覧はチェックポイントの一覧と同じく 60 秒ほどキャッシュしている。WebUI に LoRA を足したときは、管理者が「一覧を読み直す」を押す(WebUI の `refresh-loras` も呼ぶ)。一覧が空のときのダイアログにも、管理者には「一覧を読み直す」が出る。
- GAKEI が WebUI から受け取って画面に返すのは、名前・別名・ベースモデル・トリガーワードの候補だけ。LoRA のファイルの場所や、学習時のメタ情報(学習した人の環境のパスやコメントなど)は返さない。
- LoRA はプロンプトの一部として Run に残る。WebUI が生成の情報に入れる `Lora hashes` も、これまでどおり記録される。
- 作らない: LoRA のプレビュー画像、ブロックごとの重み、LoRA のファイルの管理、ComfyUI での LoRA の選択。

## 高解像度補助(hires fix)

Generate(txt2img)では、低めの解像度で描いてから拡大し、もう一度描き直せる(ADR-0038 10章)。SDXL で 1024 前後で描いてから 1.5〜2 倍にする、といった使い方をする。Edit(img2img)には無い。

- **高解像度補助**(`hires`、既定は無効)を有効にすると、次の項目が使えるようになる(無効の間はフォームで無効になる)。
  - **アップスケーラー**(`hr_upscaler`): 拡大の方式。選択肢は接続先の一覧で、Latent 系(`Latent` など)を先に、そのあとに `Lanczos` や ESRGAN 系などを並べる。既定は一覧に `Latent` があればそれ。WebUI の一覧の `None` は出さない。Latent 系はノイズ除去強度を高め(0.5 以上)にしないと崩れやすい。
  - **アップスケール倍率**(`hr_scale`、1〜4、0.05 刻み、既定 2): 1回目の寸法に掛ける倍率。フォームの倍率の欄の下に「拡大後 W×H」を出す。**拡大後の長辺は 4096px まで**(超えると実行できない。1回目の寸法は長辺 2048px まで)。
  - **高解像度でのステップ数**(`hr_second_pass_steps`、0〜150、既定 0): 拡大後に描き直すステップ数。0 なら本体のステップ数と同じ。
  - **ノイズ除去強度**(`hr_denoising_strength`、0〜1、既定 0.5): 拡大後にどれだけ描き直すか。WebUI には `denoising_strength` として送る。
  - **Hires CFG Scale**(`hr_cfg`、1〜30。Forge のときだけ): 拡大後の描き直しの CFG スケール。未指定なら本体の CFG スケールと同じ値を送る(Forge の既定は 1.0 で、送らないと CFG 1 で描き直してしまうため)。
  - **拡大後のプロンプト**(`hr_prompt`)と **拡大後のネガティブプロンプト**(`hr_negative_prompt`): 拡大後の描き直しにだけ使うプロンプト。**空なら本体のプロンプト(ネガティブプロンプト)と同じ** で、WebUI には送らない。プロンプト欄と同じく「テキスト / タグ」を切り替えられる。
- 出力の画像は拡大後の寸法になる。WebUI の生成の情報(`info`)の幅と高さは1回目の寸法のまま。
- Forge には、2回目も1回目と同じモジュール(VAE など)を使う指定(`hr_additional_modules: ["Use same choices"]`)を毎回送る。Forge はこれが無いと失敗する。VAE は1回目の指定がそのまま使われる。
- 拡大後の寸法を直接指定する方式(`hr_resize_x` / `hr_resize_y`)と、2回目だけ別のチェックポイント・サンプラーにする項目は無い。
- 「拡大後 W×H」は、1回目の寸法に倍率を掛けて切り捨て、さらに 8 の倍数に切り捨てた値で、実際の出力の画像の寸法と同じ(WebUI と同じ計算。512×768 を 1.5 倍なら 768×1152、1000×600 を 1.3 倍なら 1296×776)。長辺 4096px の判定もこの値で行う。
- 接続先からアップスケーラーの一覧が取れないときは、高解像度補助の項目を出さない。一覧は「一覧を読み直す」で読み直す。
- 無効のときは、高解像度補助の値を WebUI に送らない(WebUI の API の既定も無効)。送った値は `sdwebui_request` に残る。

## 画像の生成情報をフォームに読み込む

WebUI(A1111 形式)で作った画像には、プロンプトや設定(`parameters`)が埋め込まれている。これを SD WebUI の生成フォームに読み込める(ADR-0038 9章)。SD WebUI が有効なときだけ、次の2つの入口が出る。

- **スタジオの「画像から設定を読み込む」**(プロンプト欄の下の操作列。どのプロバイダーを選んでいても出る): 押すとダイアログが開く。「ファイルを選ぶ」か、ダイアログに画像をドロップするか、ダイアログを開いたまま貼り付け(Ctrl+V)で画像を渡す。フォームへのドロップとプロンプト欄への貼り付けは、これまでどおり入力画像の追加になる。**画像は保存しない**(ストックにも入らない。サーバーはメモリの上で生成情報だけを読んで捨てる)。大きさの上限はアップロードと同じ。
- **ストックの画像のビューア**: 生成情報が A1111 形式の画像では、「画像の生成メタ情報」の欄に「SD WebUI のフォームに読み込む」が出る。押すとスタジオへ移って読み込む。

読み込むと、プロバイダーを SD WebUI にし、プロンプトとパラメーターを画像の生成情報で置き換える。今のプロンプトが空でなければ、置き換える前に確かめる。

- **入れるもの:** プロンプトとネガティブプロンプト、ステップ数、サンプラー、スケジューラー(生成情報の表示名 `Automatic` などから WebUI の名前へ)、CFG スケール、seed、サイズ(8 の倍数に切り捨てて入れる。803x601 なら 800x600 にし、切り捨てたことを通知で知らせる。切り捨てた後でサイズの制約に収まらなければ入れない)、`Clip skip`(1〜12 のとき)、`Batch size` と `Batch count`(枚数とバッチ回数。範囲に収まるときだけ。1枚ごとの位置 `Batch pos` は並べない)、VAE(接続先の一覧にあるときだけ。Forge の `Module 1: 名前` のように拡張子の無い書き方でも探す)。古い A1111 の「DPM++ 2M Karras」のようにサンプラーの後ろにスケジューラーが付いた書き方は、分けて入れる。
- **チェックポイント:** 生成情報の `Model` の名前で接続先のチェックポイントを探し、無ければ `Model hash` で探す(名前を変えたファイルでも、WebUI がハッシュを計算済みなら見つかる)。見つからなければモデルは変えず、通知の注意で知らせる。`Model hash` と `VAE hash` は照合にだけ使うので、見つかったかどうかにかかわらず「読み込めなかった項目」には出さない。
- **高解像度補助:** `Hires upscale`(倍率)があり、接続先で高解像度補助を使えれば、高解像度補助を有効にして、倍率、`Hires steps`、`Hires upscaler`(接続先の一覧にあるときだけ)、`Hires CFG Scale`(Forge のときだけ)、`Denoising strength`(拡大後の描き直しの強さ)を入れる。`Hires prompt` / `Hires negative prompt` は、本体のプロンプト(ネガティブプロンプト)と違うとき(前後の空白は無視)だけ「拡大後のプロンプト」に入れ、同じなら空のまま(= 本体と同じ)にする。拡大後の寸法を指定した画像(`Hires resize`)や、2回目だけ別のチェックポイント・サンプラーを使った画像では、それらの項目は入れない。
- **Dynamic Prompts:** 生成情報に `Template`(展開前のプロンプト)があり、接続先に Dynamic Prompts があれば、展開前のプロンプトを入れて Dynamic Prompts を有効にする。接続先に無ければ、展開後のプロンプトを入れる。
- LoRA はプロンプトの中の `<lora:…>` としてそのまま入る。
- 生成情報に無いパラメーター(枚数やバッチ回数が書かれていないときなど)は、新規のフォームと同じ初期値に戻す。**入力画像は変えない**(入力画像があれば、そのまま Edit のフォームになる)。
- 入れられなかった項目(`Hires resize`、`Hires checkpoint`、`Hires sampler` など、hires でない画像の `Denoising strength` や `Hires prompt`、ADetailer や ControlNet の項目など)と注意(チェックポイントが見つからない、など)は、フォームの上部に出る通知で確かめられる。通知には読み込み元(生成情報の `Version`。WebUI の版)も出す。通知は × で閉じられ、「新規生成」でも消える。
- 作らない: A1111 形式以外(ComfyUI、NovelAI など)の生成情報からの読み込み、img2img への読み込み(WebUI の「img2img に転送」に当たるもの)。

## 入力画像から描き直す(img2img と inpaint)

スタジオで入力画像を1枚選ぶと Edit になり、WebUI の img2img を呼ぶ。入力画像は1枚だけ(2枚以上は選べない)。

- **マスクは任意。** マスクエディターで塗った範囲(GAKEI のマスクでは透明にした範囲)だけを描き直す。マスクが無ければ画像全体を描き直す。
- GAKEI のマスク(透明 = 描き直す範囲)は、送るときだけ WebUI の形(白 = 描き直す範囲の白黒の PNG)に変換する。境目のぼかし(半透明)はそのまま濃淡として渡す。入力画像とマスクの原本は変えない。
- **サイズ** を「未指定(自動)」にすると、入力画像の寸法(長辺 2048px に収め、8 の倍数に切り捨てる)で描く。入力画像を足したとき、サイズを自分で変えていなければ、フォームは自動で「未指定(自動)」に切り替わる(既定の 1024 × 1024 のままで入力の縦横比が崩れないように)。サイズを指定したときに入力画像と縦横比が違えば、「サイズの合わせ方」(引き伸ばす、切り抜いて合わせる、合わせて余白を埋める)で合わせる。
- **ノイズ除去強度**(`denoising_strength`、既定 0.75)は、元の画像をどれだけ描き直すか。目安は、0.3〜0.5 で色や細部の手直し、0.6〜0.8 で構図を残した描き直し、0.9 以上で元の画像をほとんど残さない。
- マスクがあるときだけ使う項目(マスクが無い間はフォームで無効になる):
  - **マスクのぼかし**(`mask_blur`、既定 4px): 境目をなじませる幅。
  - **マスク内の初期値**(`inpainting_fill`、既定は「元の画像」): 描き直す範囲を何から描き始めるか。元の画像を活かすなら「元の画像」、まったく別のものを描くなら「ノイズ」や「周りの色で埋める」。
  - **マスク部分だけを拡大して描く**(`inpaint_full_res`、既定はオフ): マスクの範囲(と周りの余白)を切り出し、出力のサイズまで拡大して描いてから元の画像に戻す。顔や手など、小さな範囲を細かく描き直すときに使う。余白は「拡大するときの余白」(`inpaint_full_res_padding`、既定 32px)。
- ネガティブプロンプト、サンプラー、ステップ数、CFG スケール、seed、VAE、Clip skip、枚数、バッチ回数、Dynamic Prompts(WebUI に入っているとき)は Generate と同じ。
- 系列では、出力の主たる親は入力画像になる。マスクも Run の入力として残る。

## WebUI を起動する

WebUI は **`--api` を付けて起動する**。付けないと、画面は動いていても API(`/sdapi/v1/*`)が無く、GAKEI からは「API が見つかりません(404)」になる。

```bash
# 例(起動の方法は WebUI ごとに違う。webui-user.sh / webui-user.bat の COMMANDLINE_ARGS などに足す)
--api
```

### Basic 認証(`--api-auth`)

WebUI を LAN に出すときは、`--api-auth` で API に Basic 認証を掛けられる。

```bash
--api --api-auth ユーザー名:パスワード
```

- 書式は **`ユーザー名:パスワード`**(コロンで区切る)。書式を誤ると、Forge は画面だけを起動し、API は 404 のままになる(起動のログにエラーが出る)。接続テストで 404 になったら、起動のログを確かめる。
- GAKEI では、設定 → SD WebUI の「資格情報」に同じユーザー名とパスワードを入れる。値は `DATA_DIR/secrets.json` に保存し、画面にも API の応答にも出さない(「設定済み」とだけ表示する)。
- URL に `ユーザー名:パスワード@` を書くことはできない。
- 資格情報が無い・違うと、接続テストは「Basic 認証が必要か、資格情報が違います(401)」になる。

## GAKEI から接続する

1. 管理者設定 → SD WebUI(`/settings/sdwebui`)を開く。
2. WebUI の URL(例: `http://127.0.0.1:7860`)を入れて「接続テスト」を押す。Forge か AUTOMATIC1111 か、チェックポイントの数が表示される。
3. 保存する。再起動は要らない。生成フォームのプロバイダーに「SD WebUI」が出る。

- 環境変数 `SDWEBUI_URL` と `SDWEBUI_TIMEOUT_SECONDS` は、画面で一度も設定していないときの初期値としてだけ使う([configuration.md](configuration.md))。
- 1回の実行を待つ上限は既定で 600 秒。同じページで変えられる(60〜10800 秒)。
- チェックポイントや LoRA を WebUI に足したときは「一覧を読み直す」を押す(WebUI の `refresh-checkpoints` と `refresh-loras` を呼び、GAKEI の一覧も読み直す)。一覧は 60 秒ほどキャッシュしている。
- SD WebUI の Run が待機中か実行中の間は、接続先と資格情報を変えられない。

## VAE の選び方

VAE は **実行ごとに選ぶ**。既定は「チェックポイントに内蔵のもの」。

WebUI はチェックポイントを切り替えても VAE の設定を残すので、たとえば SDXL 用の VAE を選んだまま SD1.5 のチェックポイントで描くと、画像が崩れる。GAKEI は毎回 VAE を指定して送り(Forge は `forge_additional_modules`、AUTOMATIC1111 は `sd_vae`)、実行の後に WebUI の設定を元に戻す。

- VAE を内蔵しているチェックポイントは、「チェックポイントに内蔵のもの」のままでよい。
- VAE を内蔵していないチェックポイントは、種類(SD1.5、SDXL など)に合う VAE を選ぶ。
- 選択肢は接続先の VAE の一覧(Forge は `VAE` のフォルダーにあるもの)。

Flux など、テキストエンコーダーを別に読み込むチェックポイントは対象外(動くかは WebUI の設定次第)。

## 指定したチェックポイントで描かれなかったとき

WebUI は、知らないチェックポイント名を渡されてもエラーにせず、今読み込んでいるもので描く。GAKEI は応答の情報で実際に使われたチェックポイントを確かめ、違えば画像を取り込まずに Run を失敗(`sdwebuiModelMismatch`)にする。チェックポイントのファイルを消したり名前を変えたりしたときは、「一覧を読み直す」を押す。

## LAN の別の PC で WebUI を動かすとき

GPU のある PC で WebUI を動かし、GAKEI は別の PC で動かす使い方ができる。

- WebUI を LAN から受けられるように起動する(例: `--listen`)。**`--api-auth` で Basic 認証を掛ける。** 認証の無い WebUI を LAN に出すと、同じネットワークの誰でも WebUI を使える。
- GAKEI でループバック以外の URL を保存するときは、画面の確認のチェックを入れる。サーバーのログにも警告が出る。
- Basic 認証は `http` では平文で流れる。信頼できるネットワークでだけ使う。
- GAKEI を Docker で動かし、同じホストの WebUI に接続するときは `http://host.docker.internal:7860`(`--add-host=host.docker.internal:host-gateway` が要る。README の Docker の節)。

## 実行中のキャンセル

キャンセルできるのは、GAKEI の中で待機中の Run だけ。WebUI で実行中のものは止めない(WebUI の中断の API は、誰が始めたかに関係なく、実行中のものを止めてしまうため)。

## 記録されるもの

Run の `params` には、利用者が指定した値に加えて、次を記録する(ADR-0038 3章)。

- `sdwebui_seed`: 実際に使った seed(指定が無ければ GAKEI が決める)
- `sdwebui_task_id`: 進み具合の問い合わせに使う ID
- `sdwebui_request`: WebUI に送った本文そのもの。ただし Edit の入力画像とマスク(`init_images`、`mask`)は base64 を入れず、`{"asset_sha256": ...}`(GAKEI の原本の sha256)で記録する。画像そのものは Run の入力として残っている

`sdwebui_` で始まる項目はサーバーだけが書く。`sdwebui_request` と `sdwebui_task_id` は共有のページの公開パラメーターには出さず、`sdwebui_request` は PNG に埋め込む系列情報にも入れない(WebUI 自身が `parameters` として生成の設定を PNG に入れている)。

## 作らないもの・今後

- 作らない: InvokeAI、Fooocus、SwarmUI など、A1111 互換でない API
- 作らない: 拡張機能(ControlNet、ADetailer など)の項目、refiner、アップスケール(`extra-single-image`)。hires fix は倍率の指定だけある
- 作らない: チェックポイント・LoRA・VAE のダウンロードや管理、WebUI の設定の変更(LoRA を一覧から選んでプロンプトに入れる補助はある)
- 作らない: 実行中の Run のキャンセル
- 作らない: 複数の WebUI サーバー
- 作らない: 入力画像が2枚以上の Edit
