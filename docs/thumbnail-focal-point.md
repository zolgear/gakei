# サムネイルの焦点(顔の位置)

ストック、履歴、系列のノード、入力画像、検索、マップなどのサムネイルは、正方形などの枠に合わせて画像を切り取って表示します。GAKEI は画像ごとに **焦点**(顔のおおよその位置)を記録し、切り取る位置をそこに寄せます。縦長・横長の画像でも顔が枠に入りやすくなります(ADR-0043)。

- サムネイルの画像そのものは作り直しません。画面で切り取る位置(`object-position`)だけを変えます。ビューアで画像全体を出すところには使いません。
- 焦点が無い画像(顔が見つからない、まだ求めていない)は、今までどおり中央で切り取ります。
- 利用者が焦点を手で直す機能はありません。

## どの画像に効くか

顔の検出には、アニメ・イラスト調の顔のための軽い検出器(opencv の LBP カスケード [lbpcascade_animeface](https://github.com/nagadomi/lbpcascade_animeface))を使います。精度より軽さを優先しています。

- **効きやすい:** イラスト・アニメ調の人物で、顔が正面かそれに近い向きで、画像の中である程度の大きさがあるもの。
- **効きにくい:** 実写の顔、横顔や後ろ姿、顔が小さい(全身の立ち絵、集合の絵)もの、顔が大きすぎて画像からはみ出すもの、線画だけのもの、厚塗りなど画風が大きく違うもの。人物ではない画像(動物、風景、模様)は対象外です。
- 顔がいくつもあるときは、いちばん大きい顔に寄せます。ごくまれに、顔でない模様を顔と取り違えることがあります。

参考までに、開発時に実際の生成画像 48 枚(SD WebUI、ComfyUI、OpenAI、アップロード)で試したところ、顔を見つけたのは 26 枚でした。見つからなかったものの多くは、後ろ姿や顔の写っていない構図、実写調、模様の画像でした。

## いつ求めるか

- 新しく取り込んだ画像(生成の出力、アップロード、スケッチ、系列の取り込み、MCP・URL でのアップロード)は、取り込みの後にサーバーの中で求めます。取り込みの応答は待たせません。1枚あたり、原本の読み込みを含めて Raspberry Pi 5 で 0.1 秒前後です。
- マスクは対象外です。
- 結果は DB の `asset_focal_point` に保存します(原本と派生画像には触れません)。来歴の情報ではないので、作り直してかまいません。
- 画像の保存先がオブジェクトストレージ(Azure Blob、S3 互換)でも同じように動きます。

## 既存の画像の埋め戻し

この機能より前に取り込んだ画像には焦点がありません。埋め戻しのツールで求めます。GAKEI を止めずに実行できます。

```bash
cd backend
uv run python -m app.tools.backfill_focal_points --dry-run   # 対象の件数を数えるだけ
uv run python -m app.tools.backfill_focal_points             # 求める
uv run python -m app.tools.backfill_focal_points --limit 500 # 件数を区切って少しずつ
```

- 対象は、焦点がまだ無い画像と、検出の手順の版が古い画像です(マスクを除く。論理削除済みの画像も、復元に備えて含めます)。顔が見つからなかった画像も「見つからない」と記録し、次からは対象にしません。
- `--recompute` を付けると、焦点がある画像も作り直します。
- 1枚ごとに短く書き込むので、途中で止めても、もう一度実行すれば続きから求めます。
- DB の移行はしません。この版の GAKEI を一度起動してから実行してください。
- Docker では `docker compose run --rm gakei python -m app.tools.backfill_focal_points --dry-run` のように実行します。

サーバーの再起動などで、取り込んだ直後の画像の焦点を求めそこねることがあります(待ち行列はサーバーのメモリの中だけに持ちます)。その画像も埋め戻しのツールで求められます。
